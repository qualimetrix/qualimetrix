# План: устойчивая идентичность объявления и сжатие значений записи

Редакция 2, после двух раундов ревью.

- Раунд 1 (весь план, 4 рецензента: claude, codex, qwen, deepseek) — 33
  подтверждённые находки, 1 отклонена; P2 и P3 переписаны целиком.
- Раунд 2 (только P2, 2 рецензента: claude, codex) — 19 подтверждённых находок,
  пять механизмов названы обоими независимо.

**Статус разделов: P1 готов к исполнению. P2 приостановлен.** Раунд 2 показал,
что раздел не сходится не по формулировкам, а по фактам об измерительном слое:
счётчиков порядка три, а не два; три из пятнадцати мест обходят конструктор
`DeclarationPath` через скалярные фабрики `MetricSubjectCodec::encode*`;
класс-визиторы (`LcomVisitor:83`, `LocVisitor:54`) ключуют карты по FQN и теряют
дубликат до всякого присвоения номера; имя анонимного класса содержит смещение
(`VisitorFileEntryScope:77`); `FileProcessor::extractClassMetrics()` выбрасывает
`ClassWithMetrics`, так что заявленный перенос смещения не совпадает с реальным
транспортом. Третья редакция того же раздела, написанная тем же способом,
провалится так же. **Раздел P2 ниже сохранён как материал разведки, а не как
задание к исполнению**; перед его переписыванием снимается фактическая карта
идентичности объявления в измерительном слое.

Перечисления: [`enumeration-identity.md`](enumeration-identity.md).

## Решения владельца, принятые до этой редакции

1. Отход от принятого ADR допустим, если улучшает архитектуру.
2. Совместимость бейзлайна не поддерживаем — перегенерируем везде, конвертера нет.
3. Сброс отпечатков GitLab/SARIF допустим.
4. Выводимый путь в ключе (бывший P3) **снят** и отложен.

## Что решается

**Дефект корректности.** Ключ объявления содержит `startFilePos` — байтовое
смещение узла. Воспроизведено: пустая строка после `<?php` в
`src/Analysis/Evidence/Cohesion/LcomOptions.php` даёт «1 baseline entries did not
appear in this run», возврат находки как новой и `exit=1`. Сдвигает смещение
любая правка выше объявления.

**Избыточность значений.** `count` при наличии `magnitudes` (232 из 264 записей,
конструктор `BaselineEntry` и так требует равенства) — 2 320 Б. Occurrence-ключ
хранится полным sha256 при домене различения «внутри одной пары субъект+канал» —
2 838 Б, из них лишних 2 064.

Итог по размеру: −7.2%. Основной результат захода — не размер, а идентичность.

**Версию формата поднимает тот пакет, который меняет формат**, а не один раз
авансом: P1 → 12, P2 → 13. Прежняя редакция поднимала версию один раз в P1, и это
дефект: DoD каждого пакета требует регенерации ратчета, значит в конце P1 в дереве

Каждый пакет оставляет `composer check` зелёным, включая регенерацию ратчета.

## P1. Значения записи

**Файлы:** `src/Analysis/Policy/Baseline/{BaselineEntry,BaselineEntryValues,
BaselineEntryParser,BaselineWriter,BaselineLoader,Baseline}.php`,
`src/Analysis/Finding/Contract/OccurrenceKey.php`.

### P1.1 `count` не сериализуется при наличии `magnitudes`

VO `BaselineEntry` **сохраняет** свойство `count` — оно осмысленно для 32 записей
без `magnitudes`. Меняются писатель и разбор:

```
BaselineWriter:  magnitudes есть ⇒ count не пишется
BaselineEntryValues::decode:
    magnitudes есть  ⇒ count в исходных данных запрещён, выводится как длина списка
    magnitudes нет   ⇒ count обязателен, как сейчас
```

Запрет обоих полей рядом — не педантизм: разрешив их, вернём расхождение, которое
и убираем, и превратим инвариант в разбор конфликта.

**DoD:**
- свойство round-trip «записать → прочитать → записать даёт байт в байт» на наборе,
  содержащем обе формы;
- запись с обоими полями отклоняется в inert с названной причиной — тест **обязан**
  проверяться против кода до P1.1 и там проходить иначе;
- в регенерированном ратчете число записей с `"count"` равно числу записей без
  `magnitudes`, посчитанное из того же файла, а не константа 32.

### P1.2 occurrence-ключ укорачивается до 16 hex

`OccurrenceKey::semantic()` — единственная фабрика, 8 производителей (E4).
Домен различения — внутри одной пары (субъект, канал), то есть единицы членов.
Собственный аргумент проекта: `EntrySelector::LENGTH = 12` с обоснованием «48 бит
хватает», причём селектор адресует всю идентичность. Берём 16 с запасом.

**Публичная поверхность шире, чем поле в JSON.** Значение входит в
`Violation::getFingerprint()`, а тот используется в
`GitLabCodeQualityFormatter::generateFingerprint()` (md5, отслеживание находок
между MR) и в `SarifFormatter` (`partialFingerprints.primaryLocationLineHash`,
идентичность алерта GitHub code scanning). Практическое последствие: в GitLab
находки один раз покажутся новыми; в GitHub code scanning закрытые и
задизмишенные алерты воскреснут как новые. Владельцем принято.

**Попутно:** докблок `Violation::getFingerprint()` утверждает «@internal Not used
in production code. May be removed in a future version» — это неверно, метод
используют два форматтера. Докблок правится в этом же пакете.

**DoD:** все occurrence-ключи в файле и в выводе длиной 16; тест на то, что
усечение берётся от того же sha256, а не от другого материала; `Breaking` в
CHANGELOG называет сброс отпечатков GitLab и SARIF и его последствие для
задизмишенных алертов.

## P2. Одна семантика порядкового номера вместо смещения

**Предмет:** идентичность объявления перестаёт зависеть от того, что лежит выше
него в файле по байтам.

### Наблюдение, на котором стоит пакет

В коде **уже** живут два счётчика порядка, и оба завязаны на смещение:

- `VisitorFileEntryScope::enterCallable()` — `callableTraversalOrdinals` по ключу
  `logicalFqn . '@' . startFilePos`;
- `VisitorFileEntryScope::register()` — группа
  `(kind, namespace, class, member, startFilePos)`.

Там же анонимные вызываемые именуются счётчиком обхода: `'{closure#' .
++$this->closureCounter . '}'`, счётчик на файл. Отсюда факт, определяющий
решение: **свойство ADR 0021 «adding a sibling declaration cannot alter an
existing declaration key» в коде уже не выполняется** — вставка замыкания выше по
файлу сдвигает имена всех последующих. Формулировка ADR шире того, что код
обеспечивает.

### Контракт

Два счётчика заменяются одним, с ключом группы без смещения:

> **порядковый номер = ранг в порядке обхода среди объявлений файла,
> разделяющих одну логическую идентичность.**

Он поглощает три случая: дубликат именованного FQN, коллизию по совпадающему
смещению и нумерацию анонимных вызываемых.

```php
// Core\Symbol\DeclarationOrdinal — новый VO, не int
static first(): self
withinFile(): int

// Core\Symbol\DeclarationPath
__construct(SymbolPath $logical, RelativePath $file, DeclarationOrdinal $ordinal)

// Core\Symbol\FileDeclarationOrdinals
static fromAst(array $ast): self
ordinalFor(SymbolPath $logical): DeclarationOrdinal   // выдаёт следующий ранг группы
```

**Почему `DeclarationOrdinal` — VO, а не `int`.** Ревью показало: из 15
производителей (E1) 11 компилируются под сигнатурой `(SymbolPath, RelativePath,
int)` без единой правки, и байтовое смещение молча станет порядковым номером.
Значение по умолчанию усугубляет это до 15 из 15. Отдельный тип делает старый
вызов ошибкой типов — заявленная гарантия «компилятор перечисляет множество сам»
становится настоящей вместо декларативной.

### Форма ключа

```
обычный файл:
  declaration:callable:App\Cache::get@src/Cache.php

файл, где App\Cache объявлен дважды (условное объявление):
  declaration:callable:App\Cache::get@src/Cache.php
  declaration:callable:App\Cache::get@src/Cache.php#1
```

`#` уже служит разделителем ordinal в `DeclarationPath::toCanonical()`.

### Доставка индекса

Прошлая редакция утверждала «единственный шов — `CompositeCollector::collect()`».
Это неверно: `DependencyVisitor::enterNode()` и `VisitorFileEntryScope` строят
идентичность **внутри обхода** и параметров `collect()` не видят.

Решение — сделать индекс не побочным эффектом обхода, а **детерминированным
предпроходом**:

```
FileProcessor (на файл):
    $ordinals = FileDeclarationOrdinals::fromAst($ast)   // полный обход AST
    → в конфигурацию traverser'а (DependencyVisitor, VisitorFileEntryScope)
    → параметром в collect() (класс-уровневые коллекторы)
```

Два маршрута доставки, потому что производителей два рода; общий у них источник
истины, а не порядок вызова. Детерминированность предпрохода — то, что позволяет
обоим родам получить одинаковые номера, не согласуя порядок между собой.

**Предпроход обязан быть полным**, а не «неглубоким»: условные объявления живут в
телах `if`, замыкания — в телах функций. Обход, не спускающийся туда, породит
второе несверяемое перечисление. Цена — один лишний полный обход AST на файл;
она **замеряется** против текущей базы (7.2 с, 814 файлов), а не оценивается
рассуждением. Порог: рост прогона более чем на 10% возвращает пакет к выбору
маршрута.

### Читатели `startFilePos`

Прошлая редакция перечислила производителей и не перечислила читателей. Читатель
в production один — `DeclarationControlBindings` (строки 71, 73, 110, 114), где
смещение служит ключом соединения инлайновых директив `@qmx-*` с диапазонами
узлов AST, плюс 4 файла тестов.

Смещение остаётся внутрирунным фактом, но переезжает с `DeclarationPath` на
`CallableWithMetrics` и `ClassWithMetrics`, которые его и так получают из
визиторов. `DeclarationControlBindings` читает его оттуда.

### Кэш AST не трогаем

Прошлая редакция требовала поднять `CacheKeyGenerator::KEY_SCHEMA_VERSION`,
обосновывая это «закэшированными метриками старой формы». Такого слоя нет:
`CachedFileParser::parseContent()` кладёт в кэш **AST**, ключ — хэш содержимого,
субъекты пересчитываются каждый прогон. Подъём версии не нужен и не делается.

**DoD:**
- регрессионный тест: файл с записью в ратчете + вставленная пустая строка в
  начале ⇒ ратчет зелёный. Тест прогоняется против кода **до** P2 и там падает;
- фикстура с двумя условными объявлениями одного FQN в одном файле: два субъекта,
  `#1` у второго;
- фикстура с замыканиями: вставка замыкания выше по файлу не меняет ключей
  последующих — свойство, которого сегодня нет;
- ни один ключ субъекта в регенерированном ратчете не содержит позиционной
  составляющей. Проверка — разбор ключей парсером формы, а не `grep ':[0-9]\+"'`:
  тот совпадает с полем `generated` (`+00:00"`) и проходит всегда;
- замер прогона на `src/` приложен к отчёту пакета.

## P3. Диагностика, документация, ADR

**Файлы:** `src/Infrastructure/Console/ViolationFilterOrchestrator.php` (владелец
сообщения о протухших записях — не `BaselineCleaner`, как утверждала прошлая
редакция), `src/Analysis/Policy/Baseline/README.md`, `src/Core/README.md`,
`website/docs/usage/baseline.{md,ru.md}`,
`website/docs/usage/output-formats.{md,ru.md}`, `CHANGELOG.md`, ADR.

Сообщение сегодня называет две причины: «finding was repaired, or configuration
stopped producing it». Третья — «объявление переехало» — до P2 была главной.

`Core/README.md` описывает идентичность объявления и после P1/P2 станет неверным.

**ADR — supersede ADR 0021 в одной части.** Свойство «adding a sibling
declaration cannot alter an existing declaration key» заменяется на выполнимое:
сосед не меняет ключ, **если не разделяет с ним логическую идентичность в том же
файле**. Обоснование в ADR: прежняя формулировка не выполнялась и до этого
захода (счётчик замыканий), а платой за неё была универсальная хрупкость всех
именованных объявлений.

**DoD:** `cd website && mkdocs build --strict` без предупреждений; EN и RU одним
изменением; `Breaking` называет старую и новую форму ключа, длину occurrence,
исчезновение `count`, сброс отпечатков и то, что единственный маршрут для
существующего бейзлайна — перегенерация.

## Тестовый план

| Что проверяем                                                        | Уровень     | Пакет  |
| -------------------------------------------------------------------- | ----------- | ------ |
| round-trip записи в обеих формах, байт в байт                        | unit        | P1     |
| `count` рядом с `magnitudes` ⇒ inert с причиной (падает до фикса)    | unit        | P1     |
| длина occurrence в файле, JSON, HTML, GitLab, SARIF                  | unit        | P1     |
| пустая строка в начале файла не рушит ратчет (падает до P2)          | functional  | P2     |
| два условных объявления одного FQN ⇒ два субъекта, `#1` у второго    | integration | P2     |
| вставка замыкания не меняет ключей последующих                       | integration | P2     |
| инлайновые директивы `@qmx-*` привязываются после переноса смещения  | integration | P2     |
| ключи ратчета не содержат позиционной составляющей (разбор, не grep) | integration | P2     |
| множество принятых потолков до и после регенерации                   | сверка      | P1, P2 |

Последняя строка — ответ на главную находку ревью: смена формы ключа делает
прямой дифф ратчета бесполезным, и регенерация способна молча **ослабить**
потолки. Сверяются не идентичности, а пары (нормализованная идентичность,
принятая величина), до и после, машинно.

## Риски

- **Регенерация ратчета ослабляет потолки незаметно.** Митигация — сверка пар выше.
- **Предпроход по AST удорожает прогон.** Митигация — замер и названный порог.
- **P2 меняет 15 производителей, 1 читателя и 2 VO.** Один пакет, один агент,
  параллелить нельзя.

## Что план сознательно не делает

- Не трогает идентичность канала: 57 объявленных каналов, из них 44 в форме
  `code == ruleName`, 13 в форме `ruleName + "." + <level>`, 0 в форме, где код не
  связан с именем правила (E5). Направление верное, но это вопрос модели со своим
  ADR, и любое сжатие строки канала здесь оказалось бы работой на выброс.
- Не выводит путь из FQN: снято решением владельца. Возврат к вопросу требует
  нового читателя PSR-4-карты — `ComposerReader::collectPsr4Paths()` выбрасывает
  ключ-префикс неймспейса и отдаёт только пути, — а также правила для глобальных
  функций, у которых канонический вид `func::name` класса не содержит.
- Не убирает префикс `declaration:kind:` — 6% размера ценой декодируемости.
- Не группирует записи по файлу — замерено 3.4% при 145 файлах на 182 субъекта.

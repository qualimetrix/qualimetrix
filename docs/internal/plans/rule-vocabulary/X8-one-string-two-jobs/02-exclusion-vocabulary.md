# Э2 — подавление перестаёт называться исключением

Закрывает запись 366. Ломающее изменение схемы конфигурации; **baseline не
касается** — коды каналов и субъекты не меняются, перегенерации
`qmx-baseline.json` у потребителей не требует.

## Что измерено

`enumeration-exclusion-vocabulary.tsv` (20 строк) даёт шесть механизмов. Запись
366 ошибается в другую сторону, чем думала: **четыре из шести названы словом
`exclude` честно** — находка при них не производится вовсе, исключается вход, а
не выход.

| механизм                                         | ключ                                                                                                                          | находка производится | вердикт                          |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- | -------------------- | -------------------------------- |
| файл не читается                                 | `exclude` (корень)                                                                                                            | нет                  | слово по праву                   |
| измерение не входит в формулу здоровья           | `exclude_health`                                                                                                              | нет                  | по праву                         |
| класс не входит в слой                           | `architecture.<layer>.exclude`                                                                                                | нет                  | по праву                         |
| сущность не измеряется правилом                  | `exclude_readonly`, `exclude_promoted_only`, `exclude_data_classes`, `exclude_tests`, `exclude_exceptions`, `exclude_methods` | нет                  | по праву                         |
| **произведена и выброшена на проекции отчёта**   | `exclude_paths`, `exclude_namespaces` (корень)                                                                                | да                   | подавление под именем исключения |
| **произведена и выброшена на выходе исполнения** | `exclude_paths`, `exclude_namespaces`, `exclude_namespace_channels` (внутри правила)                                          | да                   | подавление под именем исключения |

Множество ключей исчерпано командой
`git grep -hoE "'(exclude|ignore|skip|only|include)_[a-z_]+'" -- src` и её
camelCase-двойником; других `exclude_*` в классах опций нет, есть три соседа со
своим смыслом — `include_namespaces`, `include_generated`, `only_rules`.

**Чего первая редакция плана не знала.** Два подавления различены в коде
намеренно и уже опубликованы: `SuppressionMechanism` — закрытый словарь из семи
значений, где `path-exclusion`/`namespace-exclusion` (глобальные, внутри
`FindingProjector`) отделены от `rule-path-exclusion`/`rule-namespace-exclusion`
(поправило, внутри исполнения), и его докблок прямо говорит, что слияние
«отбросило бы различие, которое продукт уже измеряет отдельно». Формат
`--format=suppressed` публикует все семь.

Поэтому этап **не объявляет «одно поведение на двух уровнях»** — так было
написано в первой редакции, и это спорило бы с принятым решением. Уровень
вложенности остаётся областью применения, механизмы остаются двумя, а
переименовывается то, что названо неверно: слово `exclude` там, где находка
производится.

## Решение

| было                                                                                                                        | стало                                     |
| --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `exclude_paths` / `excludePaths` (корень и внутри правила)                                                                  | `suppress_paths`                          |
| `exclude_namespaces` / `excludeNamespaces`                                                                                  | `suppress_namespaces`                     |
| `exclude_namespace_channels` / `excludeNamespaceChannels`                                                                   | `suppress_namespace_channels`             |
| флаги `--exclude-path`, `--exclude-namespace`                                                                               | `--suppress-path`, `--suppress-namespace` |
| значения `SuppressionMechanism`: `path-exclusion`, `namespace-exclusion`, `rule-path-exclusion`, `rule-namespace-exclusion` | `…-suppression` в тех же четырёх          |

Слово `suppress` выбрано не по вкусу: продукт уже называет этот исход
подавлением везде, где говорит о нём вслух — `--show-suppressed`,
`--format=suppressed`, `SuppressionMechanism`. Отвергнут `ignore_*`:
`@qmx-ignore` — один из механизмов подавления, а не имя явления.

### Старый ключ обязан отказывать, а не предупреждать

**Измерено:** неизвестный ключ внутри правила даёт **предупреждение**, а не
отказ (`RuleOptionsFactory.php:124` и `:406`). Значит без отдельной работы
миграция будет молчаливой: конфиг со старым ключом продолжит запускаться, а
подавления в нём просто перестанут применяться — находки, которых пользователь
не ждёт, посыплются в отчёт, и предупреждение утонет.

Поэтому пакет заводит для пяти переименованных написаний **именованный отказ**,
а не полагается на общий путь неизвестного ключа. Текст называет обе развилки:
для подавления находок — `suppress_*`, для исключения файлов из анализа —
корневой `exclude`. Второе предложение существенно: именно эту развилку читатели
проходили неверно трижды за заход Х2.

### Чего этап не делает: `--show-suppressed`

Вторая редакция плана заводила сюда пакет на утверждении «простой
`--show-suppressed` показывает одну стадию из семи». Утверждение неверно:
`reportSuppressedFindings()` действительно читает только стадию `Suppression`,
но рядом с ним `FindingFilterOrchestrator` вызывает ещё
`reportExclusionCounts()` и `reportRuleExclusions()`
(`FindingFilterOrchestrator.php:88-95`), то есть подавления по путям и
поправильные исключения пользователю уже показываются — другими блоками вывода.
Пакет снят: он лечил бы то, чего нет. Осталась ли у этих трёх блоков связная
форма — вопрос отчёта, а не словаря; он уходит в FOLLOWUPS.

## Пакеты работ

Порядок: П1 → П2 → П3. Пакета про `--show-suppressed` больше нет — см. выше.

### П1 — переименование ключей, флагов и значений механизма

**Набор файлов задаётся командой, а не списком.** Перечисление вручную во
второй редакции было короче собственного DoD-grep — 10 названных файлов против
40 snake-вхождений и 17 camel; пакет начинается с

```
git grep -lnw "exclude_paths\|exclude_namespaces\|exclude_namespace_channels" -- src tests
git grep -lnw "excludePaths\|excludeNamespaces\|excludeNamespaceChannels" -- src tests
```

и работает по их объединению. Поимённо план называет только те места, которые
grep по ключам **не** найдёт и которые обязаны попасть в пакет:

- `src/Analysis/Finding/Contract/Filter/FindingFilterStage.php` — источник имён,
  из которых `SuppressionMechanism::fromStage()` выводит свои значения;
  переименовать значения механизма, не тронув стадии, значит развести пару,
  которую PHPStan держит исчерпывающей;
- `CheckCommandDefinition.php` и `ConfigurationInputAdapter.php` — флаги
  `--exclude-path`, `--exclude-namespace`;
- `src/Infrastructure/Console/Command/GraphExportCommand.php:83,138` — у
  `graph:export` есть собственный `--exclude-namespace`, и он **не** подавление,
  а сужение графа: его переименовывать нельзя, но проверить и назвать в отчёте
  обязательно, иначе следующий grep снесёт и его;
- `RuleOptionsFactory.php` — именованный отказ на старые написания;
- **предписывающие тексты вне `src`/`tests`**: `CLAUDE.md` в корне и
  `docs/internal/CLI_CONVENTIONS.md` учат этим ключам будущих исполнителей;
  оставленные непеределанными, они вернут старое имя следующим же заходом.

**DoD:** `git grep -nw "exclude_paths\|exclude_namespaces\|exclude_namespace_channels" -- src`
пусто; camelCase-двойники переименованы; четыре значения `SuppressionMechanism`
переименованы, `fromStage()` остаётся исчерпывающим; конфиг со старым ключом на
**обоих** уровнях даёт отказ, называющий `suppress_*` и корневой `exclude` (тест
на каждый уровень); четыре честных исключения остались в прежнем количестве
вхождений (тот же grep); `composer check:code` зелёный.

### П2 — конфигурация проекта, доки, история

**Файлы:** `qmx.yaml`, `qmx.yaml.example`, пресеты, `website/docs/**` EN и RU
одновременно, `src/Analysis/Configuration/README.md`, `src/Reporting/README.md`,
`CHANGELOG.md` (`Breaking` с обоими именами и миграцией от лица потребителя),
ADR о том, почему подавление и исключение — разные слова, а уровень вложенности
— область применения, а не второй механизм.

**DoD:** `composer check:docs` зелёный; `composer check:artifacts` зелёный
целиком, а не одной проверкой из пяти — переименование ключей двигает снимок
подавлений `docs/internal/generated/suppression/composition.tsv`, и он
перегенерируется в этом же пакете;
`bin/qmx check src/` на своём `qmx.yaml` даёт прежний состав находок;
существующий `qmx-baseline.json` применяется без изменений.

### П3 — гейт

**Файлы:** `finding-gate/maps/inputs.tsv`, корпусные кейсы, называющие эти ключи.

**DoD:** `composer gate --reference=<коммит начала Э2>` — GREEN при объявленных
строках; снятие одной строки даёт RED (проверяется и называется в отчёте).
Значения `SuppressionMechanism` видны в артефактах отчёта, а не только на входе:
если действующие карты не покрывают значение поля отчёта, пакет **возвращается
оркестратору** и не изобретает форму объявления — она отложена осознанно.
Условие возврата не путать с наличием `declared-delta.tsv`: файл в дереве уже
есть и содержит один заголовок.

## Тестовый план

- Старый ключ на каждом из двух уровней → отказ с обоими новыми путями.
- Новый ключ на обоих уровнях → находка подавлена, посчитана, механизм в
  `--format=suppressed` по-прежнему различает глобальный и поправильный уровни.
- Четыре честных исключения работают под прежними именами.
- `exclude` (корень) и `suppress_paths` на одном пути: файл не читается вовсе,
  подавление к нему не применяется и в счётчик не попадает.
- `qmx-baseline.json` из предыдущего релиза применяется без изменений.

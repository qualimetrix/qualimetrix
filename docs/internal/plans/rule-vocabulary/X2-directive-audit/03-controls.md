# П3. Контроли на сам детектор

Детектор, всегда отвечающий «инертна», проходит наивную проверку: директив,
которые действительно ничего не делают, в дереве немного, и отчёт «инертных
ноль» выглядит одинаково у работающего детектора и у сломанного. Пакет
доказывает, что инструмент кусается.

Пакет стоит **до команды и до CI**. Прецедент — П0 захода Х1: инструмент
проверяется до продукта. Первая редакция плана ставила контроли последними, и
это нашли двое ревьюеров независимо: гейт, включённый в `composer check` до
доказательства детектора, — это enforcement на непроверенном измерителе.

## Контроли

Положительная проба и по мутации на каждое утверждение детектора. **Числа здесь
нет намеренно**: ревью насчитало в первой редакции этого файла четыре разных
(20 / 18 / 17 / 18 в плане и в двух докблоках), потому что список рос от прогона
к прогону, а прозу правили не всюду. Сколько проб сегодня — печатает сам стенд.

Ядро списка собрано из того, что П2 и три раунда ревью исполнения измерили;
остальное добавил стенд, показав, какие случаи не краснеют ни от чего.

**Положительная пара** — не мутация, а фикстура: заведомо действующая директива
даёт `Effective`, заведомо инертная **на том же якоре** даёт `Inert`. Парность
несущая: сломанная адресация дала бы `Inert` обеим, и одиночная проба этого не
видит.

**Мутации.** Сгруппированы по тому, какое утверждение детектора они отменяют.

| Мутация                                             | Отменяет утверждение                                       |
| --------------------------------------------------- | ---------------------------------------------------------- |
| сравнение исходов всегда отвечает «совпало»         | разность исходов вообще наблюдается                        |
| сравнение исходов всегда отвечает «разошлось»       | то же, с другой стороны                                    |
| снятие директивы не снимает ничего                  | контрфактический прогон отличается от базового             |
| снимается первая запись группы вместо всей группы   | единица снятия — авторская директива, а не привязка        |
| из отпечатка убрана граница                         | `Overrun` отличим от `Effective`                           |
| `recommendation` переведён в идентичность           | граница — это поле **и проза**                             |
| поле идентичности выброшено из ключа                | отпечаток видит находку целиком                            |
| разбор коалиций выключен                            | маскирование вообще разбирается                            |
| маскирование объявляется структурно, без исполнения | перекрытие — гипотеза, а не факт                           |
| снимается пара вместо всех маскировщиков            | единица — множество, а не пара (тройка класс+свойство+хук) |
| маскировщики сравниваются с базовым прогоном        | вопрос дифференциальный, эффект соседей сокращается        |
| имя маскировщика берётся позицией                   | названный сосед — измеренный, а не первый в списке         |
| контроль воспроизводимости «до» снят                | свип начинается с доказанной воспроизводимости             |
| контроль воспроизводимости «после» снят             | дрейф за промежуточные исполнения ловится                  |
| контроль идёт мимо пересборки контекста             | контроль идёт тем же путём, что контрфактические проходы   |
| судится директива, уже отказанная адресуемостью     | `Unmeasured/AlreadyRefused` — отказ, а не вердикт          |
| судится директива выключенного продюсера            | `Unmeasured/ProducerDisabled`, оба способа выключения      |
| универсум подменён на `published`                   | судим по произведённому                                    |

Последние восемь строк заработаны ревью исполнения, а не планом: механизм
маскирования переписан дважды (структурный признак → пара → множество с
дифференциальным сравнением), и каждая редакция проходила контроли предыдущей.

**Инвариант стенда — четыре условия, и «не красит остальные» в него не входит.**
Первая редакция требовала, чтобы каждая мутация красила ровно свой контроль;
измерение показало, что так не бывает и не должно: мутация в сравнении исходов
красит почти все случаи разом, и это её назначение, а не дефект. Проверяется:

1. каждая мутация красит **хотя бы один** случай — иначе это утверждение,
   которого никто не проверяет;
2. каждый случай краснеет **хотя бы от одной** мутации — иначе это тест,
   который нечем сломать;
3. ни одна мутация не красит **все** случаи — красящая всё не свидетельствует
   ни о чём;
   3a. и то же условие с другой стороны: случай, который красит **только**
   сплошная мутация, покрытым не считается. Две пробы, замыкающие сравнение
   исходов накоротко, объявлены сплошными и в покрытие не идут — иначе треть
   случаев была бы «доказана» ровно теми пробами, которые план сам называет
   несвидетельствующими. Это нашло ревью исполнения: одиннадцать из пятнадцати
   полей `Finding` держались только на них;
4. мутация, не применившаяся к исходнику, — отказ стенда, а не пропуск: продукт
   ушёл вперёд, и контроль молча перестал что-либо проверять.

Условие 4 не декоративное: в прототипе П2 три мутации разошлись с кодом после
рефакторинга и вернули «краснеет ноль случаев», что читается одинаково с «тест
не покрывает». Стенд обязан различать эти два ответа.

Мутация, ломающая загрузку класса, засчитана быть не может — она красит всё с
нулём ассертов.

**Код возврата PHPUnit — часть наблюдаемого, а не шум.** `failOnWarning` и
`failOnRisky` живут только в нём: прогон, где случай стал risky, в JUnit
выглядит зелёным и отличается лишь кодом. Стенд, читающий один XML, объявил бы
такую мутацию неувиденной. Ненулевой код без единого красного случая — отказ.

**Списки полей отпечатка проверяются в обе стороны.** Рефлексивный страж видит
исчезновение имени, но не перенос имени между идентичностью и границей: union
не меняется. Поэтому поведенческий тест берёт ожидание **из самих констант**, и
перенос имени делает ожидание ложным при неизменившемся поведении.

## Фикстуры, которых требуют контроли

Все уже существуют: их завёл П2, и П3 их не пишет, а доказывает кусающимися.

- Пара «действующая + инертная» на одном якоре и одном правиле.
- Классовая директива, чья группа содержит **больше одной** записи и чей исход
  зависит от записи, не являющейся первой.
- Пара класс+метод одного правила с совпадающим вердиктом — коалиция.
- **Тройка** на одном субъекте (класс + метод + хук): ни одна пара исход не
  двигает, тройка двигает.
- Мёртвая директива рядом с живой — и она же с двумя соседями, живым и мёртвым.
- Директива, чья величина уже прошла поднятую границу, — `Overrun`.
- Правило, не публикующее границу, — `boundaryObservable = false`.
- Пятнадцать полей `Finding`, по кейсу на поле.

Доказательство «фикстура кусается» — это и есть матрица мутаций: случай, который
не краснеет ни от чего, кусаться не доказан.

## Дом контролей

`scripts/finding-gate-controls.php` такие пробы **не принимает**: его `Control` и
`Expectation` типизированы вокруг `FailureClass` гейта, то есть вокруг того, как
падает сравнение двух деревьев, — а здесь наблюдаемое другое, вердикт аудита на
фикстуре. Поэтому отдельный скрипт рядом, `scripts/directive-audit-controls.php`,
запуск через `composer directives:controls`, явный код возврата.

Что переиспользуется без изменений — `Mutation`, `Scratch`, `Shell` того стенда.
Это не экономия строк, а перенос трёх решений, каждое из которых уже оплачено:
клон по содержимому из git вместо всего каталога, отказ при мутации, которая не
применилась или применилась не один раз, и запись **не через хардлинк**.
Прототип П2 наступил на первое и третье.

Наблюдаемое читается из JUnit XML, а не из `--testdox`: имя случая и его исход
нужны машинно, а текстовый отчёт для этого не предназначен.

## Definition of Done

- `composer directives:controls` исполняет положительную пробу и двадцать
  мутаций, и все четыре условия инварианта выполнены; таблица прогона читается
  структурно.
- Каждая фикстура доказана кусающейся — то есть каждый случай краснеет хотя бы
  от одной мутации.
- `composer directives:controls` — exit 0; `composer check` — exit 0;
  `composer gate -- --reference=<коммит П2>` — GREEN. `composer gate:controls`
  не трогается: сравнение исходов гейта пакет не меняет.
- Манифест обновлён, если пакет завёл production-декларации.
- Коммит и полная цепочка до начала П4.

# Пакеты A–D — механический свип по живым поверхностям

Четыре пакета, наборы файлов не пересекаются, исполняются параллельно.
Ни один не коммитит: коммит K2 собирает оркестратор.

## Общее правило свипа, одинаковое для всех четырёх

Шесть замен, целыми идентификаторами, барьер `(?<![\w.-])…(?![\w.-])` —
тот же, каким снято перечисление. Замена подстрокой запрещена: `complexity.cyclomatic`
— собственный префикс `complexity.cyclomatic.callable`, а `--cyclomatic-warning`
и `#[CliAlias('cyclomatic-warning', …)]` **не должны двигаться вовсе**
(ADR 0048 §6: в warn-and-default поверхность переименования не заходят).

```
architecture.coverage        -> architecture.coverage-gap
complexity.cyclomatic        -> complexity.ccn
design.inheritance           -> design.dit
maintainability.index        -> maintainability.mi
duplication.code-duplication -> duplication.clone
design.type-coverage.pct     -> design.type-coverage.all
```

**Инструмент — скрипт на python, не `sed -i ''`.** В этом shell `sed -i ''`
умеет съесть пустой аргумент, не тронуть файл и отрапортовать успех; ложно-зелёный
свип неотличим от выполненного. Каждый пакет обязан после мутации предъявить
**счёт вхождений до и после** по своему набору файлов, а не текст отчёта.

**Мест заморозки три, а не два — измерено исполнением.** Первая редакция
называла продуктовую константу и два файла-стража. Третье — юнит-тест
`CodeDuplicationRuleTest::itKeysOccurrenceToTheFrozenChannelSpellingNotToName`:
он строит `OccurrenceKey::semantic('duplication.code-duplication', …)` и
сравнивает с ключом, который выдаёт правило. Свип переименовал этот литерал, и
тест стал утверждать ровно обратное тому, ради чего написан — что ключ
occurrence следует за **именем**, а не за замороженным написанием. Поймал это
не страж (стражи пиннят литералы и по построению не краснеют), а сам тест: в
продукте константа осталась замороженной, хеши разошлись. Признак этого класса
повреждений — старое написание в роли **ключа идентичности** (occurrence key,
отпечаток, пиннутый хеш), а не в роли имени правила.

**Исключения, поимённо, для всех пакетов:**

| место                                                                                                                                     | почему не трогать                                                     |
| ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `src/Analysis/Evidence/Duplication/CodeDuplicationRule.php:37`                                                                            | `OCCURRENCE_KIND` заморожен на сегодняшнем написании                  |
| `tests/Analysis/Finding/Integration/OccurrenceKindFreezeGuardTest.php`                                                                    | страж пиннит литерал; не краснеет при переименовании — это правильно  |
| `tests/Analysis/Finding/Integration/OccurrenceLeafFreezeGuardTest.php`                                                                    | то же для двенадцати листовых констант                                |
| `tests/Analysis/Evidence/Duplication/Unit/CodeDuplicationRuleTest.php`, строка с `OccurrenceKey::semantic('duplication.code-duplication'` | **третье место заморозки, первая редакция его не называла**; см. ниже |
| `docs/adr/**`, `docs/internal/plans/**`                                                                                                   | исторические записи; правка — порча                                   |
| `CHANGELOG.md` в секциях выпущенных версий                                                                                                | то же                                                                 |
| `docs/internal/generated/**`                                                                                                              | регенерируется, не правится                                           |

## Пакет A — `src/`

**Набор:** `src/**`, кроме `src/Analysis/Configuration/Preset/*.yaml`
(они у пакета D).

**Объём: 109 вхождений в 104 местах.** Свидетели совпадают точно — расхождение
первой редакции было артефактом сравнения (места против вхождений, плюс три
файла пресетов, которые принадлежат пакету D); см. `00-overview.md`. По именам:
`architecture.coverage` 18, `complexity.cyclomatic` 39, `design.inheritance` 6,
`maintainability.index` 11, `duplication.code-duplication` 22,
`design.type-coverage.pct` 13. Свип меняет 108 и оставляет 1.

**Запрет, который свип не нарушит, а рука нарушит.** Фразу
`Maintainability Index` в прозе трогать **запрещено**: это академическое название
метрики (CLAUDE.md, Metrics Policy), а не код канала, и ADR 0048 переименовал
код. Места: `MaintainabilityRule.php:54` (описание правила), `:121` (текст
находки), `MetricHintCatalog.php` (human label), докблоки и README. Барьерный
свип их не видит — другой регистр и пробел вместо точки; запрет нужен против
правки «на согласованность». То же для `Cyclomatic Complexity` и
`Depth of Inheritance Tree`. К0м измерил цену нарушения: перевод этой фразы
картой давал 24 отказа гейта из 33.

**Особые места, которые пакет обязан посмотреть глазами, а не только свипом:**

- `src/Analysis/Evidence/ComputedMetrics/**/ComputedMetricDefaults.php:85` —
  встроенная формула `health.typing` читает `m["design.type-coverage.pct"]`.
  Не переедет — `health.typing` молча начнёт считать по отсутствующему ключу.
  Свип это место закрывает, но пакет обязан назвать его в отчёте отдельно
  и предъявить, что оно изменилось.
- `src/Reporting/Template/**` — исходники JS отчёта входят в поверхность `src`.
  Если свип их задел, нужен `composer build:js`; собранный бандл — тоже часть
  набора A.
- `MetricHintProvider` и всё, что печатает подсказку по ключу метрики.
- `src/**/README.md` — документация компонентов живая, переезжает.

**DoD A:** счёт до свипа — 109 вхождений по шести именам; после свипа `grep`
шести старых написаний по `src/` даёт ровно один результат — замороженный
литерал; фраза `Maintainability Index` в прозе не изменена; `composer phpstan` и `composer cs-check`
зелёные; если тронут `src/Reporting/Template/`, `composer build:js` выполнен и
`composer test:js` зелёный. `composer test` в DoD пакета **нет** — см. ниже.

## Пакет B — `tests/`

**Набор:** `tests/**`, кроме двух файлов-стражей заморозки.

**Объём:** 892 вхождения — самый крупный пакет.

**Особое:** пакет **не добавляет и не удаляет тестов**. Если после свипа падает
тест, чьё падение не объясняется переименованием, это находка, а не повод
править — она идёт в отчёт пакета, а не в код.

**DoD B:** `grep` шести старых написаний по `tests/` даёт только строки внутри
двух стражей; свип не добавил и не удалил ни одного метода
(`git diff --stat` по числу строк совпадает с перечислением). `composer test`
в DoD пакета **нет** — см. ниже.

### Почему у параллельных пакетов нет древесных ворот

Первая редакция требовала `composer test` от B и запуск
`cross-tool-comparison.py` от D. Ни то ни другое **не выполнимо внутри
пакета**: A, B, C и D идут параллельно, и до слияния всех четырёх дерево
несогласовано по построению — тесты B адресуют новые имена, которых `src/` ещё
не знает, пока не закончен A. Пакет, чей DoD требует зелёного древесного
прогона, либо ждёт сиблинга (тогда параллельность фиктивна), либо
рапортует зелёное, которого не было.

Поэтому: **пакет доказывает свой набор, дерево доказывает оркестратор.**
Локальные ворота (`grep` по своему набору, `phpstan`/`cs-check` для `src/`,
`docs:check` для `website/`) остаются в пакетах; `composer test`,
`composer check:code` и запуск `cross-tool-comparison.py` переезжают в проверку
перед K2, к оркестратору, где дерево уже согласовано.

## Пакет C — `website/docs/`

**Набор:** `website/docs/**` **плюс `website/CONTRIBUTING_DOCS.md`**. Файл
живой (правила структуры и стиля документации), он есть в перечислении, но
`website/docs/**` его не захватывает, а поимённый список набора D его не
называет — без этой строки он не принадлежал бы ни одному пакету.

**Объём:** 265 вхождений — 263 в `website/docs/**` (142 EN, 121 RU) плюс 2 в
`CONTRIBUTING_DOCS.md`, у которого RU-пары нет по построению. Обе языковые
версии правятся одновременно.

**`website/docs/changelog.md` — симлинк на корневой `CHANGELOG.md`, и он в набор
не входит.** Обнаружено исполнением: свип по `website/docs/**` проходит сквозь
симлинк и физически пишет в файл вне набора — так и произошло, 21 вхождение,
откачено `git checkout --`. Все 21 лежат в **выпущенных** секциях (в
`[Unreleased]` их нет), то есть подпадают под запрет из таблицы исключений выше:
переписывать их значило бы задним числом менять то, что версия объявила. Ни
перечисление, ни оракул этих 21 в `website_docs` не считают — ни `sweep.php`, ни
Symfony Finder по симлинкам не ходят, — поэтому счётные ворота 265 верны, а
неверна была формулировка DoD.

**Особое:** `website/docs/reference/default-thresholds.md` и страницы правил
группы должны остаться согласованными с фактическими умолчаниями; имя канала
меняется, значения — нет.

**DoD C:** `grep` по `website/` **с `--exclude=changelog.md`** чист — без этого
исключения ворота недостижимы, а достигнутые означали бы порчу истории;
`composer docs:check` зелёный (строгая сборка mkdocs); счёт EN и RU изменений
назван, и расхождение объяснено.

**Набор, поимённо** (перечисление, а не «всё остальное»):

| `README.md`                                                 | 1         | живая документация                                                                                    |

| `docs/internal/CLI_CONVENTIONS.md`                          | 4         | живая документация                                                                                    |
| `docs/internal/SCANNER_VALIDATION_ROUND_2_PLAN.md`          | 7         | исторический — **не правится** (решено, см. ниже)                                                     |

| `scripts/cross-tool-comparison.py:259`                      | 1         | `--disable-rule=duplication.code-duplication` — **входит в `composer check` через `test:cross-tool`** |
| `scripts/directive-audit-controls/Probes.php`               | 3         | **посмотреть глазами**: ссылки на забаненное правило в контролях аудита директив                      |

`qmx.yaml` и `qmx.yaml.example` (8 вхождений) **в набор D не входят** — они
целиком принадлежат пакету F вместе с ключом секции; см. `00-overview.md`.

**Не входит в набор D и никем не правится:**
`scripts/finding-gate/SelfTest.php` (**14** вхождений с барьером идентификатора;
безбарьерный счёт даёт 22, разница — формы `complexity.cyclomatic.callable` и
`.class`) и `scripts/finding-gate-controls/Controls.php` (1). Измерено: это **собственные
синтетические фикстуры самотеста гейта**, включая уже написанную там пару
`complexity.cyclomatic → complexity.ccn` как пример. Они не ссылаются на
настоящий канал, и свип по ним сломал бы самотест. Пакет D обязан подтвердить
это чтением, а не принять на веру: если хоть одно из десяти окажется настоящей
ссылкой, оно переезжает и называется в отчёте.

`scripts/finding-gate/RenameMaps.php:113` и `SubjectLevel.php:22` — комментарии,
объясняющие механизм на примере; трогать не нужно, назвать в отчёте нужно.

**Решение по `SCANNER_VALIDATION_ROUND_2_PLAN.md`:** документ **исторический**,
свипом не правится. Он — запись состоявшегося раунда валидации, а не живая
инструкция; править в нём написания значило бы задним числом переписать то, что
раунд наблюдал. Это то же правило, по которому из свипа исключены `docs/adr/` и
`docs/internal/plans/`. Пакет подтверждает чтением заголовка (документ описывает
прошедший раунд), а не принимает решение заново.

**DoD D:** каждый файл набора назван в отчёте с числом «до/после»; 23
вхождения самотеста гейта и контролей прочитаны и подтверждены как синтетические;
`SCANNER_VALIDATION_ROUND_2_PLAN.md` не тронут. Запуск
`scripts/cross-tool-comparison.py` — у оркестратора перед K2, не в пакете.

## Что оркестратор проверяет перед K2

1. Полный `grep` шести старых написаний по всему дереву: остаются только
   исторические записи, генерируемые артефакты, два стража, один замороженный
   литерал, алиасы CLI и 23 вхождения в самотесте гейта и его контролях — и
   ничего больше.
2. `composer check:code` целиком.
3. `git diff --stat` пакета против ожидаемого объёма из перечисления.

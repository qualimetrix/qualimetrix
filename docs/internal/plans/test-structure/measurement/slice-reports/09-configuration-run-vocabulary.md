- `Unit/PromiseEffect/ClassifierTest.php`, `FloorTest.php`, `LedgerVocabularyTest.php` — все три `require_once` файлы из `scripts/promise-effect/*.php` под неймспейсом `Qualimetrix\PromiseEffect`; этот неймспейс физически не в `src/`. ## Дубли и противоречия

- **`YamlConfigLoaderTest.php` × `YamlNormalizationCharacterizationTest.php` × `YamlKeyReachabilityTest.php`** (все три — Configuration): у каждого файла в докблоке заявлено «мы про разное» (behaviour vs snapshot vs reachability), но по факту кейсы почти буквально повторяются для одних и тех же root-ключей: `cache.dir`/`cache.enabled`, `parallel.workers`, `coupling.framework_namespaces`, идентификатор-секции `rules`/`computedMetrics` (сохранение имени + нормализация опций), `architecture.layers`/`allow`/`coverage-gap`/`max_expanded_layers`. Три файла защищают одно и то же поведение `YamlConfigLoader` тремя почти одинаковыми наборами утверждений. Разумная цель (ADR 0009 миграция) не отменяет того, что конкретные строки дублируются.
- **`DeadConfigurationKeysTest.php` × `YamlConfigLoaderTest.php`**: отказ по корню `namespace` проверяется в обоих файлах (`itRejectsTheRemovedNamespaceRoot`, `itRejectsTheRemovedNamespaceRootRegardlessOfItsChildren` в `YamlConfigLoaderTest`; `'namespace strategy'`/`'namespace composer json'` в `DeadConfigurationKeysTest`) — тот же SUT, то же утверждение.
- **`AnalysisConfigurationCacheDirResolutionTest.php` × `AnalysisConfigurationTest.php`**: один SUT (`ConfigurationDocument`), оба — маленькие файлы про `workingDirectory()`/`contributions()`. Разумно слить в один класс.
- **`Run/Unit/Discovery/FinderFileDiscoveryTest.php` × `FinderFileDiscoveryAbsolutePathTest.php`**: не строгий дубль (второй файл целится в контракт `AbsolutePath`-ключа, введённый ADR 0015 Phase 2), но покрытие сильно смежное — оба гоняют один и тот же `FinderFileDiscovery` на одинаковых сценариях (одиночный файл, директория, дедупликация, несуществующий путь). Разница оправдана историей миграции, но сегодня это двойная защита одного поведения.
- **`AnalysisConfigurationTest::itDoesNotExposeAMergedGenericConfigurationBag`** и **`ConfigurationHolderTest::itDoesNotProvideMutableReplacementOperations`** — не дубль по содержанию (разные списки запрещённых методов), но один и тот же слабый паттерн: рефлексия «метода X нет» вместо проверки поведения. См. раздел ниже.
- Противоречий (двух тестов, утверждающих несовместимое об одном поведении) в срезе не найдено.

## Чем проверено и чего этот способ не видит

Аудит выполнен только чтением: полное содержимое всех 63 файлов плюс релевантные README (`src/Analysis/Configuration/README.md`) прочитаны целиком; SUT выводился из `use`-импортов и фактических вызовов в теле теста, а не из имени файла. Для control-кандидатов проверялось, куда указывает `require_once` (`scripts/...` vs `src/...`), а не полагались на неймспейс — неймспейс `Qualimetrix\PromiseEffect` мог бы обмануть поиск по одному только имени.

Чего этот способ не видит:
- **Не запускались тесты и `composer check`** (по прямому запрету брифа) — ни один вывод не подтверждён исполнением. В частности, догадка про докблок `AnalysisPipelineIntegrationTest` («тесты должны падать») не проверена прогоном — вывод сделан по чтению кода (тела тестов явно проверяют исправленное, а не сломанное поведение) и может расходиться с реальностью, если сохранился какой-то `markTestSkipped`/условный путь, который я не заметил.
- **Не измерялось реальное покрытие мутациями** — «не дубль» или «дубль» определялись по текстовому сравнению утверждений и фикстур, а не по прогону мутационного тестера. Возможны как ложные дубли (два теста выглядят похоже, но по факту ловят разные мутанты), так и пропущенные дубли (разная форма кода, тот же самый мутант).
- **Не проверялась актуальность `@covers`/`#[CoversClass]`** программно — бралось на веру, что атрибут соответствует фактическому импорту; в подавляющем большинстве файлов это совпадало.
- Заключение «SUT — `scripts/`, не `src/`» опирается на текущее расположение файлов `scripts/promise-effect/*.php` и `scripts/directive-audit*/*.php` в этом рабочем дереве; если владелец решит физически перенести эти классы под `src/` (например, в `src/Infrastructure/Tooling/`), вывод о категории `control` придётся пересмотреть — сейчас он верен для данного состояния дерева.
- Долгие/большие файлы (`CollectionOrchestratorTest` 1190 строк, `FileProcessorTest` 847, `AnalysisPipelineIntegrationTest` 964, `YamlConfigLoaderTest` 1179, `ThresholdPopulationAgreementTest` 705) прочитаны целиком, но при таком объёме нельзя исключить единичный пропущенный тонкий дефект на уровне одной строки-ассерта.

## Допущения

- Категория `unit` присваивалась одному классу-SUT независимо от того, пишет ли тест временные файлы через `sys_get_temp_dir()`/`tempnam()` — такой FS-доступ типичен для конфиг-загрузчиков и в этом проекте физически соседствует с прочими unit-тестами (папка `Unit/`). Более строгое прочтение брифа («integration = несколько классов ИЛИ ФС») дало бы `integration` почти всем loader/reader-тестам (`YamlConfigLoaderTest`, `ComposerReaderTest`, `PresetResolverTest`, `ConfigFileStageTest`, `DeadConfigurationKeysTest`, `ProjectScopeCoverageTest`, discovery-тесты в `Run/`) — это смена ~10 строк таблицы с `unit` на `integration`; выбранное более мягкое прочтение сделано явным здесь, чтобы владелец мог отвергнуть его.
- `MultiNamespaceAnalysisTest` размечен «functional (2 теста) / integration (1 тест)» — категория присвоена файлу целиком как functional, так как это доминирующий и более показательный режим (реальный бинарник через `Process`).
- Для control-файлов «правильный каталог» не назван конкретной директорией: решение о том, жить ли таким тестам под `tests/` вообще (или перейти в `scripts/promise-effect/tests/`, `scripts/directive-audit/tests/`, отдельный `tests/Tooling/`) — оставлено владельцу, как и просит бриф п.4 «отдельным вопросом решение владельца».
- Дубль-группа по `YamlConfigLoader` (3 файла) оценивалась как «налог», а не как штраф какому-то одному файлу: без прогона мутационного тестера нельзя достоверно сказать, какой из трёх — лишний, а какой ловит уникальный мутант; рекомендация «слить» — гипотеза, не факт.

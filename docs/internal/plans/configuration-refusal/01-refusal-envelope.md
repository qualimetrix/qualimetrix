## 1. Что именно чинит этап

Главный вывод сведения — «код возврата определяется не классом ошибки, а тем, какая
команда её поймала» — держится на четырёх независимых механизмах предъявления, и все
четыре в моём наборе:

1. **Разные `catch`-лестницы.** `CheckCommand.php:160-201`, `BaselineCommand.php:44-65`,
   `DirectivesCommand.php:140-175`, `LayerAssignmentCommand.php:158-172` — четыре разные
   таксономии над одним и тем же множеством исключений.
2. **Разные потоки.** `check` пишет через `ResultPresenter::writeDiagnostic` →
   `ErrorStream` (stderr); `baseline:*`, `directives`, `rules`, `debug:layer-assignment`
   — через `$output->writeln` (stdout).
3. **Разные числа для одного смысла.** `CheckCommand::EXIT_CONFIG_ERROR = 3`,
   `DirectivesCommand::EXIT_CONFIG_ERROR = 3`, `BaselineCommand::fail()` по умолчанию
   `self::FAILURE = 1`, `LayerAssignmentCommand` — `self::FAILURE` даже там, где
   `ConfigurationFailure::message()` признала ввод пользовательским.
4. **Нет сети под `Error`.** `setCatchErrors()` не вызывается ни разу
   (`grep` по `src/` и `bin/` — пусто), умолчание `catchErrors = false`
   (`vendor/symfony/console/Application.php:80`), ветка `:200` перебрасывает,
   собственный обработчик снят в `finally` `:215-228` → PHP-фатал, код 255, трасса в
   оба потока.

## 2. Развилки, решённые мной

### 2.1. Конверт: какие форматы машинные, и что в конверте лежит

Форма `{"error": …, "exit_code": …}` не изобретается: она уже существует у
`DirectiveAuditPresenter::jsonError()` (`:132`) и у
`LayerAssignmentCommand::reportError()` (`:193`), и уже несёт **код 1** на маршруте 34.
Берётся оттуда дословно.

**Схема конверта описана здесь и только здесь.** Ровно два поля:
`error` — обрамлённое `summary()` носителя (одна строка), `exit_code` — число.
`origin()` и `position()` структурно в конверт **не** попадают: они входят в текст
`error` через формулировку. `03-carrier-and-normalization.md` §2.1 на это ссылается и
своего описания не держит — два описания одной схемы расходятся молча.

**Отвергнуто: `{error, exit_code, origin, position}` со структурными полями.** Довод за —
машинный потребитель разобрал бы позицию без парсинга текста. Против: сегодня ни один
потребитель этого не просит, а поля `position.accepted`/`isClosed` — публичный контракт,
который пришлось бы поддерживать во всех девяти JSON-несущих форматах и в SARIF-схеме
заодно. Условие пересмотра названо в `01-refusal-external-contracts.md` §12 как возврат, а не как правка контракта носителя.

Открытым был не вид конверта, а какие из двенадцати форматов `check` его получают.
Перечисление — весь список `FormatterRegistry` (снято `bin/qmx check --help`, 12 имён;
слепое пятно способа — форматтер, зарегистрированный, но скрытый из `--help`:
`text-verbose`, он в таблице):

| формат                                                       | контракт stdout                 | предъявление отказа   |
| ------------------------------------------------------------ | ------------------------------- | --------------------- |
| `summary`, `text`, `text-verbose`                            | человеческий                    | stderr, stdout пуст   |
| `json`, `sarif`, `gitlab`, `metrics`, `health`, `suppressed` | JSON-документ                   | **конверт на stdout** |
| `checkstyle`                                                 | XML-документ                    | stderr, stdout пуст   |
| `github`                                                     | команды workflow (`::error::…`) | stderr, stdout пуст   |
| `html`                                                       | документ для чтения/сохранения  | stderr, stdout пуст   |

**Правило распространяется на команду, а не только на формат, и потому команды
перечислены.** Иначе «любой машинный формат несёт конверт» осталось бы утверждением о
множестве без перечисления множества — и ровно так `graph:export --format=json` уехал бы
на exit 3 с нулём байт, то есть в тот самый дефект, ради которого затеян раунд. Снято
чтением опций всех тринадцати команд на `1513bf67`:

| команда                                      | машинный формат                     | как получает конверт                                                                    | пакет         |
| -------------------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------- | ------------- |
| `check`                                      | девять из двенадцати (таблица выше) | предъявитель в команде                                                                  | P01-3         |
| `directives`                                 | `json`                              | предъявитель в команде                                                                  | P01-5         |
| `debug:layer-assignment`                     | `json`                              | предъявитель в команде                                                                  | P01-5         |
| `graph:export`                               | `json` (`dot` — не JSON-документ)   | **предъявитель в команде плюс собственная `catch`-лестница**, которой у неё сегодня нет | P01-5         |
| `baseline:rename-channels`                   | `json`                              | предъявитель в `BaselineCommand`, формат протягивается из команды                       | P01-4         |
| `baseline:{generate,update,cleanup,explain}` | нет                                 | одно предложение на stderr                                                              | P01-4         |
| `rules`, `hook:*`                            | нет                                 | одно предложение на stderr                                                              | P01-5 / никто |

**Решение по `rules`: конверта не получает, и это не пропуск.** У команды нет опции
формата вовсе (`RulesCommand::configure()` объявляет только `--group`), поэтому машинной
трубы, в которую конверт можно было бы положить, не существует; ей нужен только код 3, и
его даёт лестница `Application` (§2.4). Отвергнуто **завести ей `--format=json` заодно** —
это новая пользовательская поверхность в раунде, который поверхности сокращает.

**Решение по `graph:export`: предъявитель проводится и в неё, вместе с клаузой в самой
команде.** Отвергнуто **оставить её лестнице `Application`**: там формат неизвестен по
построению (§2.2), значит `--format=json` дал бы код 3 и ноль байт на stdout — предмет
раунда, воспроизведённый в команде, которую раунд правит. Отвергнуто **признать её
`--format=json` не машинным**: он печатает JSON-документ графа, и потребитель у него
ровно тот же, что у `check --format=json`.

`baseline:rename-channels` наследует лестницу `BaselineCommand::execute()` вместе с
четырьмя другими `baseline:*`, поэтому клауза одна на всех; протянуть в неё формат — это
работа в самой команде, и она названа в P01-4.

**Отвергнуто: родная форма ошибки для каждого формата** (`<error>` в checkstyle,
`::error::` для github). Довод за — консьюмер читает один поток. Против, решающее:
это ровно то умножение поверхностей, которое раунд схлопывает, и ни у XML-конверта
checkstyle, ни у github-аннотаций нет стандартной формы «прогон отказался» — она была
бы придумана здесь и стала бы четвёртым диалектом отказа.

**Отвергнуто: конверт во всех двенадцати.** JSON-блоб в трубе, где консьюмер ждёт XML,
хуже пустого stdout: пустой поток он отличит от документа, а блоб уронит его парсер.

### 2.2. Внутренняя ошибка под машинным форматом

**Решение: тот же конверт `{error, exit_code}` с кодом 1 и шапкой `Internal error: …`
там, где формат известен команде; голый stderr там, где он ещё не известен.**

Формат известен внутри `execute()` — там внутренняя ошибка ловится `catch (Throwable)` и
предъявляется конвертом с кодом 1. Формат **не** известен на уровне `Application`: до
выбора команды и до разбора её опций форматтера нет. Там — stderr и код 1.

Довод: маршрут 34 уже сегодня печатает конверт с `exit_code: 1`, то есть форма проверена
и код 1 в ней законен. Консьюмер, разбирающий stdout, отличит «инструмент упал» от «нет
вывода» — сегодня оба вида дают ноль байт.

**Отвергнуто: голый stderr всегда.** Довод за — «внутренняя ошибка не документ». Против:
это оставляет машинного потребителя ровно с тем, что раунд назвал дефектом (код без
байтов), и заводит второй способ узнать об ошибке в одной и той же трубе.

### 2.3. Семантика `-q`

**Решение: `-q` подавляет полезную нагрузку и прогресс, но никогда — сообщение,
завершающее прогон. Отказ и внутренняя ошибка пишутся уровнем
`OutputInterface::VERBOSITY_QUIET`, то есть проходят сквозь quiet.**

Три довода, каждый измерен:

1. **Прецедент внутри зависимости.** Symfony печатает необработанный `Throwable` именно
   так: все `writeln` в `Application::doRenderThrowable` несут `VERBOSITY_QUIET`
   (`vendor/symfony/console/Application.php:882,887,888,934,937,956,959`). «Сообщение,
   которым кончается прогон, исключено из quiet» — не наше изобретение.
2. **`-q` и так уже съедает нагрузку.** Измерено на валидной конфигурации:
   `check src --format=json -q` → `ec=0, stdout 0 байт, stderr 0 байт`. Значит правило
   «quiet прячет документ» не нарушается: документа под `-q` нет ни в успехе, ни в отказе.
3. **Симметрии не ломается.** Под `-q` пользователь получает ровно одно предложение
   там, где раньше не получал ничего, — и получает его на том же канале, что и без `-q`.

**Отвергнутая альтернатива — «quiet значит только код возврата».** Она законна, и
позиция #51 (`measurement/verdicts-30-75.md:81`) не вполне дефект X13: до него было
0 байт при exit **0**, после — 0 байт при exit **3**, то есть по оси кода стало строго
лучше, и сегодняшний тест
`tests/Infrastructure/Console/Unit/RuleOptionKeyDoorSymmetryTest.php:186-191`
(`itStillRefusesUnderQuiet`) пришпиливает именно её как осознанное поведение.

Отвергнута она по двум причинам. Первая: код 3 говорит «ввод отвергнут», но не говорит
**какой** ключ и **в каком файле**; пользователь, поставивший `-q` в CI ради тихого
лога, получает красную сборку без единой подсказки и вынужден повторить прогон руками —
то есть `-q` покупает тишину ценой второго прогона. Вторая: она делает `-q`
единственным флагом, меняющим не громкость, а состав диагностики, — и это тот же род
дефекта, что раунд чинит на оси кодов, только на оси потока. Прогон, который нечем
объяснить, не становится объяснимым оттого, что пользователь попросил тише.

В ADR. Тест `itStillRefusesUnderQuiet` переписывается (P01-3): утверждение «`-q` глушит
предложение» становится утверждением «`-q` глушит отчёт и оставляет предложение».
Проверено, что тест кусается: `CommandTester` с `capture_stderr_separately` строит
настоящий `ConsoleOutput` (`vendor/symfony/console/Tester/TesterTrait.php:147`), то есть
`ErrorStream` привязывается к реальному stderr, а не к `NullOutput`-заглушке, и
сегодняшнее `assertSame('', $stderr)` зелено по существу, а не по недосмотру.

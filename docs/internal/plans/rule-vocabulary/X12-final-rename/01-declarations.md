# К1 — токен шага, каталог плана и объявление решений

Первый коммит. Ничего не переименовывает; открывает возможность объявить
решения так, чтобы инструмент их принял.

## Почему нужен новый токен

`scripts/generate-rename-enumeration.php` требует, чтобы решённая строка
называла шаг (`assertEveryDecisionNamesItsStep()`, `:644`), и берёт список
допустимых шагов **только** из заголовков `../PLAN.md`
(`planSteps()`, `:610`, регекс `^#{2,4}\s+([А-Яа-яA-Za-z][^\s.]*)\.`).

Измерено: PLAN.md сегодня отдаёт 33 токена, среди них `П0` и `П1` — **пакеты
работ шага Ш5 того плана**, а не шаги этапа 04. Токенов `П4`/`П5` там нет.
Завести заголовок `### П4.` значило бы дать букве `П` в одном файле третий
смысл; `emitMapsForStep()` группирует строки по точному совпадению строки шага
и молча смешал бы разные заходы в одну карту.

**Решение: токен `Х12П4`.** Не коллидирует ни с `П`-пакетами, ни с
`Ш`-шагами, ни с `Р`-решениями, и по построению читается как «П4 захода Х12».

Заголовок ставится в раздел `## Шаги` файла `../PLAN.md`, последним, и
содержит только отсылку: тело шага живёт здесь, дублировать его в PLAN.md
нельзя — две копии решения расходятся молча.

## Состав коммита К1

| файл                                                             | что                                                                             |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `../PLAN.md`                                                     | заголовок-заглушка `### Х12П4. Ломающее переименование словаря` со ссылкой сюда |
| `X12-final-rename/00-overview.md` … `04-release.md`              | этот план                                                                       |
| `X12-final-rename/enumeration-rename-sites.tsv`                  | перечисление мест                                                               |
| `scripts/generate-modular-architecture-production-inventory.php` | строка в `documentationDisposition()` на каждый новый `.md`                     |
| `../enumeration-renames.tsv`                                     | колонки `new` и `step` для десяти строк                                         |

**Любой новый отслеживаемый `.md` требует строки в `documentationDisposition()`
тем же коммитом** — иначе `check:artifacts` краснеет. Функция ведёт поимённый
список всех `.md` дерева, а не только тех, что под `docs/internal/plans/`;
формулировка брифа тут уже реальности. Это касается и **двух релизных файлов
карты**, которые появятся в K4 (`docs/migration/v0.26-rename-map.json` строки
не требует, `…-rename-map.md` требует). `.tsv` не требует; проверяется прогоном
`composer architecture:check` внутри К1, а не после.

## Отображение ролей в колонку `kind`

`enumeration-renames.tsv` знает три вида, `emitMapsForStep()` (`:715`)
раскладывает их по картам жёстко:

| роль в `decision-table.tsv` | `kind` в enumeration | карта             |
| --------------------------- | -------------------- | ----------------- |
| `channel-code`              | `channel`            | `channels.tsv`    |
| `producer-rule-name`        | `producer`           | `inputs.tsv`      |
| `metric-key`                | `metric-key`         | `metric-keys.tsv` |

Десять строк, которые получают `new` и `step=Х12П4`: шесть с `kind=channel`
(пять переименований плюс `design.type-coverage.pct` идёт как `metric-key`) —
точнее, пять строк `channel`, одна `metric-key`, четыре `producer`.

Порядок операций: заголовок в PLAN.md → правка колонок вручную →
`php scripts/generate-rename-enumeration.php` (без аргументов — это запись) →
`php scripts/generate-rename-enumeration.php --check` (должен быть чистым).

## Что `--emit-maps=Х12П4` даст и чего не даст

Даст: пять строк `channels.tsv`, одну `metric-keys.tsv`, четыре `inputs.tsv`.

**Не даст, и это не пробел, а граница модели** (докблок `:686-712`): скрипт
моделирует *идентичности*, а ключ опции и ключ секции конфигурации —
не идентичности. Рукописной остаётся **одна** строка:

`coverage:` → `coverage-gap:` — четвёртая форма `inputs.tsv`, «ключ
конфигурации так, как его пишет YAML-документ, с двоеточием». Строки в
`decision-table.tsv` у неё нет намеренно (ADR 0048, «Third»), значит нет и в
`enumeration-renames.tsv`.

Отдельной рукописной строки под `--disable-rule=`/`only_rules` **не нужно**:
единственная такая заявка корпуса — `--disable-rule=duplication.code-duplication:project`
в кейсе `disabled-rule-duplication` — потребляет ту же строку `inputs.tsv`, что
`--emit-maps` уже печатает для `duplication.code-duplication`
(перечисление потребителей — в `03-gate-and-hand-surfaces.md`, E1).

Обе стороны держит сам гейт: необъявленный вход даёт
`reference-input-untranslated`, объявленная строка, ничего не переведшая, —
`map-stale`.

## Запрет формы `rule#code` для `architecture.coverage`

`decision-table.tsv` для этой строки говорит прямо: `channels.tsv` **одна**, в
голой форме кода. Причина измерена в
`../X11-final-vocabulary/followups/naming-questions-answered.md`: форма
`rule#code` теряет обратное направление и конфликтует со строкой `inputs.tsv`
на того же производителя. Производитель здесь — `architecture.layer-violation`,
он **не переименовывается**, поэтому строки `inputs.tsv` у этого канала нет
вовсе.

## Строка `coverage:` переводит текст диагностики — механизм прочитан

Первая редакция называла это риском «надо измерить, попадёт ли». Механизм
прочитан по коду, и ответ — **попадёт, гарантированно**:

- `RenameMaps::SURFACES` ограничивает поверхностями только `METRIC_KEYS` и
  `REPORT_VALUES`. `INPUTS` там **отсутствует**, поэтому
  `appliesToSurface()` уходит в ветку `$surfaces === null` и возвращает `true`
  для любой поверхности: строка `inputs.tsv` применяется вперёд к **каждому**
  артефакту эталона, а не только назад ко входу;
- сообщение `DeclaredLayerReachability.php:96` начинается словами
  `Architecture coverage: %d edge(s)…`. Слева пробел, справа пробел; ни один не
  входит в `NAME_CHARS`, значит границы токена `coverage:` совпадают и
  подстановка сработает.

Оба запасных пути первой редакции закрыты: без строки `inputs.tsv`
конфигурация корпуса после пакета F читается эталоном как `coverage-gap: error`
— неизвестный ключ, exit 3, `reference-input-untranslated` ещё до сравнения; а
снять кейс `layers` нельзя, он единственный авторитетный владелец семи каналов
`architecture.*`.

**Решение — привести прозу сообщения ровно к тому, что даёт прямая карта.**
Продукт печатает `Architecture coverage-gap: %d edge(s)…`; эталон печатает
старое `Architecture coverage: …`, прямая карта переводит его в то же самое.
Переведённый эталон и кандидат совпадают побайтно — ни дельты, ни снятия кейса,
а диагностика начинает называть канал его новым именем. K0м обязан подтвердить
совпадение прогоном; если совпадение неточное (например, сообщение встречается
ещё где-то в другой огласовке), запасной ход — объявленная дельта на кейс
`layers`, и тогда её `reason` называет ровно эту причину.

## Definition of Done К1

- `php scripts/generate-rename-enumeration.php --check` — чисто.
- `php scripts/generate-rename-enumeration.php --emit-maps=Х12П4` печатает
  ровно 5 + 1 + 4 строки и не падает.
- `composer architecture:check` — зелёный (диспозиция документации на месте).
- `composer check:artifacts` — зелёный.
- Ни одно написание в дереве ещё не изменилось: свип не начат.

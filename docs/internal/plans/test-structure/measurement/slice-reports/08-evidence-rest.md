## Control candidates

- **Coupling/Unit/UnmatchedFrameworkNamespaceRuleTest.php**, the method
  `itPinsTheNumberOfClassificationSitesTheUniverseMirrors` (lines 161-172) — reads
  `src/Analysis/Evidence/Coupling/CouplingCollector.php` as text via `file_get_contents()` and
  counts occurrences of `$this->isFrameworkSymbol(` with a regex to pin down the number of
  classification sites. This is not control-invariant (not over every `src/` class, but over one
  specific product file), but it falls under the brief's control definition: "scans `src/` via
  reflection/as text for a layout invariant". The relocation decision belongs to the owner; the
  file as a whole is an ordinary unit test of the rule's behavior.

slice: all 74 files check the real behavior of product code (metric collectors, rules, VOs, AST
visitors, detectors) through a direct call or (in three cases) a real CLI run, not
repository/documentation/tooling-configuration state.

## Duplicates and contradictions

1. **CircularDependency/Unit/CycleTest.php** (the disambiguation tests, ~71-83+) ↔
   **CircularDependency/Unit/CycleMemberLabelsTest.php** — the same logic for resolving
   cycle-member name collisions is checked twice: directly on `CycleMemberLabels` and via
   delegation into `Cycle::toShortString()`. Not a strict duplicate (different SUTs), but
   redundant coverage of one branch.
2. **CircularDependency/Unit/CircularDependencyRuleTest.php**
   (`itKeepsCycleIdentityStableWhenMemberOrderChanges`) ↔
   **CircularDependency/Unit/CycleIdentityStabilityTest.php** — one and the same guarantee
   ("permuting cycle members doesn't change identity") is checked at two levels: with hand-built
   `Cycle` objects through the Rule, and with an end-to-end detector→rule run on real graphs.
3. **Cohesion/Unit/LcomCollectorTest.php**: the pair
   `itExcludesStaticMethodsFromLcom`(601)/`itDoesNotInflateLcomWithStaticMethod`(636) and the
   pair `itExcludesAbstractMethodsFromLcom`(733)/`itDoesNotInflateLcomWithAbstractMethods`(768) —
   confirmed by a line-by-line reading, both pairs check the same assertion on nearly identical
   fixtures.
4. **Cohesion/Unit/TccLccCollectorTest.php**: the pair
   `itExcludesStaticMethodsFromTccLcc`(657)/`itPreventsStaticMethodsFromInflatingTccLcc`(694) —
   the same pattern as in item 3.
5. **Coupling/Unit/RfcCollectorTest.php** ↔ **Coupling/Unit/RfcVisitorTest.php** —
   RfcCollectorTest almost entirely repeats scenarios already exhaustively covered by
   RfcVisitorTest (an empty class, a simple calculator, external calls, deduplication by name,
   internal calls, static calls, global functions, constructor calls, abstract methods, a
   complex example), adding only the `collect()` wrapper/the metric names in `MetricBag`.
6. **Coupling/Unit/NamespaceCboOptionsTest.php** — a thin file (1 default test), while real
   `fromArray()` coverage (min_class_count, a camelCase alias, warning/error, enabled=false) is
   already given by `CboRuleTest.php` through the same `NamespaceCboOptions` class.
7. **DependencyModel/Unit/DependencyGraphBuilderTest.php** ↔
   **DependencyModel/Unit/DependencyGraphTest.php** — both build the graph via
   `DependencyGraphBuilder` and check identical behavior (deduplication of repeated dependencies
   in Ce/Ca; excluding builtin classes from coupling while keeping `extends`) on different but
   semantically equivalent fixtures.
8. **DependencyModel/Unit/Extraction/DependencyVisitorTest.php**:
   `itResetsDependenciesAndImportsWhenReusedForAnotherFile`(462) and
   `itClearsResolverAndDependencyStateWhenBeginningASecondFile`(723) — both check the visitor's
   state reset between files.
9. **Design/Unit/TypeCoverage/TypeCoverageScaleTest.php** ↔
   **Design/Unit/TypeCoverage/TypeCoverageCollectorTest.php** — confirmed by grep: both pairs
   "100.0/0.0/66.67 on design.type-coverage.{param,return,property}" are present in both files on
   the same SUT (`TypeCoverageCollector`). The second file adds exactly one new check
   (`assertGreaterThan(1.0, ...)`), which doesn't justify a separate file.

## How this was checked and what this method cannot see

- **Coupling (19 files), DependencyModel (8), Duplication (9), Maintainability (5), Size (7) —
  48 files** were read by me in full and directly (via `Read`), with no intermediary; the SUT was
  determined by `use` expressions, constructors and `#[CoversClass]`, duplicates by matching
  specific assertions and fixtures between files. For large files
  (`DependencyVisitorTest.php`, 776 lines), method signatures were first gathered via `grep`, and
  disputed pairs ("reset" tests) were read through line by line.
- **CircularDependency and Cohesion (12 files)** were analyzed by a background agent; I
  personally re-checked its most weighty assertions — both LCOM/TCC duplicate pairs (matching
  line numbers and content confirmed by `grep`+`Read`). The rest of this agent's points (no
  duplicates/control/§9 violations in the remaining 8 files) were taken on faith after this
  partial check — if there's a systematic error in them from the same agent that both
  enumerated and judged, I won't catch it.
- **Design (14 files)** were analyzed by a second background agent; I personally re-read

## Assumptions

- "Correct directory" is left blank (`—`) where the test's directory already matches the owning
  capability in `src/Analysis/Evidence/{Capability}/` — no placement discrepancies (a test in the
  wrong capability directory) were found in this slice.
- Duplicates are flagged only where both the SUT (or a directly neighboring SUT in the same
  capability) and the specific checked assertion match — a shared theme (e.g. "static methods"
  or "state reset") without a matching assertion was not counted as a duplicate.
- Tests checking `Options`-class getters/defaults (`itGetsName`, `itHasOptionsDefaults`, etc.)
  are not flagged as a defect by default — they're cheap, follow the project's general
  convention and pin a public contract (a rule's name/CLI alias), not a tautology in the brief's
  sense ("an assertion on what it just plugged in itself"); only cases where the assertion
  literally checks the value just set, with no additional semantics, are flagged separately
  (`NamespaceInstabilityOptionsTest::itIsEnabledWhenTheEnabledFlagIsTrue`,
  `DependencyTest::itDependencyIsReadonly`).
- For the three functional tests (`UnmatchedFrameworkNamespaceIntegrationTest`,
  `DuplicationMemoryLimitProcessTest`) the `functional` category was assigned by the fact of an
  actual CLI/subprocess run — both explicitly and justifiably document why the unit level isn't
  enough (docblocks in the files themselves), so they aren't considered excessive despite the
  cost.
- No contradictions (two tests asserting incompatible things about the same behavior) were found
  in the 74 files checked.

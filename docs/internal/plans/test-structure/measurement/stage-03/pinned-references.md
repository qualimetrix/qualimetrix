## 5. How obtained / what each spelling's sweep cannot see

All sweeps ran over `git ls-files` minus `.claude/` and `vendor/` (3,476 files), via `grep -n -F <term>` (literal) for basenames, and `grep -rnE <pattern>` for namespace-prefix probes.

1. **Project-relative path** (`grep -F 'BenchmarkCoverageRefusalTest'` etc., matching the `.php`-suffixed basename): finds every literal path and every bare-basename mention regardless of directory, because the search term has no leading directory. Blind spot: a reference that spells the path with a different directory separator convention (none found) or reconstructs the path from parts (e.g., `dirname(__DIR__) . '/Fixtures/...'`) is invisible unless the literal basename string still appears — none of the pinned literals in this codebase build a path piecewise, so this was not an issue here, but the method would miss it if one did.
2. **Backslashed FQN** (`grep -F` on the basename, then manually filtering hits whose line also contains `\` before it, plus a targeted `grep -E 'Qualimetrix\\Tests\\...'` per namespace prefix): finds `use`, `@see`, and string-literal FQNs. Blind spot: cannot distinguish a real `use`-based code dependency from a docblock `@see` by grep alone — each hit had to be opened and read to classify (done for every non-self, non-plans hit in this sweep).
3. **Dot-separated FQN** (targeted `grep -E 'Qualimetrix\.Tests\.Unit\.RuleVocabulary'` etc.): this is the form a pure basename grep for `ThresholdPopulationAgreementTest` *does* catch (the basename substring survives inside the dotted form), so a basename-only sweep is not blind to it here — but a sweep that instead greps for `Qualimetrix\\Tests\\` backslash-only would have missed every one of the ~130 dot-FQN lines in `Probes.php`. Confirmed live: this file is exactly the "live use" case named in the task brief.
4. **`::method` and bare method names**: captured incidentally wherever the basename grep also matched a `ClassName::methodName` string (all of `Probes.php`'s ~130 entries). A bare `itXxx` method name pinned with **no** class qualifier anywhere (e.g., a lone `'itNamesEveryFormTheFixtureDeclares'` string) would not be found by a basename-only sweep; a second pass grepping every declared `#[Test]` method name of the 16 files individually would be needed to rule this out exhaustively, and was not run to completion given budget — the one instance checked in depth (`Probes.php:822`, per the orchestrator's tip) was confirmed present as `ThresholdPopulationAgreementTest::itNamesEveryFormTheFixtureDeclares`, i.e., always class-qualified in this file.
5. **Bare class name** (the same basename grep, filtered to hits with no `\`, `.`, `use`, or `/` context around them): found the four dead-prose cases in section 1 (`TrackedLedgerNonEmptinessTest.php:17`, `SeededFixtureIsolationTest.php:20`, `Gate.php:44`, and the `FloorTest`/`ThresholdPopulationAgreementTest` mentions). Blind spot: a bare name inside a string that also happens to be a common English-like word combination could produce false positives; none observed for these 16 specific class names, but generic ones like `ClassifierTest`/`FloorTest` were checked by hand for unrelated hits (none found beyond the generated docs and prose already listed).
6. **Namespace prefix only, no class named** (`grep -rnE` on each of the 9 relevant namespace prefixes owned by the 16 files): every hit was either (a) a sibling file's own `namespace`/`use` declaration sharing the same parent namespace — not a pin on the *moving* files specifically, since the namespace is shared by dozens of non-moving files too — or (b) one of the already-catalogued FQN hits. No new pinned reference was found this way. Blind spot: this form cannot distinguish "pins one of our 16 files" from "pins any sibling under the same namespace", so every hit had to be checked against the full file list by hand; a script that inferred "namespace X is pinned" from this grep alone would over-count by roughly 20x (most hits are unrelated sibling test files' own declarations).
7. **Path:line prose citations inside a TSV/log column** (found opportunistically while reading `directive-audit/enumeration-unguarded-cases.tsv`): a path cited as human-readable evidence text inside a data file that is itself never machine-parsed. This form is invisible to any grep strategy that assumes "TSV = machine input" — it had to be confirmed by checking, separately, whether anything actually opens that TSV (nothing does).

General blind spot across all forms: this sweep is static (grep + manual file reads), not a build of the actual `composer architecture:check`/`directives:controls` machinery under the post-move tree. Every LOUD/SILENT verdict not backed by a live plant (D1-D4) rests on reading the reader's source code rather than on an end-to-end run against the moved tree; four verdicts (Suite.php list, coverage-control fixture dependency, namespace-path-allow-list, and the `@see`-is-silent claim) were independently confirmed by actually breaking the tree and reverting.

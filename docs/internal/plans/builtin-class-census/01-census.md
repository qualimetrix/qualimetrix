# Builtin class registry: census and its control

## Problem

`src/Core/Symbol/PhpBuiltinClassRegistry.php` is a hand-written list that
answers one question for the whole product: "is this name provided by PHP
rather than by the analysed project?" Nothing checked it against a PHP.

Four call sites act on the answer — `ExternalAncestry`,
`InheritanceDepthCollector:157`, `InheritanceDepthResolver:200`, and
`DependencyGraphBuilder:344`. The last one is the consequential one for
coupling: `retainGraphDependencies` keeps an `Extends` edge to a builtin and
**drops every other edge** that reaches one. So a missing name has two effects
that point in opposite directions — a chain that should have stopped keeps
walking (DIT under-reported), and an edge that is not the project's coupling
stays in the graph (CBO, Ce and ClassRank over-reported).

Measured on `ba5fdc66`: `SessionHandler` is absent, so
`symfony/http-foundation`'s `NativeFileSessionHandler extends \SessionHandler`
leaves `ExternalAncestry` as `BrokeAt(depth 0)` instead of `ReachedRoot(1)`.

The defect class is not "one name is missing". It is "no measurement stands
behind the list".

## Enumeration

`builtin-class-census.tsv` (scratchpad artifact, regenerated by `census.php`) —
every name known to a witness or to the registry, one row per name: owning
extension, in-registry, canonical-or-alias, presence per witness, disposition.

| Witness         | PHP    | OS     | Ext | What only it answers                        |
| --------------- | ------ | ------ | --- | ------------------------------------------- |
| `stock-8.4`     | 8.4.25 | Linux  | 34  | the floor; which names are 8.5-only         |
| `rich-8.4`      | 8.4.25 | Linux  | 61  | 8.4 availability of the optional extensions |
| `enchant-8.4`   | 8.4.25 | Linux  | 35  | `enchant`, which nothing else loads         |
| `stock-8.5`     | 8.5.10 | Linux  | 36  | the ceiling; `uri`, `lexbor`                |
| `local-8.5-mac` | 8.5.9  | Darwin | 69  | breadth                                     |

**332 rows: 265 keep, 59 add, 1 remove, 5 version-gated, 1 unverifiable.**
Every registry entry but one was observed on at least one witness, which is
what makes `Pcntl\QueuedSignalInfo` a finding rather than a gap in the method.

**How obtained, and what it cannot see.** `ReflectionExtension::getClassNames()`
per loaded extension, each spelling canonicalised through
`ReflectionClass::getName()`. Blind to:

- **Bundled extensions no witness loads.** `pdo_firebird` (needs a Firebird
  client library) and `com_dotnet` (Windows-only, and it registers classes in C
  rather than in a stub, so it is unenumerable from here). For these, php-src's
  `*.stub.php` is the fallback oracle — it is also what proved
  `Pcntl\QueuedSignalInfo` is in no branch of php-src at all.
- **Source spellings that are not canonical.** PHP class names are
  case-insensitive; `isBuiltin()` is an exact-key lookup. Because the census
  canonicalises both sides, it structurally cannot see that
  `class X extends \exception` is measured as extending a project class. Named
  as residue in ADR 0075, not fixed here.
- **Names whose extension no witness loads** — covered only by the hand
  attribution, which is why an unattributed name is refused rather than skipped.

Two readings that measurement corrected, recorded so they are not re-derived:
`dom\domexception` is an alias-table key, not a gap — its canonical name
`DOMException` was already listed. And `Pcntl\QosClass` is *not* Darwin-gated:
the `#ifdef HAVE_PTHREAD_SET_QOS_CLASS_SELF_NP` covers only the two functions,
and the Linux 8.4 witness has the enum.

## Decision: the list stays hand-written

Recorded in **ADR 0075**, with the rejected alternative (keying the registry by
extension and carrying a minimum version per name) and the reasoning for each
of the three sub-decisions: metadata in the control rather than the product,
per-extension set equality rather than flat membership, and an unknown
extension refused rather than assumed PECL.

## Control

`governance/SymbolVocabulary/PhpBuiltinClassRegistryCensusTest.php` — existing
group, so `phpunit.xml.dist` and `testSuitePrefixTable()` need no edit. The
**generated artifacts do**: `test-ownership.tsv` and
`test-phpunit-discovery.txt` carry a row per governance file, and
`composer architecture:check` refuses them stale.

Six assertions, cheapest failure first:

1. **Floor** — every `REQUIRED_EXTENSIONS` entry loaded, else the run is not
   evidence.
2. **Bijection** — attribution ≡ registry, both directions in one message, so a
   single stale entry cannot abort before fifty-nine missing ones are reported.
3. **Per-extension set equality** — each loaded extension's declarations
   against *that extension's* row. This is what makes the attribution measured;
   against the flat list, a misfiled name passes and is silently exempted from
   assertion 6. Carries the coverage floor.
4. **No undisposed extension** — loaded, declares classes, neither attributed
   nor excused ⇒ red.
5. **Scope** — every attributed extension is in the php-src roster; no
   extension both excused and attributed; every `UNVERIFIABLE_EXTENSIONS` entry
   attributes something and is genuinely not loadable here.
6. **List → env** — every registered name whose extension is loaded and whose
   version cell the running PHP meets must exist.

## Verification performed

| Evidence                          | Result                                                                    |
| --------------------------------- | ------------------------------------------------------------------------- |
| Control on the pre-change tree    | RED, naming all 59 missing names and the fabricated one                   |
| Mutation stand, one per assertion | 6/6 red, each by its target assertion; tree restores green                |
| Second witness, Linux 8.4         | `php:8.4-cli`, 64 extensions — green                                      |
| Second witness, Linux 8.5         | `php:8.5-cli`, 66 extensions — green                                      |
| `composer check`                  | green on the rebased tree                                                 |
| `composer gate --reference=…`     | RED, 55 failures — **none of them this change's**, see below              |
| `benchmark:check`                 | run against the recorded baselines, which are themselves the before-state |

**The gate cannot currently judge, and not because of this change.** All 55
failures are `delta-stale` and `field-move-stale` in the `duplicate-declaration`
and `external-parent` cases — proof declarations in `finding-gate/maps/` left
behind by the DIT campaign, which fail until retired. Zero failures name any of
the 59 newly recognised classes, and no failure is of the "undeclared change"
kind, so the gate reports no delta attributable here.

That was not read off the failure text alone. Reverting **only** the product
file, leaving the candidate behaviourally identical to the reference, produces
the identical 55 failures in the identical two kinds — so the redness is a
property of `finding-gate/maps/` on the base commit, not of this change.
Retiring those declarations is someone's task; precedent is `ad878c13` and
`da996903`. Until it happens, the corpus fixture in Residue below would prove
nothing either.

The coverage floor is 240 names, measured as what a stock `php:8.4-cli`
compares; the macOS box compares 326 of 330. The gap is why the workflow now
pins the extensions the control needs, exactly as it already pinned `igbinary`.

## Residue

- Case-insensitive spellings, above — ADR 0075 names it.
- `Pdo\Firebird` is verified on CI, which loads `pdo_firebird`, and nowhere
  else. The "unverifiable" disposition written for it is gone: the control
  refused the excuse as stale the first time it ran somewhere that loads it.
- A corpus fixture extending `\SessionHandler` would let the finding gate
  witness this fix rather than be silent about it. It belongs in its own commit
  *before* the census commit — added after, it moves the gate's input in the
  same step that measures it.

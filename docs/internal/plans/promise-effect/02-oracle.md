# Этап 02. Оракул расхождения эффекта с обещанием

Судит по реестру этапа 01. Оси раунда — **A, B (только `same-source`), D**.

## 1. Почему не годится существующий стенд

`composer input-doors` мерит референциальный промах: значение указало в
пустоту, сказал ли продукт. Здесь значение указывает во что-то, молчание
законно, дефект — в эффекте; весь `rules:` там одна дверь из восемнадцати.
Берётся оттуда: дисциплина колонки `observable`, нормализация из
`finding-gate/normalization.tsv`, правило «не знаю ⇒ худший вердикт»,
хранение сырых наблюдений, каталог фикстур.

## 2. Тройка проб и семь вердиктов

```
omitted     — ключ не написан
value       — ключ написан проверяемой формой
equivalent  — запись, которую РЕЕСТР объявляет равносильной
```

| вердикт          | условие                                                                        |
| ---------------- | ------------------------------------------------------------------------------ |
| `OK`             | совпало с обещанным **и** есть свидетель достижимости                          |
| `INERT`          | `value == omitted`, а реестр обещал эффект                                     |
| `COLLAPSED`      | `value == equivalent(другая величина)`                                         |
| `REFUSES`        | exit 3 **и** рамка `Configuration error:`                                      |
| `MALFORMED`      | отказ без рамки, `exit 1`, падение — измерено: 5 падений, 4 безрамочных отказа |
| `NOT OBSERVABLE` | `omitted == equivalent`: стенд не чувствителен                                 |
| `UNPROMISED`     | строки реестра нет; после закрытия 01 работает сторожем роста сетки            |

### Проба для пары ключей — своя, и вердикт у неё восьмой

Тройка `omitted / value / equivalent` — проба о **форме значения**. Обещание
о **соседстве** ею не выражается: «обещан отказ, продукт скомпоновал» не
`INERT` и не `COLLAPSED`. Поэтому у строк `kind=pair` своя проба и свой
вердикт:

```
onlyA  — написан только ключ A
onlyB  — написан только ключ B
both   — написаны оба, в одном документе
```

| вердикт          | условие                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------- |
| `COEXISTENCE-OK` | `both` совпал с `coexistence` реестра (`compose` / `refuse` / `one-wins:<ключ>`)         |
| `MISCOMPOSED`    | `both` дал иное: скомпоновал там, где обещан отказ, либо молча выбрал не того победителя |

`MISCOMPOSED` — восьмой вердикт, заведённый явно, чтобы исполнитель не
натягивал на ось B чужой. Контроль подсадкой полагается и ему.

**Ось B в этом раунде ТОЛЬКО измеряется.** Лечения соседства нет ни в одном
пакете, и это не упущение: у 90 строк вида 1 свидетель обещания —
`RuleThresholdKeyGroupRegistry::groupsFor()`, замороженный целиком, а мандата
на семантику пар нет ни у одного владельца. Следствия записаны, а не
подразумеваются: ось B несёт строку выноса в таблице этапа 01, `MISCOMPOSED`
на ней **не блокирует приёмку**, и число таких строк — вход захода по оси C,
который и получит мандат. Красное по осям A и D блокирует по-прежнему.

**Свидетель достижимости — по имени продюсера** (54 имени), а не по классу
опций: `TypeCoverageOptions` обслуживает три правила,
`ComputedMetricRuleOptions` — восемь, шесть продюсеров `health.*` класса не
имеют вовсе, а измеренная дыра именно рулевая.

## 3. Четыре точки наблюдения

`warning: true → 1` случается внутри `fromArray()`; до фабрики значение ещё
`true`. Стенд различает четыре: **выход двери**, **слитый документ**, **объект
опций**, **отчёт**. Основная масса — in-process; процессные прогоны — свидетельский
набор: по одному на имя продюсера для `OK` и по одному на ось для импликации
«схлопывание объекта ⇒ схлопывание отчёта».

## 4. Протокол измерения: кеш не в доверенной цепочке

Оба ранних измерения раунда шли с `--no-cache`, а этот флаг **не держит** —
измерено в самом раунде и вынесено в `DEFERRED`. Оракул, доверяющий
неисправному выключателю, недостоверен независимо от того, отчитались ли мы о
дефекте. Поэтому каждая проба:

1. каталог кеша задаётся **явно** и уникален для пробы — так прогон не может
   молча уйти в каталог по умолчанию;
2. каталог физически удаляется перед прогоном;
3. после прогона проверяется, что заданный каталог либо отсутствует, либо
   создан этим прогоном **и** что прогон один: файл, записанный этой же
   пробой, не может быть ею прочитан;
4. если продукт проигнорировал заданный каталог (появился каталог по
   умолчанию) — проба **падает**, а не отчитывается.

Постусловие «каталог создан этим прогоном» само по себе слабее заявления «кеш
не читался» — отсюда пункты 1 и 4, закрывающие обход через другой каталог.
exit снимается без пайпа. Прогон, не подтвердивший постусловие, — не
наблюдение.

**Пол дефектов переснимается.** 21 строка `non-rules-roots.tsv` измерялась со
сломанным `--no-cache`, поэтому старый артефакт для пола — **вход, а не
свидетельство**: стенд обязан снять эти строки заново по протоколу выше, и
расхождение со старым числом является фактом для отчёта, а не поводом
подогнать.

## 5. Знаменатели

**Ось A — форма значения. Не произведение, а сумма по дверям**: двери
неравномощны, и произведение `пути × двери` ложно (замороженный
`writer-applicability.tsv` это и доказывает).

| дверь       | сколько путей достижимо                   |
| ----------- | ----------------------------------------- |
| `yaml`      | все 205 объявленных путей                 |
| `rule-opt`  | все 205 (произвольный путь любой глубины) |
| `cli-alias` | 80 объявленных путей                      |
| `cli-root`  | путей в ось A не даёт: они учтены осью D  |
| `inline`    | **вынесена**: дверь целиком в `DEFERRED`  |

Две двери инвентаря в схему реестра не входят и это названо: `preset` —
та же грамматика, что `yaml`, и уходит с осью C как отдельный слой;
`composer` пишет только `paths` и является чужим документом (исключение
инвентаря). Ещё две CLI-двери — `--suppress-path` и `--suppress-namespace` — идут мимо
адаптера ввода прямо в Reporting. Они остаются значением `cli-root`, но несут
пометку «мимо конвейера»: их форма решается не там, где у соседей, и проба без
этой пометки измеряла бы не ту точку.

Форм **восемь, и они перечисляются поимённо, а не числом**: `null`, `bool`,
`int`, `float-дробный`, `строка-число`, `строка-не-число`, `список`, `карта`.

Три framework-ключа проверяются **одним местом применения**
(`FindingExclusionLedger::keeps()`): он решает по имени продюсера и
местоположению находки, объект опций не читает. Арифметика артефакта в двух разных единицах, и смешивать их нельзя:
**480 = 3 × 160** — это «framework-ключ × объявленный верхнеуровневый путь
опции»; **162 = 3 × 54** — «framework-ключ × продюсер». Знаменатель раунда —
второй. Gate-зависим только `enabled`. Место применения доказывает применение
эффекта, но не весь путь формы: извлечение и отбрасывание неверных элементов
происходит раньше, в фабрике, и эта часть покрыта осью A. В границу притязаний эти пары
входят **явным членом про место применения**, а не через формулу
«`acceptedOptionKeys()`»: ни один класс опций их не объявляет.

**Ось B — соседство ключей. Выносится КООРДИНАТА, а не пара.** У одной пары
бывают два разных обещания сразу: `key-pairs.tsv` для объявленных
threshold-групп прямо пишет «взаимно исключающи внутри одного источника, а
между источниками верхний слой вытесняет нижний». Прошлая редакция
классифицировала всю пару по одной координате и тем выбрасывала настоящую
`same-source` гарантию 108 пар — это находка четвёртого раунда ревью.

Поэтому: **в раунде — координата `same-source` всех 465 строк**; координата
`cross-source` существует у 108 строк (90 + 18) и вынесена вместе с осью C.
Это **не** те 108, что стоят в разбивке видов («межгрупповые»): совпадение
чисел случайно, и в артефакте они разные множества. Отображение «вид строки →
`source_scope`» фиксируется колонкой в `key-pairs.tsv` перед стартом стенда,
иначе популяция стража меняется вместе с интерпретацией. Строка реестра
ключуется парой **и** координатой, поэтому у такой пары строк две, и это
разрешено явно.

**Ось D — пути вне `rules:`:** 54 позиции, `UNENUMERATED` — 8, все в простых
корнях. Свободные деревья не свободны: отказывают неизвестному ключу до
глубины 4, состав выводим из кода. Координата политики нормализации: 14
camel / 1 immediate / 1 subtree.

## 6. Пятое множество: независимый знаменатель против кругового

Четыре множества сверки реестра с объявлением (этап 01) не ловят ключ,
который код **читает**, но `acceptedOptionKeys()` не объявляет: такой ключ
отсутствует и в декларации, и в знаменателе оси A. Поэтому стенд печатает
пятое:

```
consumer \ declaration — ключевые литералы, читаемые телами fromArray(),
                         которых нет в объявлении
```

Источник — `form-deciding-sites.tsv`. **Пятое множество становится
свидетельством только после того, как разобраны 117 мест без ключа**: сегодня
оно считалось бы по 338 местам из 455 и молчало бы об остальных по
построению. Разбор — первое действие P1 (см. 03), и до него множество
печатается с пометкой «не свидетельство».

## 7. Популяционный страж

Считается из кода: реализации `RuleOptionsInterface`; имена продюсеров (54);
позиции `config-paths.tsv`; `same-source` пары `key-pairs.tsv`. Краснеет на
члене популяции, не покрытом сеткой, — проверяется подсадкой.

Страж намеренно **не** опирается на `RuleThresholdKeyGroupRegistry` и
`RuleOptionsRegistry`: их вправе удалить заход по оси C. Следствие, названное
честно: пропущенную или неверную запись реестра групп этот страж не находит —
это работа захода по оси C, и она записана его входом.

## 11. Definition of Done

1. Вердикты по осям A, B (`same-source`, только измерение), D; exit 0/1 —
   код возврата определяют оси A и D. Сверка реестра с
   объявлением в DoD этого этапа **не входит** — объявление появляется в 03.
2. Снимок «до» заморожен, проверен `git ls-files`, а не `git status`.
3. Пол дефектов воспроизведён: 64, 66, 21 строка `non-rules-roots.tsv`.
4. Протокол изоляции кеша исполняется и проверяется утверждением после
   каждого прогона.
5. Страж красный при подсадке нового имени продюсера, новой позиции
   `config-paths.tsv`, новой `same-source` пары.
6. Контроли: по подсадке на каждый из семи вердиктов.
7. Два прогона подряд дают тот же текст.
8. Доля `NOT OBSERVABLE` снята числом — базис ратчета приёмки.

# Test audit: Infrastructure/Core slice

Slice: `tests/Unit/Infrastructure/`, `tests/Unit/Core/`, `tests/Core/`,
`tests/Infrastructure/{Unit,Cache,Logging,Parallel,Profiler}/`, `tests/Integration/Infrastructure/`,
`tests/Integration/DependencyInjection/`. 93 files.

Methodology: 52 files (Core/Path, Core/Symbol, Unit/Core, Cache×3 locations, Logging,
Parallel×2 locations, Profiler) were read and analyzed directly, line by line, together with the
corresponding `src/` classes. Another 41 files (17 — DI/CompilerPass/Rule, 24 —
Ast/Console/Git/Serializer) were read and analyzed by two parallel read-only sub-agents using the
same method (a full reading of the test + the SUT in `src/`); their reports were merged in here
without changing the conclusions. No test, composer script, or `bin/qmx` was ever run — the
entire analysis is by reading code.

## How this was checked and what this method cannot see

The check was entirely read-only: every test file was read in full together with the
corresponding SUT class in `src/` (via `use` imports and, where needed, a direct reading of the
implementation — e.g. `KnownRuleNamesAdapter`, `WorseDirection`, `FileDeclarationIndex`). The
presence of `#[Test]`/the `itXxx` form was checked by actually reading the code (a grep for
`function test` returned no matches — no explicit §9 violations by method name were found in the
slice; the absence of `#[CoversClass]` in a few Logging files is noted separately as a minor
finding, not a §9 violation). The test directory's match to the owning subject in `src/` was
checked via `find`/`ls` over both trees.

Neither `composer check`, nor `phpunit`, nor `bin/qmx` was ever run — per the brief's direct
prohibition. This means:
- "Tautology" and "duplicate" are determined **by reading** (the assertion doesn't depend on
  broken SUT behavior, by the test's own construction), not by an actual mutation run — per the
  project's memory ("the mutation rig gives a false green"), only a real mutation run
  conclusively proves a test doesn't catch a regression; here this is a high-confidence
  hypothesis, not a fact.
- Not checked: whether the tests are currently green, or whether the documentation inside the
  hand-written lists (`ContainerFactoryTest::itRegistersAllRules` and 46 other classes) has
  drifted from the current state of `src/` — this could diverge independently of the test's own
  quality.
- Line coverage was not checked: a test with a "good" name and a sensible assertion can still
  never reach some of the SUT's branches (e.g. `HookStatusCommandTest` is directly admitted as a
  smoke test, `execute()`'s behavior isn't covered at all — this is a finding about a **gap**,
  not a defect in the existing tests).
- The "integration in fact, unit by directory" category (`GitClientTest`,
  `GitRepositoryLocatorTest`, `ReportingGitScopeQueryTest`, `CachedFileParserTest` partially) is
  determined by the fact of real access to a git process/filesystem inside the test, not by any
  official framework definition — the unit/integration boundary in this report follows the
  brief's wording ("I/O or several classes"), which is broader than just "a slow test".
- Test order dependency (flakiness from `--order-by=reverse`, a global-state leak via
  reflective swaps of statics in `FileSetInspectionParticipantCompilerPassTest`,
  `WorkerBootstrap::reset()`) was not checked by a run — flagged as a footgun from reading the
  code, not empirically confirmed.

## Assumptions

- The `control` category was applied per the brief's wording: the test checks
  repository/layout state, not a specific product class's behavior — including cases where the
  control part is just one method inside an otherwise normal unit file (such files are marked in
  the table with the mixed category "unit + control", naming the method in the defects).
- "Correct directory" is proposed only where the discrepancy is not about a technical label
  (Unit/Integration), but about subject ownership (e.g. `NamespaceTreeTest` physically checks a
  class from `Analysis\Evidence\Measurement`, not `Core`), or where the test's actual behavior
  (a real git/filesystem call) directly contradicts the declared `Unit/` folder.
- Duplicates inside `ContainerFactoryTest.php` and
  `RuleCompilerPassTest.php`/`RuleOptionsCompilerPassTest.php` are taken from a parallel
  sub-agent's report, which read both files in full with line numbers; merged in here without a
  line-by-line re-check on my own side — trust is limited by the same class of assumptions as my
  own part (reading without a run).
- Table count: 93 files in the slice = 93 substantive rows (a few placeholder rows in the
  table are explicitly marked "see above/see block" where one file is naturally described in one
  row next to a direct SUT neighbor, to avoid fragmenting related analysis — in fact every path
  appears in the table exactly once).

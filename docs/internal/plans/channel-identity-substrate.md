# План: идентичность канала — точное равенство и явная группировка

**Статус:** предложение, готово к ревью перед исполнением
**Дата:** 2026-08-18
**Область:** `src/Analysis/Finding/Contract/Rule/`, `src/Analysis/Finding/Contract/Filter/`,
`src/Analysis/Policy/Inline/Contract/Suppression/`, `src/Analysis/Finding/Contract/Threshold/`,
реестры каналов, `ChannelDeclaration`, пять точек ветвления `src/Analysis/Policy/Baseline/`
**Отношение к предыдущему:** единственный канонический документ. Заменяет редакции 1-4 и отдельный файл находок;
всё, что нужно для исполнения и ревью, здесь.

## 1. Что сломано

Находка идентифицируется парой `(ruleName, violationCode)` — обе половины строки с точками. Четыре подсистемы
независимо отвечают на вопрос «выбирает ли эта пользовательская строка эту находку», и все зовут один матчер с
семантикой `exact ∨ startsWith(pattern . '.')`, но читают **разные половины пары**:

| Подсистема                                                 | Что матчит                 | Файл                                                          |
| ---------------------------------------------------------- | -------------------------- | ------------------------------------------------------------- |
| подавление `@qmx-ignore`                                   | только `violationCode`     | `Policy/Inline/Contract/Suppression/Suppression.php:48`       |
| override порога `@qmx-threshold`                           | только `ruleName`          | `Finding/Contract/Threshold/ThresholdOverride.php:51`         |
| выбор правил (`only_rules`, `--disable-rule`)              | обе половины, дизъюнкцией  | `Finding/Contract/Rule/RuleSelector.php:193-195`              |
| исключения по путям/неймспейсам                            | `ruleName` через категорию | `Finding/Contract/Filter/{Namespace,Path}ExclusionFilter.php` |
| пер-rule исключения каналов (`exclude_namespace_channels`) | `violationCode`            | `Finding/Exclusion/RuleNamespaceExclusionProvider.php:185`    |

**Д1. Канал, названный точечным потомком существующего, молча попадает под все селекторы предка.** Проверено
исполняемо: `RuleMatcher::matches('architecture.coverage', 'architecture.coverage.source') === true`. Пользователь,
заглушивший шумный канал покрытия, включает новый гейт и получает зелёную сборку без гейта. Это заблокировало
клиентский запрос `architecture-unassigned-class`.

**Д2. Две директивы принимают разные словари, и диагностика уводит не туда.** Отчёт печатает
`coupling.cbo.class`; вставленное в `@qmx-threshold`, оно не совпадает ни с одним правилом (правило называется
`coupling.cbo`). Директива не срабатывает — но не молча: `AnalysisPipeline.php:342-354` эмитит
`annotation.unsupported-threshold` с `Severity::Warning` и сообщением «Rule 'coupling.cbo.class' does not support
@qmx-threshold overrides; annotation ignored». Сообщение **приписывает причину не тому**: пользователь читает,
что правило не поддерживает override, тогда как на деле строка не называет правило вовсе, а `coupling.cbo`
override поддерживает. При дефолтном `fail_on: error` этот Warning вдобавок не гейтит. Это клиентский запрос
`threshold-override-exact-matching`.

**Д3. Поддерживает ли правило override — снаружи не видно.** Признак: реализует ли класс опций
`ThresholdAwareOptionsInterface` и вызывает ли правило `getEffectiveOptions()`. Обратного отображения
«код → адресуемая единица» нет, поэтому подсказку «вы имели в виду» построить не из чего.

**Д4. «Можно ли принять находку в baseline» закодировано наличием объекта декларации.** Следствия: диагностики о
директивах (`annotation.*`) эмитятся напрямую из `AnalysisPipeline`, владельца-правила у них нет, объявить форму и
настраиваемую severity негде; и наоборот — четыре архитектурные диагностики (`architecture.coverage`,
`.unreachable-layer`, `.potential-shadow`, `.empty-template`) декларации имеют и потому **могут быть приняты в
baseline как обычный долг кода**, хотя ADR 0017 строка 25 требует обратного. В текущем `qmx-baseline.json` таких
записей нет — дефект латентный.

## 2. Ограничения, установленные по коду

Любое решение обязано им удовлетворять. Все проверены чтением кода или исполняемой командой.

**О1. Точечная иерархия — протестированный инвариант, а не соглашение.**
`ChannelDeclarationFixtureDriftTest::everyDeclaredViolationCodeEqualsOrIsPrefixedByItsRuleName` требует, чтобы код
канала был равен имени правила либо начинался с `имя_правила.`.

**О2. Имя не разрешается в единственный уровень.** 38 из 51 объявленного канала имеют `violationCode === ruleName`.
Схема «имя → ровно одна сущность» потребовала бы необъявленного приоритета уровней.

**О3. Потребители различаются половиной пары.** Практическое следствие: `@qmx-ignore architecture.layer-violation`
гасит сегодня **один** канал и не трогает четыре диагностики того же правила.

**О4. У открытых семей произвольная глубина.** Имя вычисляемой метрики — `prefix.identifier(.identifier)*`, то
есть `computed.team.quality.score` легально; один производитель эмитит под двумя префиксами (`computed.`, `health.`).

**О5. Строка идентичности — внешний контракт в пяти местах:** `ruleId` в SARIF, `check_name` в GitLab, `source` в
Checkstyle, поля `code` и `channel` в JSON.

**О6. Собственный корпус не может служить оракулом совместимости.** Свойство, на которое опирается план:
**все живые аннотации в `src/` адресуют существующие точные имена** — каналов у `@qmx-ignore`, правил у
`@qmx-threshold`; категорийных, префиксных и wildcard-селекторов в репозитории нет ни в аннотациях, ни в
`qmx.yaml`, ни в пресетах. Поэтому тест на собственном коде будет зелёным при сломанной групповой семантике, и
оракул обязан быть синтетическим.

Голые счётчики здесь сознательно не приводятся: за сессию они трижды оказались неверны, потому что подстрока
`@qmx-*` встречается в трёх видах — живая аннотация в докблоке, экранированный бэктиками пример, обычный
`//`-комментарий или строковый литерал (последние два экстрактором не читаются: он берёт `getDocComment()`).
Свойство устанавливается командой, а не памятью:

```bash
grep -rhoE '^\s*\*\s*@qmx-(ignore|threshold)\S* +[a-z][a-z0-9.*-]*' src --include='*.php' | awk '{print $NF}' | sort -u
```

**О7. Эмиссия имеет три формы, статический охранник видит две.** Прямо в правиле; объявление в абстрактном предке
через позднее статическое связывание (12 правил: 9 наследников `AbstractCodeSmellRule`, 3 —
`AbstractSecurityPatternRule`); конструирование в отдельном коллабораторе (`CodeSmellFinding`,
`SecurityPatternFinding`, `ComputedMetricFindingBuilder`) — эти классы вне цепочки наследования, и
`ChannelEmissionStaticGuardTest` их не обходит.

**О8. Потребители идентичности есть и вне общего матчера:** `RemediationTimeRegistry.php:123-124` сравнивает
`ruleName` со списком литералов; `RuleNameValidator.php:59-61` содержит собственную копию трёхсторонней логики;
`BaselineConfiguredThresholds::axisOf` отрезает префикс.

**О9. Идентичность записи ратчета позиционная.** Ключ вида `declaration:class:FQCN@path:5158`, где число —
`startFilePos`, байтовое смещение начала объявления (`Core/Symbol/MetricSubjectCodec`). Любая правка выше
объявления переписывает ключ. Вне скоупа этого плана, см. §9.

## 3. Решение

### 3.1 Матчинг = равенство; группировка = явный wildcard

`RuleMatcher::matches()` теряет префиксную семантику и вырождается в `===`. Единственная групповая форма —
**явная звезда замыкающим сегментом**: `code-smell.*`.

Семантика фиксируется здесь и не подлежит толкованию:

- `X` — точное совпадение, ничего больше;
- `X.*` — **строго потомки** `X`; сам `X` не входит. Нужен и он — пишется отдельной директивой. Без этого
  `architecture.coverage.*` снова размывал бы границу родителя и потомка, ради которой всё затевается;
- голый префикс без звезды (`coupling` в смысле «все coupling-правила») — **ошибка**, а не догадка о намерении;
- **одиночная `*` перестаёт быть селектором, но не перестаёт существовать.** Сегодня токен несёт **три**
  разных смысла, и все три обслуживаются одним спецкейсом `Suppression.php:44`, общим для символьной, next-line и
  файловой форм:
  - `@qmx-threshold * 15` — «переставить пороги всем правилам». Футган, удаляется;
  - `@qmx-ignore * [причина]` на символе или строке — «все правила на этом символе». Задокументировано в обеих
    локалях (`website/docs/usage/baseline.md:113`) и покрыто тестом;
  - `@qmx-ignore-file` без аргумента — «весь файл»; `SuppressionExtractor.php:139-140` десахарит пустой
    аргумент в `'*'`.

  Второй и третий смысл — не селекторы по пространству имён правил, а **отсутствие фильтра по правилу**. Оно
  моделируется явно, для всех трёх форм подавления сразу, и потому переживает удаление `*` как токена селектора:
  `@qmx-ignore *` и голый `@qmx-ignore-file` продолжают работать, меняется только внутреннее представление.
  Удаляется ровно первый смысл — групповая переустановка порогов. Без этого разделения каждый файл с голым
  `@qmx-ignore-file` и каждый символ с `@qmx-ignore *` не только потеряли бы подавление, но и завалили бы сборку
  по §3.3;
- синтаксис один и тот же в аннотациях и в конфигурации;
- селектор, не совпавший ни с чем, — ошибка (см. §3.3);
- **`X.*` у правила, чей код равен имени, не покрывает ничего** — таких каналов 38 из 51, и `code-smell.eval.*`
  даст ошибку с подсказкой «используйте `code-smell.eval`». Это принятое поведение: разрешать звезду там, где
  потомков нет, значило бы вернуть догадку о намерении;
- **«все каналы правила слоёв» невыразимо**, и это принятая цена. `architecture.layer-violation` даёт один канал,
  `architecture.layer-violation.*` — ошибку (потомков нет), `architecture.*` захватил бы чужое правило
  `architecture.circular-dependency`. Причина — четыре канала правила несут собственные `ruleName` (§3.6);
- **wildcard допустим только в односоставной форме.** Форма `ruleName#violationCode` требует обе половины
  точными: она существует ради явного разведения половин, и звезда внутри неё умножала бы поверхность без
  показанной надобности. Нужна группа — пишется односоставная форма.

`anyReverseMatches` и его противоречивый докблок удаляются. Его единственный вызов — `RuleSelector::
matchesKnownProducer()`, то есть валидация **владельцев опций**: ключей секции `rules:` и аргументов
`--rule-opt RULE:...`. Селекция `only_rules` пользуется не им, а инлайн-реверсом в `RuleSelector.php:155` —
прошлые редакции приписывали обратный режим не тем потребителям. Обе поверхности переходят на равенство, и обе
входят в набор файлов P1.

### 3.2 Уровень задаёт директива, а не число сегментов

| Директива / потребитель                                          | Что адресует            | Форма                                                                                                                                                                                  |
| ---------------------------------------------------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@qmx-ignore X`, `@qmx-ignore-next-line X`, `@qmx-ignore-file X` | канал (`violationCode`) | точное имя канала либо `X.*`; полная квалификация обязательна. Форма «без фильтра по правилу» сохраняется: `*` у символьной и next-line форм, отсутствующий аргумент у файловой (§3.1) |
| `@qmx-threshold X`                                               | правило (`ruleName`)    | точное имя правила; wildcard не принимается — порог не бывает групповым                                                                                                                |
| селекция (`only_rules`, `disabled_rules`, `--disable-rule`)      | правило и/или канал     | точное имя либо `X.*`; форма `ruleName#violationCode` адресует обе половины явно                                                                                                       |

Это снимает неоднозначность О2 **без переименования каналов и без приоритета уровней**:
`@qmx-ignore code-smell.boolean-argument` — всегда канал, `@qmx-threshold code-smell.boolean-argument` — всегда
правило. Асимметрия не случайна: порог физически принадлежит правилу (один объект опций), подавление — каналу.

Wildcard у `@qmx-threshold` запрещён сознательно: групповая переустановка порога — это и есть исходный футган.

### 3.3 Громкий отказ: три состояния, три ответа

| Состояние                                                       | Пример                                                                                                                                                                                                                                            | Ответ                                                                                                                       |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| имя не адресует единицу, которую эта директива умеет адресовать | `@qmx-ignore coupling.instabilty` (опечатка); `@qmx-ignore coupling.instability` (имя правила у многоканального правила); `X.*`, не покрывший ни одного канала; `@qmx-threshold design.lcom` на правиле, чей класс опций не поддерживает override | **Error**: конфигурационная ошибка — не базлайнится, не подавляется, гейтит. Сообщение перечисляет то, что адресовать можно |
| имя валидно, но директива не сработала за прогон                | подавление осталось после починки нарушения                                                                                                                                                                                                       | отдельный канал, дефолт ниже Error, гейтится по желанию. Это не ошибка конфигурации: так выглядит нормальная уборка долга   |
| имя валидно и сработало                                         | —                                                                                                                                                                                                                                                 | тишина                                                                                                                      |

**Инвариант реестра «неизвестный канал — не ошибка» этому не противоречит: он про другой предмет.**
Докблок `ChannelDeclarationRegistry.php:73-78` говорит о **хранимом артефакте** — записи baseline, чей канал
исчез: она становится инертной, потому что взрывать старый baseline недопустимо. §3.3 говорит об **авторской
директиве**: имя, которое ни во что не разрешается, означает, что директива врёт о том, что делает. Опечатка это
или метрика, убранная из `computed_metrics:`, роли не играет — и то и другое висячая ссылка, которую автор должен
починить. Разные жизненные циклы, разные правильные ответы, отдельного состояния не требуется.

Первое состояние сформулировано **через адресуемость, а не через существование имени**, и это важно: случай
«правило существует, но override не поддерживает» (сегодня — `annotation.unsupported-threshold`) им покрывается,
хотя имя разрешается. Директива, которая никогда не сработает, — такая же ложь, как опечатка. Второе состояние не
смешивать с первым: иначе каждый проект, починивший нарушение и не убравший аннотацию, начнёт падать.

**Механизм отказа разный по поверхностям, и это фиксируется.** Селекторы конфигурации и CLI валидируются до
анализа, поэтому их отказ — исключение с завершением команды (сегодня так работает `RuleInputValidator`), и
понятия «базлайнится/подавляется» к нему неприменимы. Инлайн-директивы обнаруживаются в ходе анализа, поэтому их
отказ — находка на общем канале, и к ней применимы принимаемость и подавление. Общее у обеих поверхностей одно:
молчания не остаётся.

**Скоуп учёта «не сработала» ограничен.** Считаются только директивы, адресующие включённые правила и попавшие в
проанализированное множество файлов. Иначе отключение семьи правил (как в поставляемом `legacy.yaml`) давало бы
находку на каждую относящуюся к ней аннотацию, а `--report=git:staged` — на каждую аннотацию вне диффа.

**Владение новыми каналами объявляется здесь, а не подразумевается.** Оба состояния порождают находки, значит у
них есть каналы, у каналов — владелец, форма и принимаемость. Владелец — правило слоя инлайн-директив (та же
форма, что у правила слоёв: правило внутри policy-возможности, эмитящее несколько каналов). Принимаемость:
`ConfigurationError` для первого состояния, `AcceptableAsDebt` для второго. Судьба двух существующих каналов
`annotation.unsupported-threshold` и `annotation.invalid-threshold` решается там же: они становятся каналами
этого правила и покидают `excluded.txt`, чей механизм заменяется объявлением. Открытое суффиксное семейство
`annotation.invalid-threshold.<code>` устраняется — код ошибки становится данными находки, а не частью
идентичности.

### 3.4 Момент проверки — после резолва конфигурации

**Вселенная одна и собирается после резолва конфигурации.** Статические декларации правил и сконфигурированные
определения вычисляемых метрик — два её вкладчика, а не два пространства имён: происхождение имени нигде не
хранится и ни на что не влияет. Проверено, что это возможно: ничему не требуется вселенная каналов до резолва
конфигурации — имена правил нужны раньше, при разборе `rules:`, и они известны на сборке, а имена каналов нужны
только после. Реестр уже устроен так наполовину: статическую часть он получает от сборочного прохода, а
вычисляемую резолвит на каждом обращении из каталога определений.

Внутри вселенной адресуются два вида сущностей — правила и каналы, — и вид задаёт директива (§3.2), а не
происхождение имени.

**Включённость правила не входит в идентичность.** Вселенная содержит все объявленные каналы этой конфигурации
независимо от того, включено правило или выключено: отключение — фильтр исполнения, а не факт о существовании
имени. Отсюда `@qmx-threshold` на выключенном правиле остаётся валидным (имя существует), и сегодняшняя
диагностика для этого случая исчезает. Это осознанная цена: иначе выключение правила делало бы невалидными
аннотации, которые станут нужны, как только его включат обратно.

Ограничение выведено из собственного кода: живые `@qmx-ignore health.cohesion` адресуют канал вычисляемой
метрики, чьё имя приходит из `computed_metrics` конфигурации и в статическом реестре отсутствует. Валидация,
выполненная до резолва конфигурации, объявила бы их ошибками. Количество — командой из О6, не отсюда.

### 3.5 Группировка: wildcard адресует, категория показывает

Разделение работ, которые сегодня совмещены в `RuleCategory`:

- **адресация групп** — только wildcard (§3.1). Категория перестаёт быть единицей адресации;
- **группировка для показа** — `RuleCategory` остаётся как есть: объявленный атрибут, `RuleInterface::getCategory()`,
  потребитель `qmx rules --group`. Категория **не участвует ни в одном матчинге**;
- **поведенческое исключение** — сегодня `NamespaceExclusionFilter`/`PathExclusionFilter` спрашивают
  `RuleCategory::Architecture->matches($violation->ruleName)`, чтобы не гасить архитектурные находки исключениями
  по путям и неймспейсам. Это не группировка, а свойство: находка не привязана к файлу, поэтому исключение по
  пути к ней неприменимо. Заменяется **объявленным булевым свойством правила**.

Категория не удаляется сознательно: `getCategory()` объявлен в 33 правилах, входит в `RuleInterface` и
`RuleMetadata`, используется в выводе и упоминается в 46 тестовых файлах — удаление стоило бы ~85 файлов, а
поведенческую работу всё равно пришлось бы заменить отдельным свойством. Лишив категорию поведения, мы устраняем
дефект (совмещение двух работ) ценой ~6 файлов. Совпадение значения категории с первым сегментом имени становится
безобидной корреляцией: на ней никто не матчится, поэтому расхождение у `computed.health → Maintainability`
перестаёт быть аномалией.

**Проекция первого сегмента (`familyOf()`) не вводится.** После §3.1 у неё нет потребителей: группировку
выражает wildcard, показ — категория.

### 3.6 Реестр — валидатор и резолвер, не участник матчинга

Два существующих реестра (`ChannelDeclarationRegistryInterface`, `RuleChannelRegistryInterface`) сводятся к одной
инстанции с узкими представлениями по потребителям. Матчинг остаётся сравнением строк и в реестр не ходит; реестр
отвечает на вопросы и хранит объявленные свойства.

```
Rule (производитель):
  name: string                        # полное имя, единственный литерал (NAME)
  category: RuleCategory              # только показ (§3.5)
  supportsThresholdOverride: bool     # §3.7
  fileScoped: bool                    # §3.7, заменяет проверку категории в фильтрах исключений

Channel (владелец — Rule):
  ruleName: string                    # НЕ обязательно равен name владельца: четыре канала правила слоёв
                                      # несут собственные имена, которых нет ни у одного правила
  violationCode: string
  shape: Occurrence | Magnitude(+direction)
  acceptability: AcceptableAsDebt | ConfigurationError   # §3.7
```

**Где живут константы идентичности.** Сложилась конвенция: полное имя производителя объявляется контрактом
возможности, а класс правила на него ссылается — `CircularDependencyPreparationInterface::PRODUCER_RULE_NAME`,
`LayerPolicyPreparationInterface::PRODUCER_RULE_NAME`, `ComputedMetricChannelFamily::PRODUCER_RULE_NAME` (P0
привёл к ней первые две). Новые объявленные свойства §3.7 размещать там же: контракт — разрешённая точка обзора
для кросс-владельческих потребителей, и на него может сослаться коллаборатор, эмитящий находку вне цепочки
наследования правила (О7).

Операции: существует ли имя; какие каналы производит правило; `violationCode → ruleName` (для «did you mean»);
принимаемость канала; разворачивание `X.*` в множество каналов.

### 3.7 Объявленные свойства вместо выводимых

- **`supportsThresholdOverride`** — закрывает Д3. Объявляется правилом, а не выводится из наличия интерфейса у
  класса опций. Даёт «did you mean» обратным запросом к реестру, а не отсечением суффикса: у двух правил из 41 код
  не производен от имени вообще.
- **`fileScoped`** — заменяет проверку категории в двух фильтрах исключений (§3.5).
- **`acceptability`** — закрывает Д4. Четыре канала `architecture.*` (`coverage`, `unreachable-layer`,
  `potential-shadow`, `empty-template`) переклассифицируются в `ConfigurationError`; пятый канал того же правила,
  `architecture.layer-violation`, — настоящий долг кода и не трогается. `ConfigurationError` влечёт эффективную
  severity не ниже `Warning` и не принимается ратчетом ни на одном из пяти путей.

  **`architecture.coverage` — гибрид, и решение записывается, а не подразумевается.** Он означает одновременно
  «в объявлении слоёв дыра» (конфигурационная ошибка) и «появился новый неклассифицированный модуль»
  (архитектурный долг). Классифицируется как `ConfigurationError`, потому что различить эти два случая может
  только автор конфигурации, а не анализатор: и то и другое означает, что объявленные слои не покрывают
  наблюдаемый код, и разрешается это правкой `layers:`. Принять такую находку в ратчет значило бы зафиксировать
  расхождение конфигурации с кодом как норму. Цена решения — счёт переклассифицируемых каналов равен четырём, и
  DoD P3 на это число опирается; при обратном решении он равен трём.

  **Цена названа явно, и оси у четырёх каналов разные.** Три из них настраиваются severity-ключами
  (`unreachable_layer_severity` и `potential_shadow_severity` дефолтят в `Info`, `empty_template_severity` — уже в
  `Warning`); у четвёртого, `coverage`, severity-ключа нет вовсе — он управляется режимом `ignore|warn|error`.
  После перевода в `ConfigurationError` значение `info` становится **ошибкой конфигурации** для всех трёх ключей,
  а не тихо повышается: тихое повышение означало бы ключ, врущий о том, что он делает. Для `coverage` менять
  нечего — режим `warn`/`error` и так не опускается ниже границы, а `ignore` гасит эмиссию целиком и остаётся
  законным способом не включать диагностику. Это разрешение противоречия между двумя объявлениями —
  «конфигурационная ошибка обязана быть громкой» против «Info никогда не гейтит», — потому что после перевода у
  этих каналов не остаётся ни `fail_on`-гейта, ни ратчета.

Сужение формулировки: «не принимается **ратчетом**». Конфигурационная ошибка может быть принята явным объявлением
намерения в конфигурации. Сегодня такой способ ровно один — `coverage: ignore`; `pending: true` на слое пока не
существует, это предложение соседнего плана `architecture-layer-pending`, и ссылаться на него как на имеющуюся
возможность нельзя.

### 3.8 Вычисляемые метрики — отдельный род декларации, но не отдельное пространство имён

`computed.*` / `health.*`: один производитель, два префикса, имя произвольной глубины из конфигурации прогона.
Отличие от прочих каналов ровно одно и оно про **декларацию**: форма и направление резолвятся из определения
метрики в рантайме, а не объявляются статически, и override аннотацией не поддерживается.

В адресации они ничем не отличаются. Вселенная одна (§3.4), поэтому равенство, `X.*` и все правила §3.3
работают по ним так же, как по статически объявленным каналам: `@qmx-ignore health.cohesion` — точное имя канала,
`@qmx-ignore health.*` — его потомки, несуществующее имя — ошибка. Отдельного словаря и отдельного поведения при
отказе нет.

## 5. Breaking-поверхность и миграция

Девять изменений публичной семантики. Каждое — запись `Breaking` в `CHANGELOG.md` и раздел миграции от лица
потребителя.

1. **Селектор перестаёт глотать точечных потомков.** `architecture.coverage` больше не покрывает
   `architecture.coverage.source`. Это и есть фикс Д1.
2. **`@qmx-threshold` перестаёт принимать префикс и `*`.** `coupling 15` и `* 15` — ошибки.
3. **`@qmx-ignore` требует полной квалификации.** Имя правила у многоканального правила (`coupling.cbo`,
   `coupling.instability`, `complexity.cyclomatic`, `complexity.cognitive`, `complexity.npath`,
   `design.type-coverage`) перестаёт быть валидным; нужен точный канал либо `X.*`.
4. **Групповые селекторы требуют звезды.** Поверхностей четыре: `disabled_rules` / `only_rules` (обе формы
   написания — snake_case и camelCase: поставляемый пресет `legacy.yaml` использует `disabledRules`), CLI
   `--disable-rule` / `--only-rule`, пер-rule `exclude_namespace_channels` (её докблок сегодня прямо предлагает
   префиксную форму вроде `health`), и три формы инлайн-подавления. Пример: `disabled_rules: [complexity]` →
   `[complexity.*]`.
5. **Ключ секции `rules:` — точное имя правила, без префиксов и звёзд.** Групповая форма там невозможна не по
   решению, а по устройству: опции применяются точным ключом (`RuleOptionsFactory.php:69`), а групповая
   переустановка порогов — тот самый футган, который запрещён у `@qmx-threshold`. Сегодня `rules: { complexity:
   {...} }` проходит обе валидации и **ничего не настраивает** — латентный дефект, который здесь и устраняется:
   такой ключ становится ошибкой. Та же поверхность у `--rule-opt RULE:option=value`.
6. **Неразрешимый селектор становится ошибкой**, а не игнорируемым Warning.
7. **`@qmx-threshold` для отключённого правила перестаёт диагностироваться.** Включённость не входит в
   идентичность (§3.4), поэтому имя разрешается и директива становится валидной и тихой. Принято как цена:
   обратное означало бы, что выключение правила делает невалидными аннотации, нужные при обратном включении.
8. **Удаление вычисляемой метрики из `computed_metrics:` делает ошибочными аннотации, которые на неё ссылаются.**
   Висячая ссылка на несуществующий канал — та же ошибка, что опечатка (§3.3). Чинится механически по
   диагностике: убрать метрику — значит убрать и директивы, её адресующие.
9. **`severity: info` становится недопустимым для трёх severity-ключей** переводимых каналов (§3.7):
   `unreachable_layer_severity`, `potential_shadow_severity`, `empty_template_severity`. Они продолжают работать
   для `warning`/`error`; `info` отвергается как ошибка конфигурации. У четвёртого канала, `coverage`,
   severity-ключа нет — он управляется режимом, и там не меняется ничего.

**Миграция механическая:** диагностика называет доступные каналы правила. В собственном коде правка ровно одна —
`@qmx-ignore coupling.instability` на классе `FindingProjector`
(`src/Reporting/FindingProjection/FindingProjector.php:23`). Заменяется на `coupling.instability.class`, а не на
`coupling.instability.*`: аннотация стоит на классе, поэтому namespace-канал к этому субъекту неприменим, и
точная форма честнее — сегодняшняя двусмысленность «покрывает ли она и namespace-уровень» устраняется. Остальные
живые подавления и все `@qmx-threshold` уже адресуют точные существующие имена (О6).

**За пределами `src/` миграция не механическая.** Документация в обеих локалях сегодня учит формам, которые план
делает ошибками: `@qmx-ignore complexity` (`website/docs/reference/default-thresholds.md:276`, `.ru.md:253`),
`@qmx-ignore complexity` как «suppresses every `complexity.*`» (`website/docs/usage/baseline.md:117`),
`disabled_rules: [..., duplication]` (`website/docs/getting-started/configuration.md:283-286`),
`--disable-rule=duplication` с поведенческим следствием — пропуском фазы обнаружения дубликатов
(`website/docs/usage/cli-options.md:530`). Все страницы правятся в пакете P6.

## 6. Пакеты работ

Внутрифазной параллельности нет. Причина не в том, что пакеты делят файлы — наборы ниже почти не пересекаются, —

## 7. Definition of Done

**Гейты на швах (оркестратор):** `composer check`; регенерация манифеста и qmx-проекции, затем
`composer architecture:check` зелёный; **разбор диффа `qmx-baseline.json` построчно** — ревью-гейт, а не
молчаливая регенерация. Пакеты добавляют импорты в классы с записанными потолками связности: пробитие означает
рефакторинг либо отдельно ревьюируемый пересмотр потолка.

| P5    | `@qmx-ignore` с именем правила многоканального правила даёт **Error** с перечислением адресуемого (регрессия на `coupling.instability`); `@qmx-threshold` на правиле без поддержки override даёт **Error**, а не инертную директиву; валидация идёт **после** резолва конфигурации — `@qmx-ignore health.cohesion` остаются валидными, и тест обязан падать на реализации, проверяющей по статическому реестру; **висячая ссылка на удалённую из конфига метрику даёт Error** (§5 п.8), а не инертную директиву; учёт срабатываний покрывает три формы подавления и ограничен включёнными правилами и проанализированным множеством файлов; несуществующий селектор в `exclude_namespace_channels` отвергается; каналы правила директив объявлены с владельцем и принимаемостью, `excluded.txt` для них пуст |
| P6    | grep по `website/docs` не находит ни одной префиксной формы без звезды в примерах; EN и RU правятся синхронно; `CHANGELOG.md` содержит восемь записей `Breaking` из §5; ADR принят и объясняет: почему равенство и явная звезда, почему категория лишена поведения, почему открытый словарь не даёт Error, что означает отсутствие декларации после изменения                                                                                                                                                                                                                                                                                                                                                                                                                                                |

**Верификация самих проверок.** Для трёх ключевых защит — захват потомка, отказ на неразрешимом имени, отклонение
конфиг-ошибки ратчетом — тест прогоняется против сломанного кода и обязан упасть. Тест, зелёный до и после,
не доказывает ничего.

| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `threshold-override-exact-matching` | Д2 и Д3 закрыты. **Но подложка отменяет его решение №3** («`@qmx-ignore` остаётся на prefix по violationCode, семья через bare-имя») вместе с его обоснованием, что префикс у подавления безопасен: полная квалификация плюс явная звезда заменяют обе формы. Первое сработало бы и без подложки — приписывать закрытие только ей неверно. Форма величины в самом плане решена — абсолютный счёт неотнесённых объявлений, не доля (ADR 0017, риск №5); докблок `channelDeclarations()` правится там же                                                                                                                                                                                                                                                                                                |

P3 переводит четыре канала в `ConfigurationError`, то есть делает их небазлайнимыми, и этот зуб исчезает; отсюда пол severity и запрет `info` (§3.7, §5 п.6). **Порядок решён: подложка первой**, и это записано в обоих файлах. Причина: подложка меняет, *что означает канал*, а severity-план — *как канал гейтит*; строить второе поверх нестабильного первого дороже. Следствие для severity-плана: он пишется в мире, где четыре архитектурных канала уже `ConfigurationError`, и потому не опирается на baseline-breach как на их гейт |

## 9. Вне скоупа

- **Позиционная идентичность ратчета (О9).** Ключи записей содержат байтовое смещение объявления, поэтому правка
  выше по файлу переписывает ключ и ратчет шумит на изменениях, не связанных с семантикой. Это отдельный словарь
  идентичности и отдельная задача; здесь он не трогается, но и не считается починенным.
- Слепая зона статического охранника эмиссии на коллабораторах (О7).
- Унификация инлайн-копий namespace-префикса — предмет селекторов неймспейсов.
- Per-level адресация суффиксом; аннотационный override для вычисляемых метрик.

## Приложение A. Установлено и не подлежит повторной проверке

Четыре раунда ревью (native, Codex, DeepSeek, Qwen) по редакциям 1-3. Ниже — факты, перепроверенные по коду
минимум дважды. Повторный отчёт о них на ревью — потраченный раунд.

**Числа:** 41 конкретное правило; 51 статически объявленный канал; 15 продакшн call-site'ов общего матчера в 6
файлах (`RuleCategory` 1, `RuleSelector` 10, `ThresholdOverride` 1, `RuleNamespaceExclusionProvider` 1,
`AnalysisPipeline` 1, `Suppression` 1); 5 путей ветвления по отсутствию декларации, все в `Policy/Baseline/**`;
33 правила объявляют `getCategory()`.

**Счётчиков аннотаций здесь сознательно нет.** Прошлые редакции трижды приводили неверное число живых
`@qmx-ignore`/`@qmx-threshold`, и последний раз — прямо в этом приложении, которое само же предупреждает об этом
классе ошибки. Подстрока встречается в трёх видах (живая аннотация в докблоке, экранированный пример, обычный
комментарий или строковый литерал), и экстракторы читают только `getDocComment()`. Нужно свойство — снимай
командой из О6.

**Механизмы построения `violationCode`:** 21 равенство имени напрямую; 12 через абстрактного предка с поздним
статическим связыванием; 4 конкатенации; 1 тернарник (`CboRule.php:246`); 1 `match` со строковыми литералами
(`TypeCoverageRule`, объявление и эмиссия строятся разными механизмами и совпадают случайно); 1 сиблинг-константы,
не производные от имени (`LayerViolationRule`, 4 из 5 каналов); 1 рантайм-имя из конфигурации через коллаборатор.
Скрипт — приложение B.

**Проверено верным:** `excluded.txt` существует (2 строки данных); `glob`/`fnmatch` на именах правил и кодов не
используется нигде; формат `qmx-baseline.json` изменением словаря каналов не инвалидируется (архитектурных и
директивных записей в ратчете нет); кэш AST риска не несёт; `ChannelEmissionStaticGuardTest` существует, skip-лист
пуст, `match` резолвится.

**Отклонённые гипотезы:** «смена идентичности инвалидирует ратчет» — опровергнута; «новые типы несериализуемы для
воркеров» — опровергнута, типы живут в главном процессе; «`debug-layer-assignment-json` конфликтует за
`LayerViolationRule`» — план этот файл не трогает.

**Ошибки перечислений, стоившие раундов** (метод, а не арифметика): grep по одному шаблону не видит тернарник и
сиблинг-константы; вхождение `self::NAME . '.'` может оказаться именем спана профайлера; обход по файлам
`*Rule.php` не видит 12 правил, объявляющих канал в предке; экранированный бэктиками пример в докблоке выглядит в
grep как живая аннотация — на этом обоснование одной из редакций опиралось на несуществующий факт. Самый дешёвый
детектор — **расхождение двух независимых перечислений между собой**.

## Приложение B. Классификация механизмов идентичности

```bash
#!/usr/bin/env bash
# СЛЕПЫЕ ЗОНЫ: делегирование предку не разворачивается (бакет delegated-to-base смешивает
# объявление в предке и эмиссию в коллабораторе); косвенность через переменную попадает
# в бакет other (CboRule); регексы гоняются по всему файлу; эмиссия через инжектированный
# коллаборатор не видна. Бакет other — дефект классификатора, а не класс.
set -euo pipefail
cd "${1:?repo root required}"
for f in $(find src -name '*Rule.php' ! -name '*Interface.php' | sort); do
  grep -q '^abstract class' "$f" && continue
  base=$(basename "$f" .php)
  em=$(grep -c 'violationCode:' "$f" || true)
  if [ "$em" -eq 0 ]; then
    parent=$(grep -oE 'extends [A-Za-z]+' "$f" | head -1 | awk '{print $2}')
    echo "delegated-to-base|$base|${parent:-?}"
  elif grep -qE "violationCode: *match" "$f"; then echo "match-literals|$base|-"
  elif grep -qE "violationCode: *self::NAME \. '" "$f"; then echo "concat|$base|-"
  elif grep -qE "violationCode: *self::(COVERAGE|UNREACHABLE|POTENTIAL|EMPTY)[A-Z_]*" "$f"; then echo "sibling-const|$base|-"
  elif grep -qE 'violationCode: *(self::NAME|\$this->getName\(\)),' "$f"; then echo "equals-name|$base|-"
  else echo "other|$base|-"; fi
done
```

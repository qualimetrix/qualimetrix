# Measurement — what a rule really accepts, and what the listing advertises

Every table here is regenerated by an instrument beside it. Run them from the
repository root; each resolves its own bootstrap from its position in the tree,
so none depends on the working directory.

| Instrument                   | Writes                                       | Answers                                            |
| ---------------------------- | -------------------------------------------- | -------------------------------------------------- |
| `dump-declared-options.php`  | `declared-options.tsv`, `orphan-aliases.tsv` | what the declarations admit, per rule and depth    |
| `sweep-refusal.sh`           | `runtime-refusal.tsv`                        | what the shipped binary names in its refusal       |
| `check-agreement.php`        | — (exit 0/1)                                 | whether the two witnesses agree                    |
| `measure-declared-delta.php` | — (report)                                   | how large the gate would judge the listing's delta |

```
php  docs/internal/plans/rules-listing/measurement/dump-declared-options.php \
   > docs/internal/plans/rules-listing/measurement/declared-options.tsv
     docs/internal/plans/rules-listing/measurement/sweep-refusal.sh \
   > docs/internal/plans/rules-listing/measurement/runtime-refusal.tsv
php  docs/internal/plans/rules-listing/measurement/check-agreement.php
php  docs/internal/plans/rules-listing/measurement/measure-declared-delta.php
```

## The two witnesses

`declared-options.tsv` is read out of the **production container**: every
`RuleMetadata` from `RuleExecutionInterface::allRules()`, that producer's
`optionsClass::acceptedOptionKeys()->acceptedForDisplay()`, and — for a
`HierarchicalRuleOptionsInterface` — each slot of `levelOptionsClasses()` with
its own accepted set. Aliases are joined through `ConfigKeySpelling::normalize()`
on both sides, splitting an alias target on its first `.` into (level, key). The
authored spelling is carried in `alias_target_as_authored` so the claim below
about non-canonical spellings is checkable from the table rather than from this
prose.

`runtime-refusal.tsv` shares no code path with it: for each (rule, depth) the
shipped binary is asked for an option nobody has and the allowed set is read out
of the refusal sentence. `check-agreement.php` holds the two against each other
and currently reports **64 pairs compared, 0 disagreements**.

`architecture.unassigned-class` is the one producer that does not accept
`enabled` at all — its `mode` is the real switch, and `enabled` is declared
*answered-by-the-class*. Its refusal reads `Options here: mode, suppress-*`.

## The gate's delta, in the gate's own unit

`measure-declared-delta.php` builds the listing the plan specifies and measures
it with `QmxFindingGate\ExactDiff`:

|                                       | changed lines | limit |
| ------------------------------------- | ------------- | ----- |
| one step, `before -> full`            | **320**       | 200   |
| two steps, `before -> alias spelling` | 72            | 200   |
| two steps, `alias spelling -> full`   | 182           | 200   |

`changedLineCount()` sums **both sides of every hunk**, and `ANCHOR = 4` keeps a
run of fewer than four identical lines from splitting one — so context between
nearby edits counts as change. Counting added-and-removed lines instead gives
134 and is not the gate's unit; reading one as the other under-reports by more
than half.

## What these instruments do not see

- **Whether a declared key is actually read.** Both witnesses read the same
  declaration (`acceptedOptionKeys()`); neither executes `fromArray()`. A key
  declared and then ignored by its own options class would be reported here as
  a real option. Recognition was spot-checked for five spellings — kebab, snake
  and camel forms of `class.max-warning`, `exclude-data-classes` and
  `min-lines` all exit 0 rather than 3 — but recognition is not application.
- **Keys read without being declared.** Same reason, mirrored.
- **The `answered-by-the-class` state.** `acceptedForDisplay()` omits it, so a
  key a class recognises only to refuse in its own words is counted nowhere
  above. That matches what the refusal prints.
- **The predicted listing is a prediction.** `measure-declared-delta.php`
  renders the format the plan specifies; no code implements it yet. A rendering
  that differs — a wrapped long option list, one more blank line — moves the
  320/72/182 figures. Re-run it against the real listing once the command
  changes, and treat the two-step margin (182 against 200) as provisional
  until then.
- **Semantics.** Nothing here says what an option *reaches*. For `threshold`
  that question is the open subject of `docs/internal/plans/shorthand-scope/`.

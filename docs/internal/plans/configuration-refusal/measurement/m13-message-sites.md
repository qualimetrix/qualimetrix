# M13 — «сообщение адресует не ту поверхность, которой пользовался автор»

Перечисление снято на дереве `1513bf67` (worktree `x12-orchestrator-k0m-8334bb`).
Предмет: отказ (или предупреждение) называет не ту поверхность, на которой автор
писал, либо не тот ключ, либо последствие вместо причины, либо форму, которой не
существует. Разное **написание одного и того же имени** — предмет соседнего
перечисления; здесь такие находки только помечены в «Смежном».

Все прогоны — на однофайловом фикстуре (`Probe\A`; где нужна находка —
`Probe\B` с CCN 16), протокол
`bin/qmx -d <probe> --no-ansi check src --workers=0 --no-cache --no-progress
--fail-on=none [--format=json]`, `1>out 2>err; ec=$?` сразу и без пайпа,
YAML пишется `printf '%b'`.

**Развилки, решённые самостоятельно.** (1) Пробник однофайловый, а не `src/`
продукта: все перечисленные отказы срабатывают до анализа, а там, где вердикт
зависит от найденного (базлайн, инлайн-директивы), фикстура доводилась до нужной
находки, а не подменялась. (2) Файл на русском по прямому указанию задания,
хотя языковая политика репозитория — английский; решение оставлено за
заказчиком. (3) Строка засчитывается в M13, только если сообщение называет
**другую поверхность или другой ключ**; совет «а можно ещё вот так» сам по себе
дефектом не считается — засчитан лишь случай, где два сестринских отказа на одну
и ту же ошибку советуют разные поверхности.

## 3. Чем получено и чего этот способ не видит

**Перебранные каналы.**

- **Символьный (Serena).** Вызваны `initial_instructions`; `find_symbol` по
  `RuleSelector/matchesKnownIn`, `RuleSelector/selectorMatchesProducer`,
  `RuleSelector/matchesName` (это дало решающее свидетельство для M-05/H-01…H-04);
  `find_referencing_symbols` по `RuleInputValidator/conflictingSelectionWarning`
  (единственный вызов — `CheckCommand::doExecute`, M-06) и по
  `RetiredSuppressionOptions/refusalText` (три двери, M-11). Всё остальное по
  символам делалось прямым чтением файлов и grep'ом по именам статических
  методов — то есть Serena покрыла развилки семантики селектора и достижимость
  сайтов, а не весь обход.
- **Строковый литерал с интерполяцией.** Сплошной grep по `src/` на литералы,
  содержащие `--<flag>`, плюс обратный grep на snake_case-ключи YAML внутри
  `src/Infrastructure/Console/**`. Это дискриминатор, породивший M-01, M-06,
  M-08, M-13: флаг в тексте под `src/Analysis/` заведомо достижим и с
  YAML-двери.
- **Сетка опечаток (пробник).** По одному переименованию за раз:
  `computed_metrics` (6 ключей), поля записи базлайна (5), `architecture`
  (6 пробников), `coupling`/`cache`/корневые ключи и их типы. Отсюда M-02, M-03,
  M-09, M-10 и отрицательный результат по `architecture`.
- **Справка команды.** Снята прогоном для всех 13 команд; каждое перечисление
  значений и каждый пример проверены отдельным прогоном (раздел 2).
- **Словарь продукта против селектора.** Все 13 групп, которые печатает отказ
  `qmx rules -g`, поданы в `--disable-rule`.
- **README компонентов.** `src/Analysis/Configuration/README.md` (таблица
  псевдонимов CLI) — источник H-08.

**Чего этот способ не видит.**

- **Сообщения, собираемые из кусков в рантайме** (склейка через VO, метод enum
  или `implode` по вычисленному списку): grep по литералу их не ловит, Serena не
  видит текст. Проверены только достижимые перечисленными пробниками.
- **Пути, требующие настоящего репозитория, кеша, параллельных воркеров и
  HTML-отчёта:** `--report=git:*` дальше проверки «внутри ли git»,
  `--cache-dir` на нечитаемом пути, `--workers>0`, шаблоны
  `src/Reporting/Template/`, форматтеры кроме `json`/`text`/`summary`/`dot`.
- **`hook:install` / `hook:status` / `hook:uninstall`** — требуют git, дальше
  разбора опций не проверены (`--restore-backup` проверен: есть и в справке, и в
  реализации).
- **Пресеты из файла** (`--preset=./file.yaml`) и `-c/--config` на битом или
  отсутствующем файле — не перебирались.
- **Документация сайта (`website/docs/**`)** — вне перечисления целиком. H-14 —
  единственный случай, где документная поверхность (пример в справке) сверена с
  деревом.
- **Тесты** как канал не перебирались: ожидаемая строка в тесте закрепляет
  дефект, но не является местом его формирования.
- **Полная карта «какая проверка стреляет первой»** внутри одной двери не снята.
  Именно она определяет, сколько ещё строк вида «названо последствие» всплывёт
  после починки верхних проверок; измерена только там, где дала отдельную
  строку (M-09, M-12).
- **Молчание** (вход принят без сообщения) фиксировалось попутно и не
  перечислено полностью — это другой механизм.

## 4. Смежное

- **Другое написание того же имени** (предмет соседнего перечисления):
  - `exclude_health: [typng]` → в тексте `health.typng` и список `health.*`:
    возвращён нормализованный рендер имени, а не токен автора (обе формы
    принимаются, `ec=0` и на `typing`, и на `health.typing`);
  - отказ `rules: {complexity.ccn: {nosuchopt: 1}}` печатает опции в kebab-case
    (`suppress-namespace-channels`, `suppress-paths`), тогда как автор в YAML
    писал snake_case; обе формы принимаются.
- **Коды возврата.** Один и тот же `--disable-rule=complexity`: `check` `ec=3`,
  `directives` `ec=3`, `baseline:generate` `ec=1`, `baseline:explain` `ec=1`
  (и текст уходит в stdout, а не в stderr), при том что `check --help` обещает
  «3 = config/input error». Не M13 и не расхождение формы — отдельный дефект.
- **Молчание вместо отказа** (не M13, но те же двери): опечатки в
  `description` / `levels` / `inverted` / `warning` / `error` внутри
  `computed_metrics`, поле `mode` в записи базлайна, `--log-level`,
  `--profile-format`, `graph:export --direction`, `--rule-opt rule:option` без
  `=value`, `baseline:explain --channel=nosuch`.
- **Асимметрия дверей:** `parallel.workers: -3` в YAML принимается молча, а

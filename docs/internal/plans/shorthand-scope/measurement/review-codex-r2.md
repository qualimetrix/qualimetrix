## codex-02 (переоткрыта раундом 2)

- **reviewer**: codex
- **severity**: HIGH
- **kind**: contract
- **domain**: reliability
- **title**: `scope` по-прежнему обходит per-layer unfold и нарушает C3 в межслойной ориентации
- **mechanism**: C1 объявляет reach `scope → class`, C3 требует «Specificity never overrides layer priority, in either orientation». Ревизия 2 разрешила конфликт раунда 1 в противоположную сторону: P3 ЗАПРЕЩАЕТ push-down `scope` («pushing it here too would apply it twice»), а P4 обязан сохранить композицию в `CboOptions::fromArray()`. Но эта композиция происходит ПОСЛЕ слияния слоёв, где провенанс потерян: нижний слой пишет `class: {scope: all}`, верхний — top-level `scope: application`; `fromArray()` копирует top-level значение только при отсутствии вложенного, поэтому побеждает нижний слой. Один и тот же ключ, объявленный в C1 как достигающий `class`, единственный из всей таблицы reach не подчиняется C3.
- **trigger**: воспроизводится в нормальной работе — два авторских слоя (свой preset/config плюс config/CLI), нижний с `class.scope`, верхний с top-level `scope`
- **in_scope**: да (якорь — пересмотренный план; продуктовый код лежит в базе `main` и служит доказательством)
- **anchor**:
  - `docs/internal/plans/shorthand-scope/01-contract.md:68-76` (C3), `:202-205` (reach `scope`)
  - `docs/internal/plans/shorthand-scope/02-cure.md:145-147` (P3 исключает `scope`)
  - `src/Analysis/Evidence/Coupling/CboOptions.php:94-97`
- **evidence**:
  > **`scope` is not**: `CboOptions::fromArray()` composes it by key already, and pushing it here too would apply it twice. (`02-cure.md:145-147`)

  > Specificity never overrides layer priority, in either orientation. (`01-contract.md:68`)

  ```php
  // Allow scope to be set at top level and propagate to class config
  if (isset($config['scope']) && !isset($classConfig['scope'])) {
      $classConfig['scope'] = $config['scope'];
  }
  ```
- **verification**: confirmed
- **verification_note**: перепроверено фасилитатором. `CboOptions.php:94-97` совпадает с цитатой дословно; второе место той же логики — `:73-75` (плоская ветка, там top-level `scope` копируется безусловно). `02-cure.md:145-147` и `01-contract.md:202-205` действительно фиксируют решение «`scope` остаётся в `fromArray()`», и P4 обязан эту композицию СОХРАНИТЬ. В DoD P3 (`02-cure.md:158-163`) `scope` не назван. `grep -n "scope" 03-acceptance.md` даёт два вхождения, и ни одно не является acceptance-кейсом на межслойную ориентацию `scope` (одно — `pair-kind-scope.tsv`, второе — строка `class.scope × scope` в списке NOT OBSERVABLE). Оговорка по достижимости, перенесённая из раунда 1: shipped-пресеты `strict`/`legacy`/`ci` слова `scope` не содержат, поэтому пару слоёв автор должен написать сам — триггер достижим, но не «из коробки». Фасилитатор severity Codex не менял.
- **fix_direction**: либо реализовать per-layer нормализацию `scope` (и тогда снять довод «применится дважды», описав, что именно применяется дважды), либо изменить сам контракт: назвать `scope` явным исключением из C3 с обоснованием. В любом случае — обе межслойные ориентации в DoD P3 и в кейсе finding-gate.

## codex-07

- **severity**: MEDIUM

- **evidence**:
  > **(c)** every leaf the shallower side changed whose pointer lies OUTSIDE R is present in `both` with the same value (`axis-b-values.md:104-105`)

  > **The push-down only ADDS keys to a level. It never removes, replaces or rebuilds any key the level wrote.** (`01-contract.md:50-52`)

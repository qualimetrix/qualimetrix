# П4. Команда и контракт, который она читает

Пакет делает ответ доступным человеку и машине. Логики вердикта здесь нет ни
строки — адаптер, две проекции одного отчёта, проводка и **объявление контракта
вместе с его первым потребителем**. CI в следующем пакете: включать enforcement
можно только после того, как измерена его цена.

## Что заводится именно здесь, а не раньше

Проверяющий манифеста отвергает запись потребителя, которого нет
(`unused contract consumer entry`,
`generate-modular-architecture-production-inventory.php:1932`). Поэтому:

- `Analysis\Run\Contract\Pipeline\DirectiveAuditInterface` и
  `DirectiveAuditReport` объявляются в этом пакете, вместе с командой —
  единственным их читателем;
- типы вердиктов Inline повышаются здесь из `internal` в `contract`, потому что
  команда печатает их поля.

## Поверхность

```
bin/qmx directives [paths...] [--config=…] [--format=text|json]
```

Имя верхнеуровневое: `CLI_CONVENTIONS.md:33` даёт критерий буквально — команда,
принимающая исходный код и производящая аналитический вывод, верхнего уровня;
`noun:verb` для управления подсистемой. Прецедент рядом — `qmx rules`.

Коды возврата сняты с продукта (`CheckCommand.php:99-105`,
`ExitCodeResolver::resolve()`), а не придуманы:

| код | значение                                              |
| --- | ----------------------------------------------------- |
| 0   | ни одной `Inert`                                      |
| 2   | найдена хотя бы одна `Inert`                          |
| 3   | негодный ввод или ошибка конфигурации                 |
| 4   | прогон неполон (`ReportCoverage::isComplete()` ложно) |

`1` не занимается: у вердиктов нет второй ступени тяжести, а `1` в этом продукте
означает «предупреждения». `Overrun` и `Unmeasured` печатаются, но кода возврата
не двигают: первое — невыполненное обещание, требующее человека, второе — вовсе
отсутствие ответа.

Текстовый отчёт: шапка с проанализированным охватом и селекцией (если она не
пуста), затем строка на директиву — путь, строка, форма, адресат, вердикт;
для `Unmeasured` причина, для `Masked` перекрывающая директива, для правила без
публикуемой границы пометка, что вопрос `Overrun` не задавался (О5). Итог
четырьмя числами.

JSON — тот же отчёт документом; обе проекции читают один `DirectiveAuditReport`.
На ошибке в JSON печатается конверт `{error, exit_code}`, как у
`debug:layer-assignment`.

Оговорки печатаются фактами отчёта, а не дисклеймером: охват в шапке (О2),
`Unmeasured` с причиной (О3), пометка ненаблюдаемой границы (О5); О1 — в справке
команды.

## Размещение и паритет с `check`

- `src/Infrastructure/Console/Command/DirectivesCommand.php`. Не в `Debug/`:
  это обслуживание собственных аннотаций проекта, а не диагностика внутренностей.
- Регистрация: `#[AsCommand]`, запись в карте `bin/qmx`, регистрация сервиса в
  конфигураторе Infrastructure — автоконфигурация на команды не
  распространяется, они перечислены явно.
- **Discovery резолвится тем же путём, что у `check`.** Утверждение «принимает
  пути ровно как `check`» ложно, если команда не получает того же
  discovery-фактора: пользовательские `exclude` и git-область (`--report=git:…`)
  применяются в `AnalysisFileDiscovery` через переданный `FileDiscoveryInterface`,
  и команда, не пробросившая его, молча проанализирует не то дерево — а вердикт
  относителен охвату. Паритет проверяется тестом, а не заявляется.
- Команда **импортирует типы вердиктов Inline**, потому что печатает их поля.

## Документация

- `website/docs/usage/cli-options.md` и `.ru.md` — обе версии одновременно.
- `CHANGELOG.md`, раздел `Changed`, одной строкой от лица пользователя.
- ADR: D3 (почему отдельный контракт, а не поле результата и не порт), D5
  (почему вердиктов четыре и почему один наблюдаем не везде), D6 (почему

- README `src/Infrastructure/`.

  checkout>/website/.venv/bin/mkdocs`.

## Тестовый план

- Функциональный на фикстуре: `--format=text` и `--format=json` одного прогона
  согласованы по составу вердиктов.
- Коды возврата: `0` без инертных, `2` при инертной, `0` при `Overrun` без
  инертных, `3` на негодном формате и на нечитаемом конфиге, `4` на дереве с
  неразбираемым файлом.
- `Unmeasured` не роняет код возврата — отдельным тестом: это место, где легко
  перепутать «нет ответа» с «долг есть».
- **Паритет охвата**: прогон команды и прогон `check` на одном конфиге с
  `exclude` и с git-областью анализируют одно и то же множество файлов. Мутация
  «не пробрасывать discovery» обязана покраснеть здесь.
- Команда, зарегистрированная в `bin/qmx`, но не в контейнере, падает явно.

## Definition of Done

- Команда есть в `bin/qmx --help` и исполняется на нашем дереве; результат по
  `src/` разобран: каждая `Inert` и каждая `Overrun` объяснена **механизмом**, а
  не фактом исчезновения находки — главный урок Х1.
- Обе языковые версии документации обновлены; `composer docs:check` — exit 0.
- ADR написан, `CHANGELOG.md` дополнен.
- **Манифест**: декларация команды, контракт `DirectiveAuditInterface` со своим
  единственным потребителем, повышение типов вердиктов Inline до контракта.
- Новые `.md` плана вписаны в список классификации
  `scripts/generate-modular-architecture-production-inventory.php`.
- `composer check` — exit 0; `composer gate -- --reference=<коммит П3>` — GREEN.
- Коммит и полная цепочка до начала П5.

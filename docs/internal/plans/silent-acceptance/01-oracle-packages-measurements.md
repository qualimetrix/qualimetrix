## 19. Измерено этим этапом (сверх `measurement/`)

Команды воспроизводимы дословно; фикстура — один класс с 4 находками.

1. **`architecture.unreachable-layer` даёт exit 2 вопреки `--fail-on=none`.**
   Конфиг с недостижимым слоем `ghost` + `--fail-on=none` → **exit 2**; тот же
   прогон без `ghost` → **exit 0**. Следствия: для стенда exit — одно из
   сравниваемых полей тройки, а не самостоятельный критерий; владелец 02 обязан
   знать, что прецедент формы «находка» обходит `--fail-on`. Механизм не
   вскрывался — **гипотеза**, факт — наблюдаемое.
2. **cwd решает, какой конфиг подтянется.** Прогон по фикстуре при cwd = корень
   репозитория подхватил `qmx.yaml` продукта и дал exit 2 при `--fail-on=none`;
   при cwd = каталог фикстуры — exit 0. Отсюда инвариант «cwd = фикстура».
3. **CLI `--fail-on` перекрывает YAML `failOn`** — перекрытие §6 реально,
   направление измерено.
4. **Один прогон `check` на однофайловой фикстуре ≈ 0,3 с** (`time`, холодный
   контейнер, `--workers=0 --no-cache`).
5. `--format=text` на этой фикстуре байт-в-байт совпал между двумя прогонами.
   Свидетельство **слабое** (одна фикстура, 0,3 с): строка нормализации на
   `format:text` заводится по измерению стенда, а не по этому наблюдению.
6. **Все 32 наследованные строки — CLI** (`awk` по колонке `verdict_source`
   в `doors-reconciled.tsv`): `paths`, `--config`, `--preset`, `--only-rule`,
   `--disable-rule`, `--rule-opt` на `baseline:*`, `directives`, `graph:export`;
   конфигурационных среди них ноль. Отсюда §8: сетка снимает эти 32 по
   построению, а конфигурационное наследование — отдельный, впервые названный
   долг.
7. **Отказ бывает при ненаблюдаемом попадании.** `check src --memory-limit=zzz`
   → **exit 3**, stderr `Configuration error: Invalid memory_limit "zzz"…`;
   `--memory-limit=512M` → exit 0; без флага → exit 0, и тексты `H` и `A`
   расходятся только длительностью, то есть после нормализации совпадают.
   Отсюда порядок шагов `01-oracle.md` §4: отказ проверяется раньше
   наблюдаемости, иначе доказуемо отказывающая дверь уходит в `NOT OBSERVABLE`.
8. **Строку нормализации `format:summary` разрывает не только эхо.** Регекс
   гейта `~(— \d+ files? analyzed, ).*(s)$~m` проверен `preg_match` на четырёх
   строках: `…analyzed [namespace: Acme\NoSuch], 0.0s` — 0;
   `…analyzed [namespace: ], 0.0s` (эхо вырезано) — 0; `…analyzed (scoped), 0.0s`
   — 0; `…analyzed, 0.0s` — 1. Источник вставок —
   `SummaryFormatter::renderHeader()`: `(scoped)`, затем `[namespace: …]` либо
   `[class: …]`, и только потом `, %.1fs`. Следствия: утверждение первой
   редакции «после вырезания эха строка снова совпадает» **ложно**; вырезание
   вставки целиком класс не закрывает, потому что в `(scoped)` поданного
   значения нет; лечение — override-остаток supplement на длительность
   (`01-oracle-mechanics.md` §5), а сторож полноты — режим `--stability`.
9. **Семь команд объявляют `--config`** (`check`, `directives`,
   `debug:layer-assignment`, `baseline:cleanup/explain/generate/update`) — это и
   есть множитель конфигурационной половины сетки. Grep по
   `src/Infrastructure/Console/Command/` показал явную загрузку конфигурации у
   `CheckCommand` и `BaselineRun` и не показал у `graph:export`/`rules`; вопрос
   «подтягивается ли конфиг глубже по стеку» остаётся открытым и назван слепым
   пятном в §3.
10. **Пути в эхе печатаются абсолютными.** `check src --config=<путь>/nosuch.yaml`
    → exit 3, текст `Configuration file not found: <абсолютный путь фикстуры>/nosuch.yaml`;
    `check src --format=json -o /nosuchroot/r.json` → exit 3, JSON с абсолютным
    путём внутри. Значение в `probes.tsv` машинно-независимо, а §9 подменяет
    корни на `<FIXTURE>`/`<REPO>`, поэтому литерал декларации в тексте не
    встречается ни до, ни после записи. Отсюда правило `01-oracle.md` §4:
    сопоставление **после** тех же преобразований плюс двусторонняя колонка
    `echoes`. Наблюдение снято ревьюером второго раунда; на этих двух дверях
    вердикт решает код возврата, поэтому свидетельство — про механизм, а не про
    уже неверный вердикт.

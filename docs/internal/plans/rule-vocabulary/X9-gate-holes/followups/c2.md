# Запись для FOLLOWUPS.md — пакет C2 захода Х9

## Х9 (2026-09-05) — ключи метрик, написанные руками в JS шаблона

Слепое пятно «JS-шаблон хранит ключи метрик как ручные строковые литералы,
и ни один PHP-страж их не видит» закрыто своим читателем: населена и
перемерена вручную оценённая разведкой Х9 картина (~8 боевых мест), выбрана
и реализована защита от дрейфа.

- **Популяция:** `src/Reporting/Template/scripts/metric-key-catalog.mjs`
  разбирает `src/*.js` и `tests/*.js` парсером `rollup/dist/parseAst.js`
  (тот же нативный парсер, на котором vite строит бандл этого шаблона —
  «читатель того же языка») через `estree-walker`, собирая строковые
  Literal-узлы, чьё значение имеет форму `family.rest`, где `family` — первый
  сегмент реального ключа каталога `MetricName.php`. Комментарии находятся
  отдельным проходом: диапазоны строковых/шаблонных литералов, найденные тем
  же AST, замаскированы пробелами, и по остатку исходника ищутся `//` и
  `/* */`-области. Каталог — 82 константы `MetricName.php`, семь суффиксов
  агрегации `AggregationStrategy.php` (`sum/avg/max/min/count/p95/p5`) и
  шесть ключей `HealthDimensionCatalog.php` (`health.*`).
  `scripts/collect-metric-keys.mjs` — разовый CLI, пишет таблицу на диск
  (`node scripts/collect-metric-keys.mjs`, не часть `npm test`/`npm run
  build`).
- **Таблица:** `X9-gate-holes/enumeration-js-metric-keys.tsv`, шапка
  называет метод и слепые пятна (конкатенация, интерполяция шаблонных строк,
  ключ без узнаваемого семейства, файлы вне `src/Reporting/Template/{src,tests}`).
  317 строк (счёт снят из самой таблицы, `cut -f1 | sort | uniq -c`, после
  добавления пакетом собственного `tests/metric-key-catalog.test.js` — таблица
  тем самым видит и его докстроку, отсюда небольшой сдвиг относительно
  промежуточного прогона): `code` 27 (боевые литералы в `src/*.js`, семь
  файлов — `color.js`, `detail.js`, `hints.js`, `main.js`,
  `martin-diagram.js`, `subtree.js`, `tree.js`; разбивка — 21 `health.*`, 5
  `size.loc.sum`, 1 `maintainability.mi.avg`. Оценка разведки Х9 (~8 мест в
  4-5 файлах) считала только `size.loc.sum` и `maintainability.mi.avg` и не
  видела `health.*`-ключи вовсе — перемер даёт другую картину, а не
  уточнение той же), `comment` 15 (докблоки, включая ключи внутри примеров
  вроде `color.js:60`, которые наивный grep по тексту не отличает от
  боевого кода), `test` 272 и `test-comment` 3 (фикстура `hints.test.js` —
  включая один нарочно тестовый `health.unknown`, не входящий в каталог, не
  дефект, а тестовые данные для ветки «неизвестный ключ», — плюс докстрока
  нового `metric-key-catalog.test.js`, упоминающая `size.loc.sum` и
  `health.overall` как пример). Разрыв с каталогом на боевом коде — 0: все
  27 `code`-литералов реальны.
- **Развилка (обе цены):**
  - (а) *генерируемый модуль*: ключи уезжают в файл, сгенерированный из
    `MetricName.php`, шаблон его импортирует — рассогласование ловит сборка
    (`vite build`/`npm run dev` упадёт на отсутствующем экспорте). Цена:
    (1) переписать все 27 боевых мест в 7 файлах на импорт констант вместо
    строкового литерала; (2) завести шаг кодогенерации, который запускает PHP
    из JS-тулчейна (`npm run dev`/`npm run build` начинают требовать PHP в
    `PATH`, чего сейчас нет вовсе — JS-пайплайн этого шаблона на PHP не
    завязан); (3) кодогенерация должна перегенерироваться при каждом запуске
    (иначе устаревает так же, как ловимый ею литерал) — это лишний шаг перед
    `npm run dev`, которого сегодня нет.
  - (б) *страж-тест тем же читателем*: `tests/metric-key-catalog.test.js`
    гоняет тот же `metric-key-catalog.mjs` по `src/*.js` при `vitest run` и
    падает, если найденный `family.rest`-литерал не входит в каталог. Цена:
    ноль правок боевого кода, ноль новых зависимостей тулчейна, страж
    исполняется, только когда кто-то руками гоняет `composer test:js`/`npm
    test` (см. ниже).
  - **Выбор — (б).** Цена варианта (а) не окупается: этот JS-шаблон сегодня
    не знает о существовании PHP-бинаря, и вводить эту связь ради 27
    хардкод-мест — цена архитектурная (кросс-тулчейновая зависимость сборки),
    а не только построчная. Страж ловит тот же класс дефекта (опечатку/дрейф)
    тем же читателем при на порядок меньшей цене; проверено на подставленной
    мутации (`size.loc.sum` → `size.lcc.sum` в `martin-diagram.js`) — тест
    покраснел с именем файла, строки и ключа. Ни PHP-скрипт, ни новый
    генератор в корневом `scripts/` пакету не понадобились: выбранный
    вариант (б) читает `MetricName.php`/`AggregationStrategy.php`/
    `HealthDimensionCatalog.php` как текст прямо из JS (regex по
    `public const string ...`/`case ... =`/ключам массива), без вызова PHP.
- **Вторая копия каталога в `hints.test.js`:** вне предмета пакета. Это не
  сырой список ключей-с-риском-опечатки, а фикстура, зеркалящая другой PHP-
  артефакт — `MetricHintProvider::exportForHtml()` — который сам является
  курированным подмножеством каталога (только метрики, у которых есть
  hint-диапазоны; `health.unknown` там намеренно отсутствует из каталога,
  проверяя ветку «неизвестный ключ»). Подвести её под механизм этого пакета
  означало бы валидировать её против не того источника: она обязана
  расходиться с полным каталогом `MetricName`, это и есть её инвариант.
  Дрейф самой этой фикстуры от `MetricHintProvider` — отдельный вопрос,
  вне слепого пятна C2 (которое про JS, ссылающийся на ключи каталога напрямую,
  а не про JS-тесты, зеркалящие другой PHP-экспорт).

### Предложение: включить `composer test:js` в `check:code`

`test:js` не входит ни в `composer check`, ни в `.github/workflows/qmx.yml` —
ни этот страж, ни остальные 145 JS-тестов шаблона не гоняются нигде, кроме
рук. Измеренная цена: тёплый прогон (`node_modules` уже установлен, как в
любой разработческой машине и в закешированном CI-раннере) —
`time npm test` внутри `src/Reporting/Template`: 0.52s wall (0.23s
собственно vitest, остальное — старт npm/node). Неизмеренная часть — `npm
ci` на холодном CI-раннере без кеша `node_modules` (сеть + установка
`vite`/`vitest`/`rollup`); эта часть не снята в рамках пакета C2 (реальный
раннер не поднимался, только чтобы не трогать текущий `node_modules`
проекта), назвать явно как открытый пункт при решении владельца.

Решение о включении — за владельцем; пакет `composer.json` не трогает.

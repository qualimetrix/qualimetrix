# Пакет B2 — корпусный кейс «подавление поверх ledger-исключения»

Вторая редакция. Первая отказалась класть контрольную пробу в корпус по ложной
причине («второй производитель дал бы `coverage-multiplicity`») и не назвала
перегенерируемый артефакт. Обе находки — один способ: утверждение об инструменте
без команды, которой оно проверено.

Запись `FOLLOWUPS.md` «Ни наше дерево, ни корпус гейта не подают вход, на котором
правка видна» (Х2 П1). П1 перевёл универсум аудита директив с `published` на
`produced`; единственным свидетелем осталась фикстура
`DirectiveAuditUniverseTest`. Относительно эталона захода П1 уже влит, поэтому
кейс — не объявленная дельта, а вход, на котором **будущая** правка универсума
станет наблюдаемой сверкой версий.

## Что измерено (2026-09-02, на копии кейса вне репозитория)

В кейс добавлен класс в неймспейсе `Corpus\RuleExclusionLedger\Excluded` — том,
который ledger правила `code-smell.long-parameter-list` исключает через
`exclude_namespaces`, — с методом на пять параметров и
`@qmx-ignore code-smell.long-parameter-list <причина>` на нём.

| наблюдение                                | сегодня (`produced`)                                                |
| ----------------------------------------- | ------------------------------------------------------------------- |
| `byMechanism.suppression`                 | `0` — ledger срабатывает раньше, подавление находки уже не видит    |
| строка в `suppressed`                     | одна, механизм `rule-namespace-exclusion` (счёт 1 → 2)              |
| `annotation.unused-directive` на фикстуре | не порождается: директива признана сработавшей по `produced`        |
| публикуемые находки кейса                 | одна и та же до и после — `code-smell.long-parameter-list@callable` |

Отсутствие третьей строки — факт об универсуме, а не о выключенном канале. Это
проверено отдельной пробой: директива, не адресующая ничего вообще, в том же
кейсе и той же конфигурации даёт `annotation.unused-directive` уровня `info`.

Отсюда свидетельская сила фикстуры: при возврате универсума к `published`
директива становится инертной, и это **новая находка на сравниваемых
поверхностях**.

## Почему контрольная проба не кладётся в корпус

Не из-за множественности: кейс объявлен `"coverage": "auxiliary"`, а
`Gate.php:1112` делает `continue` для auxiliary **до** заполнения `$producers`,
так что `coverage-multiplicity` там невозможен по построению (проверено чтением;
первая редакция утверждала обратное).

Настоящая причина другая: claim auxiliary-кейса проверяется поштучно
(`checkCaseClaim` вызывается до `continue`), поэтому зажжённый канал пришлось бы
внести в `channels` — а `annotation.unused-directive@file` принадлежит кейсу
`annotations`, который и существует ради сломанных директив. Проба — контроль
моего измерения, а не вход, которого корпусу не хватает.

## Контроль: фикстура обязана краснеть

Свидетель проверяется снятием. На изолированной копии дерева
`AnalysisPipeline::reportedFindings()` спрашивается о `published` вместо
`produced` (мутация ломает поведение, не тип), и на кейсе исполняется, из
каталога кейса и с его собственной конфигурацией:

```
cd finding-gate/cases/rule-exclusion-ledger
php <копия>/bin/qmx check src --workers=0 --no-cache --no-ansi -c qmx.yaml -f json \
    <четыре --rule-opt кейса из case.json>
```

Ожидание: появляется находка `annotation.unused-directive` на файле фикстуры.
Мутация откатывается восстановлением из git, а не копией файла.

## Файловый набор

- `finding-gate/cases/rule-exclusion-ledger/src/Excluded/<фикстура>.php` — новая;
- `finding-gate/cases/rule-exclusion-ledger/case.json` — `description`;
  `channels` и `explainSubjects` не меняются;
- `docs/internal/plans/rule-vocabulary/enumeration-renames.tsv` —
  **перегенерируется** `composer enumeration:renames`: колонка `finding_gate`
  строк 24 и 150 (`code-smell.long-parameter-list`, канал и продюсер) считает
  вхождения имени под всем `finding-gate/`. Величина дельты не предсказывается,
  а читается из диффа после перегенерации: счётчик режет по границе
  `(?<![\w.-])…(?![\w.-])` (`scripts/generate-rename-enumeration.php:247`),
  поэтому его число и число наивного `grep -c` не обязаны совпадать, и правка
  `description` в `case.json` может добавить своё вхождение.
- `FOLLOWUPS.md` — закрытие записи.

Директива несёт причину: `@qmx-ignore` без неё нарушает правило репозитория.

## Definition of Done

1. Фикстура добавлена; `case.json` описывает её назначение.
2. Контроль снятием исполнен, исход записан в тело коммита.
3. `enumeration:renames` перегенерирован **до** коммита, код возврата проверен.
4. Кейс продолжает зажигать ровно `code-smell.long-parameter-list@callable`:
   гейт не даёт `case-claim-mismatch`.
5. Запись в `FOLLOWUPS.md` закрыта.
6. `composer check` зелёный; `composer gate -- --reference=38ad58e9` — GREEN на
   полном корпусе (корпус читается обоими деревьями из кандидата, поэтому новая
   фикстура сама по себе дельты не даёт).

# Test audit: Reporting (tests/Unit/Reporting, tests/Reporting, tests/Functional/Reporting)

62 files in the slice (61 test classes + 1 non-test — the test double `StubChannelPresentation`).

## Two roots — what was found

These are not duplicates by purpose, but **two generations of layout**, both genuinely wired
into `phpunit.xml.dist` (the `Unit`/`Integration`/`Functional` sections list both roots
explicitly):

- `tests/Unit/Reporting/...` — the **old** "role-bucket by test level at the root" layout (the
  level is `tests/Unit`, `tests/Integration`, `tests/Functional`, the subject is a subfolder
  inside). The bulk of the files (44 of 62), unchanged structurally since the ADR 0022 migration.
- `tests/Reporting/<Capability>/<Level>/...` and `tests/Functional/Reporting/...` — the **new**
  layout per ADR 0022/0016 ("subject is the folder, test level is a subfolder inside the
  subject": `FindingProjection/Unit`, `Formatter/Sarif/Integration`, `GraphProjection/Unit`,
  etc.). Every file here is dated 2026-08-12 — 2026-09-12 (see
  `git log --diff-filter=A -- tests/Reporting`), i.e. created alongside new features already
  AFTER the migration.

Conclusion: `tests/Unit/Reporting` is not a cancelled or forgotten root, but an unfinished
migration tail: new code and new tests are already placed by subject, while the old formatters
(`JsonFormatterTest`, `SarifFormatterTest`, `TextFormatterTest`, etc.) stayed in their old place.
No SUT duplication between the roots was found (see "Duplicates and contradictions" — the one
real duplicate is inside the newer root itself, not between roots), but an unsystematic
test-level reclassification without a directory move was found (see below).

## Control candidates

- **`tests/Reporting/Formatter/Suppressed/Integration/SuppressionSnapshotFreshnessTest.php`** —
  a single assertion line: the return code of
  `scripts/generate-suppression-snapshot.php --check` equals 0. Checks the currency of
  `docs/internal/generated/suppression/*.tsv`, not a class's behavior.
- **`tests/Reporting/Formatter/Unit/FormatOptionKeyDeclarationTest.php`** (a `control-invariant`
  subtype) — scans ALL of the `src/Reporting/Formatter/**` sources with a text regex, looking for
  `--format-opt` key reads/declarations; doesn't create or call a specific formatter instance,
  the invariant applies to the whole subtree at once.
- **`tests/Reporting/Formatter/Sarif/Integration/SarifRuleDescriptorCoverageTest.php`** — not
  pure control (the bulk of the assertions are real `SarifRuleCollector` behavior), but one of
  the invariants checked per channel reads a file from disk (`website/docs/**.md`) and searches
  it for the `**Rule ID:**` anchor — i.e. it partially checks `website/docs` state, not just
  code. A borderline case, leaving the decision to the owner: split the test into "collector
  behavior" and "documentation currency" or leave it as is.

## Duplicates and contradictions

- **`tests/Reporting/FindingProjection/Unit/ConfiguredFindingExclusionsResolverTest.php`** vs
  **`tests/Reporting/Unit/FindingExclusionShapeRefusalTest.php`** — the same SUT
  (`ConfiguredFindingExclusionsResolver::resolve()`), overlapping, in places almost verbatim
  cases:
  - "a bare number as the directory name for `suppress_paths`" — checked in both
    (`itReadsABareNumberAsTheDirectoryNameItIs` / part of
    `itReadsABareNumberAsAPathNameAndStillRefusesItAsANamespace`);
  - "a bare number is refused for `suppress_namespaces`" — checked in both files by
    semantically identical assertions;
  - "a map instead of a list is refused for `suppress_paths`" —
    `itRefusesAMapWhereAListOfEntriesBelongs` matches verbatim one of the
    `provideUnexecutableValues` data-provider cases ('suppress_paths as a map') in the other
    file.
  Not a complete duplicate (`FindingExclusionShapeRefusalTest` has a broader data provider: a
  scalar, `[true]`, a map for `suppress_namespaces`, a non-string namespace element), but an
  overlap of at least three assertions is a tax, not a guard. A sensible option: merge into one
  file next to the SUT (`FindingProjection/Unit/`), keeping the broad data provider and removing
  the repeated simple cases.

- **An unconfirmed hypothesis (did not read either file line by line in full):**
  `tests/Unit/Reporting/Formatter/Sarif/SarifRuleCollectorTest.php` and
  `tests/Reporting/Formatter/Sarif/Integration/SarifRuleDescriptorCoverageTest.php` — both about
  `SarifRuleCollector`, the second explicitly calls itself an integration end-to-end sweep

- **A hypothesis:** `tests/Reporting/Unit/OutputFormatResolverTest.php` and

## How this was checked and what this method cannot see

Because of the orchestration's shared parallel-subagent limit, all 5 planned parallel read
agents crashed with "Concurrent subagent limit reached" at once — read and analyzed the files
myself, via `Bash`/`Read`/`grep`, without running the tests (as prescribed).

What was done:
- Read in full (Read/cat): `ConfigurationErrorProjectionTest.php` (partially, via grep + reading
  key spots), `ConfiguredFindingExclusionsResolverTest.php`,
  `FindingExclusionShapeRefusalTest.php`, `DeclaredChannelFileScopeTest.php`,
  `SuppressionCompositionBuilderTest.php` (via a grep of signatures),
  `SuppressionSnapshotFreshnessTest.php`, `SuppressionSnapshotKeyTest.php` (partially),
  `SarifRuleDescriptorCoverageTest.php`, `FormatOptionKeyDeclarationTest.php`,
  `CoverageProjectionFormatterTest.php`, `JsonShapePreservationTest.php`,
  `ArchitectureViolationSmokeTest.php` (imports + signature),
  `OutputFormatResolverTest.php`/`OutputFormatRefusesUnexecutableValuesTest.php` (method
  structure), `JsonOffenderSectionDensityTest.php`/`OffenderListRendererDensityTest.php` (the
  start), `SarifSchemaValidationTest.php` (the start), `FormatterRegistryTest.php` (structure).
- For the other ~40 files (mostly flat `Formatter/*Test.php` and subject-based
  Html/Json/Summary/Support tests), the check was a mass `grep`: presence of `#[CoversClass]`
  (gives the SUT with high confidence — this is the test author's own assertion, not my guess),
  a count of `public function` against `#[Test]` (catches CLAUDE.md §9 violations — found no
  settled false positive: every discrepancy turned out to be a method of an anonymous double
  class inside test helpers, not a test method), and grep signals of I/O (`ContainerFactory`,
  `proc_open`/`Process`, `file_get_contents`/`is_file`, `JsonSchema\Validator`,
  `sys_get_temp_dir`) for the category.

What this method cannot see:
- **The real behavior of the test body** for ~40 files where only signatures/imports/CoversClass
  were checked — I cannot guarantee there are no tautologies or mock-checks at the level of
  individual assertions inside (e.g. in `JsonFormatterTest.php` with 47 methods or
  `SummaryFormatterTest.php` with 42 — not read line by line).
- **Did not run the tests** — cannot confirm every `#[CoversClass]` marker is current with the
  code (it could be stale after a refactor) or that the "duplicates" really execute identically
  rather than having drifted apart via fixtures.
- Duplicates/overlaps between the **old and new root** (`tests/Unit/Reporting/...` vs
  `tests/Reporting/...`) were checked only by matching SUT names — a deep comparison of specific
  assertions was done only for the `ConfiguredFindingExclusionsResolverTest`/
  `FindingExclusionShapeRefusalTest` pair (both in the new root, not a cross-root case). The
  other cross-root hypotheses (Sarif, OutputFormat) are not confirmed by a line-by-line
  comparison, explicitly flagged as hypotheses.
- Defects in `SuppressionCompositionBuilderTest.php` and `FindingProjectorTest.php` (36 methods)
  — the structure was checked (a grep of `#[Test]`/signatures), not every method read in full;
  point defects inside, not caught by this pass, are possible.

## Assumptions

- The owning directory in `src/` for the "Placement" comparison was taken by a direct 1:1 match
  of the subfolder name (`Formatter/Html` ↔ `Formatter/Html`, `Formatter/Sarif` ↔
  `Formatter/Sarif`, etc.) — without reading the README of every subject in `src/Reporting/**`.
- For files without an explicit `#[CoversClass]` (several GraphProjection tests —
  `SarifRuleCollectorTest.php` is actually covers-marked, I meant
  `DotExporterTest`/`JsonGraphExporterTest`), the SUT was inferred from the imports and the class
  name, not from reading the entire test body.
- The `control` vs `integration` category for files touching the filesystem only for docs paths
  (`SarifRuleDescriptorCoverageTest`) was decided in favor of "integration with a control tail"
  — the final boundary is disputed, explicitly moved into "Control candidates" for the owner's
  decision.
- No CLAUDE.md §9 violations (a method without `#[Test]` or not `itXxx`) were found in the slice
  at all — every "methods without #[Test]" discrepancy from the initial grep turned out to be a
  method of an anonymous fixture class inside test files, not a test method; re-checked manually
  on 4 files (`FormatterRegistryTest`, `SuppressionCompositionBuilderTest`,

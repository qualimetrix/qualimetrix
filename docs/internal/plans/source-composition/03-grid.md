# Этап 03. Сетка оси C и ревью-гейт

Продукт этапа — число, а не лечение. После него заход останавливается и
спрашивает ревьюеров, прежде чем писать этап 05.

## Что меряется

Произведение «строка реестра трёх форм `composition-*` × тройка `onlyLow /
onlyHigh / both`», на точке `optionsObject`; для пар, чей путь — framework-ключ
(`suppress_paths` и соседние), **обязательна вторая точка** — там, где эти
ключи читают три потребителя, у которых фабрика их вырезает до построения
объекта. Отчёт — третий свидетель там, где путь влияет на находки. Плюс тройки:
`L1 graduated → L2 threshold → L3 graduated`, где наблюдаемое — выживание
слота, который написал только `L1`.

Число сценариев троек знаменатель даёт формулой `C(N+2,3) × 30`. Упражняются
не все: пакет объявляет выборку и её правило — по одной тройке на каждую форму
T1–T4 на каждой из 30 переключаемых групп, с `L3`, пишущим **строго один**
слот пары. Тройка, где `L3` пишет оба слота, зелена по построению (TD3 в
знаменателе) и в выборку не входит; это записывается, а не подразумевается.

## Пол

`floor.tsv` получает строки оси C: те, что стенд **обязан** назвать
дефектными. Кандидаты известны заранее из знаменателя — `T4` (пресет пишет
полосу, `qmx.yaml` пишет `threshold`, CLI пишет полосу) и пара
`#[CliAlias]` против `--rule-opt`, где оба ключа доживают до одного ведра и
отказ приходит от `ThresholdParser`, а не от композиции.

Пол оси C применяется **только к живой сетке**: в X18 пол, применённый к
замороженной половине, требовал от успешного лечения выглядеть провалом.

## Контроли

`promise-effect:controls` получает подсадки: по одной на каждый новый вердикт
(`MISLAYERED`, `LOST_SIBLING`, `COMPOSITION_REFUSED`, `FRANKENSTEIN`) и по
одной на каждую из точек, где вердикт может быть подменён соседним — включая
подмену `FRANKENSTEIN` на `MISLAYERED`, к которой ведёт сравнение целых
текстов вместо листьев. Подсадка, которую не
краснит ни один контроль, — дефект контроля, а не пустой класс.

## Границы притязаний, печатаются вместе с числом

- 5 слотовых пар (`@qmx-threshold` как верхняя сторона) не измерены: другой
  механизм, другой оракул;
- содержимое поставляемых пресетов не читалось: знаменатель утверждает
  способность стадии, а не факт записи;
- тройки при `N ≥ 3` пресетах — формула, выборка;
- дверь `inline` как писатель — вынос захода.

## Definition of Done

1. Сетка оси C построена; число строк равно числу строк трёх форм
   `composition-*` реестра, умноженному на пробу, и расхождение — отказ
   прогона.
2. Число дефектов оси C напечатано по вердиктам; `UNPROMISED` напечатан
   отдельно — он говорит о реестре, а не о продукте.
3. Доля `NOT OBSERVABLE` названа числом, и названо, сколько строк имеют
   закрытые ворота чувствительности. Урок X18: падение доли обычно значит, что
   отказ судится раньше ворот, а не что стенд прозрел. Предъявляется число
   строк с закрытыми воротами, а не доля ячеек.
4. Пол оси C красный до лечения и назван поимённо.
5. Контроли зелены; каждая подсадка краснит **ровно свой** случай.
6. `composer check:artifacts` зелен: сетка — генерируемый артефакт, и этап,
   который её двигает, обязан назвать группу, которую инвалидирует.
7. Отчёт первой строкой: число дефектов оси C и сколько из них `LOST_SIBLING`
   и `FRANKENSTEIN`.

## Гейт

После этапа заход идёт на ревью — native `comprehensive` и внешний `codex`,
с вопросами:

1. какую пару писателей проба композиции не упражняет ни разу;
2. где обещание реестра шире носителя, то есть где ложно-зелёное переехало в
   декларацию;
3. какой из четырёх ремонтов стенда назван правкой классификатора, будучи
   правкой входа;
4. какое утверждение плана о множестве стоит на перечислении, которое
   занижает.

Этап 05 пишется **после** ответов и против измеренной сетки. До гейта в нём
зафиксировано направление и три вопроса ADR 0055 — но не списки файлов.

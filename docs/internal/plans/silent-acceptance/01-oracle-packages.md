## 16. Предусловия, инварианты и калибровка (материал P2 и P3)

### Предусловия фикстур по командам

| команда                               | предусловие фикстуры                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `check`, `directives`, `graph:export` | дерево деклараций с находками нескольких каналов, **в ≥2 неймспейсах и ≥2 классах** (§6: иначе вырезание эха уводит флагманские двери в `NOT OBSERVABLE`) — **и сверх того один неймспейс и один класс без единой находки**: без них `hit_empty` для `--namespace`/`--class` не строится, а с ним не строится и калибровочный случай на нейтральное добавление |
| `baseline:generate/update/cleanup`    | заранее сгенерированный baseline-файл                                                                                                                                                                                                                                                                                                                          |
| `baseline:explain`                    | baseline + канонический ключ субъекта                                                                                                                                                                                                                                                                                                                          |
| `baseline:rename-channels`            | baseline + файл карты                                                                                                                                                                                                                                                                                                                                          |
| `debug:layer-assignment`              | конфиг со слоями и реальным FQCN                                                                                                                                                                                                                                                                                                                               |
| `--report=git:*`                      | настоящий git-репозиторий с двумя коммитами                                                                                                                                                                                                                                                                                                                    |
| `hook:*`                              | вне знаменателя: дверей со значением не имеют, только флаги                                                                                                                                                                                                                                                                                                    |

Ожидаемое попадание/промах для path-дверей объявляется в `probes.tsv` и
проверяется прогоном: `PathMatcher:66` зовёт `fnmatch` без `FNM_PATHNAME`, `*`
пересекает разделители каталогов, и шелловский glob моделью матчера не является.

### Инварианты прогона и перекрываемые ими двери

`--fail-on=none`, `--workers=0`, `--no-cache`, cwd — каталог фикстуры, конфиг —
только явный, код возврата снимается **без пайпа**; инвариантный флаг подаётся,
только если команда его объявляет.

| инвариант стенда           | перекрывает двери                                            |
| -------------------------- | ------------------------------------------------------------ |
| `--fail-on=none`           | `check --fail-on`, конфиг `failOn`                           |
| `--workers=0`              | `check --workers`, конфиг `parallel.workers`                 |
| `--no-cache`               | `check --cache-dir`, конфиг `cache.dir`, `cache.enabled`     |
| `--format=<наблюдаемое>`   | `--format` на пяти командах, `--format-opt`, конфиг `format` |
| явный `--config`           | `--config` на семи командах                                  |
| фиксированная цель прогона | аргумент `paths` каждой команды, конфиг `paths`              |

Дверь со значением в `shadowed_by` прогоняется **без** своего перекрывающего
соседа, и наблюдаемое ей берётся другое.

### Калибровочные случаи классификатора (DoD P3)

Выведены под правило §4 заново. Прежние три эхо-случаев не содержали, поэтому
первый ряд обязателен. Три нижних ряда добавлены второй редакцией и калибруют
сторожей, а не текст.

| случай                                                                                                                                      | обязан дать                                                  | почему                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| Б7/Б8 (`--namespace`, `--class` на промах)                                                                                                  | `SILENT`                                                     | эхо вырезано, сигнал не объявлен — ни `SPEAKS`, ни `NOT OBSERVABLE`                        |
| `--format-opt=violation=2` (диф в 4 строки — timestamp)                                                                                     | `SILENT`                                                     | нормализация плюс отсутствие сигнала                                                       |
| Б №13 (`scoped analysis`-подсказка одинакова на `M` и `H`)                                                                                  | `SIGNAL NOT SPECIFIC` при объявлении этой подсказки сигналом | калибруется **декларация**, а не текст                                                     |
| `baseline:cleanup --remove=<нет>`                                                                                                           | `SPEAKS`                                                     | только при объявленном `stderr:<регекс>`                                                   |
| `--exclude=<нет такого каталога>` при сигнале, выписанном по тексту `M`                                                                     | `SIGNAL NOT SPECIFIC`                                        | `M ≡ A` на оси «больше задуманного»: сторож 1 обязан краснеть по стороне `A`, а не молчать |
| `--namespace` при сигнале `stderr:` / `finding:`, выписанном по `No violations found.`, и `hit_empty` на пустом, но существующем неймспейсе | `SIGNAL NOT SPECIFIC`                                        | нейтральное добавление: строка появляется и на `H₀`                                        |
| `--memory-limit=zzz` (`H` = `512M`, после нормализации `H ≡ A`)                                                                             | `REFUSES`                                                    | отказ решается тройкой кодов возврата и наблюдаемого попадания не требует (§19)            |

**Чем получен набор и чего он не видит.** Выведен из четырёх измеренных способов
ошибиться классификатором (эхо значения, нейтральное добавление, timestamp-диф,
отказ при ненаблюдаемом попадании) плюс один измеренный `SPEAKS`. Не видит:
сигнал вида `finding:` и `exit:`, конфигурационную дверь, нетекстовое
наблюдаемое — последнее закрыто отдельно контролем K14, первые два остаются
непокрытыми калибровкой и названы здесь.

**DoD:**
- Ключ строки — `surface|command|door|site`; строк с `command = (qmx.yaml)`

- В отчёте пакета — строка «чем получено и чего способ не видит» для сетки и

### P2 — декларации пробников, сигналы, фикстуры, supplement

**Зависит от P1.**

**Файлы:** `input-doors/probes.tsv`, `input-doors/cure-sites.tsv`,
`input-doors/command-observables.tsv`, `input-doors/fixtures/**`,
`input-doors/normalization-supplement.tsv`, `input-doors/README.md`.

**Ключ строки пробника — `surface|door|site`, без команды.** Стенд размножает
строку по всем командам, где сетка несёт эту дверь; per-command строка-override
допускается только с причиной. Следствие, которое обязано быть проверено при
заполнении: `miss`/`hit` двери **не зависят от команды** — для конфигурационных
корней это верно по построению (тот же YAML), для шести строк `--rule-opt` — по
тексту SPLIT-вердикта. Дверь, у которой значение промаха командно-зависимо,
получает override со своей причиной. Так рукописного остаётся O(двери + сайты +
13 команд), а не строка на каждую из ~250 строк сетки.

**DoD:**
- У каждой референтной строки сетки есть пробник — свой или полученный
  размножением; число пробников у двери **выводится из её сайтов**, а не из
  константы.
- Ни один override не заведён без причины; в отчёте — их число. Строка
  `cli|--namespace|whole-value` **обязана** нести per-command override для
  `graph:export`: наблюдаемое там граф, а не находки (`01-oracle-mechanics.md` §7).
- У каждого пробника заполнены `miss`, `hit`, `hit_empty`, `observable`,
  `signal`, `echoes`, `fixture`, `shadowed_by`. `signal=none` и `hit_empty=none`
  принимаются только с причиной; пробник без `hit` не заводится.
- `hit_empty` заполнен значением у **каждого** пробника с сигналом `stderr:`,
  `finding:` или `exit:` на оси «меньше задуманного»; `none` с причиной — только
  там, где промах и есть пустое попадание (ось «больше задуманного»), и такие
  двери поимённо перечислены в отчёте как покрываемые сторожем 2.
- **`cure-sites.tsv` несёт ровно 15 строк ключом `surface|command|door|site`**,
  поимённо совпадающих с таблицей `01-oracle-mechanics.md` §7; в отчёте — построчная
  сверка с `02-cure.md` §2 (машинной сверки нет, остаток назван в §7).
- Наблюдаемое шести дверей формы «находка warning» решено **здесь**, а не в
  пакете лечения: `format:json`. Смена наблюдаемого после заморозки краснит
  `BEFORE UNDER OTHER DECLARATION`, поэтому решение не может быть отложено.
- Ни один `signal` вида `finding:<канал>@<формат>` не объявлен над форматом, не
  несущим находок.
- Источник деклараций `signal` назван в отчёте (колонка `verdict` в
  `doors-reconciled.tsv`), вместе с числом дверей, у которых сигнал выведен из
  наблюдения, а не из словаря отказа; **это число гейтящее**: каждая такая дверь
  перечислена поимённо со ссылкой на измерение, иначе пакет не принят.
- Предусловия §16 реализованы, включая настоящий git-репозиторий и фикстуру с
  ≥2 неймспейсами и ≥2 классами.
- Ни один путь фикстуры не указывает на `src/` продукта или на `finding-gate/`.
- `README.md` называет схему строки, список поверхностей, правило токенизации
  путей `<FIXTURE>`/`<REPO>` **с порядком подстановок (длиннейший префикс
  первым) и решением про вложенность фикстур в репозиторий** и **чего supplement
  не покрывает**.
- Supplement несёт строку override-остатка на длительность `format:summary`
  (`01-oracle-mechanics.md` §5) с причиной и ссылкой на измерение §19.

### P3 — стенд, снапшот, заморозка наблюдений

**Зависит от P1 и P2.**

**Файлы:** `scripts/input-doors.php`, `scripts/input-doors/*.php`,
`docs/internal/generated/input-doors/verdicts.tsv`,
`docs/internal/generated/input-doors/observations-before/**`.

**Контракт:**

```php
final class Observation { public int $exit; public string $stdout, $stderr; }  // сырое
final class Probe    { public function observations(): array; }  // M / H / A / H0
final class Verdict  { public const REFUSES, SPEAKS, SILENT, NOT_OBSERVABLE; }
final class Stand {
    public function classify(array $observations, ProbeDeclaration $d): Verdict; // §4, чистая функция
    public function shotFingerprint(ProbeDeclaration $d): string; // поля, определяющие съёмку, + хеш фикстуры
    public function run(): VerdictTable;                 // join сетки x probes
    public function check(string $path): int;            // дрейф против снапшота
    public function freezeBefore(string $dir): int;      // отказ, если каталог есть
    public function refreezeBefore(string $dir, string $reason): int;
    public function stability(): int;                    // повтор M-стороны, UNSTABLE SURFACE
    // ... implementation details
}
```

**DoD:**
- Классификатор даёт исходы таблицы §16 на всех **семи** калибровочных случаях.
- Порядок шагов — как в `01-oracle.md` §4: специфичность и отказ проверяются
  **раньше** наблюдаемости; калибровочный случай `--memory-limit` даёт `REFUSES`,
  а не `NOT OBSERVABLE`.
- Специфичность считается по трём сторонам (`H`, `A`, `H₀`), а не по одной;
  случай `--exclude` из калибровки краснеет именно по стороне `A`.
- Вырезание эха применяется **до** шага наблюдаемости, иначе Б7/Б8 читаются
  наблюдаемыми ошибочно; сопоставляется значение **после** абсолютизации и
  токенизации, а не литерал из декларации; колонка `echoes` проверяется в обе
  стороны (`ECHO NOT FOUND` при обоих расхождениях).
- Нетекстовые наблюдаемые (`exitcode`, `file:`, `dir:`) классифицируются своим
  правилом; в наборе есть хотя бы одна такая дверь с зафиксированным исходом.
- Красные исходы стенда различены и не сливаются с `SILENT`: `NOT PROBED`,
  `STALE PROBE`, `STALE CURE SITE`, `SIGNAL NOT SPECIFIC`,
  `SIGNAL/OBSERVABLE MISMATCH`, `INCOMPLETE TRIPLE`, `ECHO NOT FOUND`,
  `UNSTABLE SURFACE`, `NO BEFORE`, `BEFORE UNDER OTHER DECLARATION`,
  `SPEAKS BEFORE CURE`.
- Пересчёт классификатора над `observations-before/**` даёт по каждой из 15
  строк `cure-sites.tsv` только `SILENT` или `NOT OBSERVABLE`; любой
  `SPEAKS`/`REFUSES` — `SPEAKS BEFORE CURE`, и пакет не принят, пока не назван
  виновник (декларация или состав списка лечимых).
- `--stability` зелёный: у каждого текстового наблюдаемого повтор M-стороны
  нормализуется в тот же текст; `format:summary` под `--namespace` зелен только
  со строкой override-остатка (`01-oracle-mechanics.md` §5), и это проверено снятием
  строки.
- Ноль строк с источником «наследование»; каждая `NOT OBSERVABLE` несёт причину.
- В сводке раздельно: `SILENT (declared none)` и `SILENT (declared, not fired)`;
  доля и абсолютное число `NOT OBSERVABLE` по конфигурационной половине сетки —
  **остаток с числом** (§8), в отчёт пакета.
- Нормализация грузится из `finding-gate/normalization.tsv`; staleness считается
  только по порождённым стендом поверхностям; строка supplement на поверхность
  гейта принимается лишь с `gate_owned=yes`, причиной и ссылкой на измерение и
  печатается отдельной строкой остатка.
- `observations-before/**` снят один раз **до первого пакета лечения**, содержит
  сырые наблюдения `M`/`H`/`A`/`H₀`, **не содержит `/Users` и `/home`**
  (`scripts/check-private-leaks.sh` зелёный); повторный `--freeze-before`
  отказывает, `--refreeze-before` требует причины.
- Рядом с каждым снимком лежит отпечаток полей, определяющих съёмку, и хеш
  содержимого каталога фикстуры; правка `observable`, `miss`, `hit`,
  `hit_empty`, `fixture` или файла фикстуры при сохранённом ключе даёт
  `BEFORE UNDER OTHER DECLARATION`, а не тихий пересчёт. Проверено правкой в обе
  стороны: правка `signal` этого исхода **не** даёт — она пересчитываемая.
- Отчёт пакета сопоставляет сводку с `doors-reconciled.tsv` (сегодня: отказывает
  72, молчит 18, смешанный 9, говорит-не-отказывает 2) и объясняет каждое
  расхождение — с поправкой на то, что часть прежних `SPEAKS` по новому правилу
  законно становится `SILENT`.

**Арифметическая половина** (прецедент `directive-audit-coverage-control.php`,
секунды вместо клонов): снятие объявления кейса обязано оставлять ровно этот
кейс «не охраняемым ничем», а объявленный кейс вне вселенной прогона — отдельным
отказом «устаревшая декларация». Дешёвое идёт первым.

**Место в валидации — по замеру, а не по оценке:**

| измеренное время | место                                                                                                                 |
| ---------------- | --------------------------------------------------------------------------------------------------------------------- |
| ≤ 25 с           | `check:artifacts` (рядом со снапшотом подавлений)                                                                     |
| > 25 с           | отдельная цель вне `composer check` (прецедент `directives:controls`) плюс `input-doors:check` в CI отдельной работой |

Порог 25 с — «не более чем удвоение самой дорогой не-тестовой позиции
`check:artifacts`». Оценка §10 (~200 с) ставит стенд во вторую строку, но решает
замер. **Режим `--stability` размещается тем же правилом и отдельным замером**:
он удваивает M-сторону текстовых наблюдаемых и по оценке §10 в `check:artifacts`
не помещается, но и это решает число, а не оценка.

**DoD:**
- Все кейсы плюс арифметическая половина; **каждый краснит ровно свой**.
- Замер снят трижды, `time`, без пайпа; эффект параллельного запуска измерен, а
  не предположен; выбранное место обосновано числом — **отдельно** для основного
  прогона и для `--stability`.
- Цели `input-doors`, `input-doors:check`, `input-doors:controls`,
  `input-doors:stability` заведены; `input-doors:controls` в `composer check` не
  входит.
- `composer check` зелёный целиком (аргумент приёмки — только агрегат).

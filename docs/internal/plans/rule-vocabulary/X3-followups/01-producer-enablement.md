# Пакет A — вердикт директивы на выключенном правиле

Третья редакция. Первые две выводили включённость **снаружи** исполнения, и
каждый раунд ревью находил новый вход, на котором вывод неверен: сначала
гранулярность продюсера вместо уровня и пересборка опций фабрикой с побочными
эффектами, затем — перечисление, не покрывающее шесть имён, пустое пересечение
уровней, дающее «выключен» по пустой истине, и два несогласованных авторитета
уровней. Дефекты разные, способ реализации один. Эта редакция меняет способ:
исполнение **записывает** своё решение, аудит его читает.

Что именно опровергнуто в первых двух — в разделе «Чего стоили первые две
редакции», чтобы следующий читатель не восстановил их из общих соображений.

## Дефект, измеренный

Стенд: класс с методом CCN 4 и директивой
`@qmx-threshold complexity.cyclomatic warning=1 error=2` на нём.

| конфигурация правила                               | вердикт                                                         | код возврата |
| -------------------------------------------------- | --------------------------------------------------------------- | ------------ |
| `enabled: false` (плоско)                          | `unmeasured: the producer of the addressed channel did not run` | 0            |
| `callable.enabled: false` + `class.enabled: false` | `inert: removing it changes nothing`                            | **2**        |
| `callable.enabled: false`, `class.enabled: true`   | `inert: removing it changes nothing`                            | **2**        |

Первая строка — верный ответ, вторая и третья — нет: правило не работало на том
уровне, к которому директива привязана, причина в конфигурации, а не в директиве,
и код `2` требует от автора снять живую директиву.

## Решение: исполнение записывает, аудит читает

`RuleExecution::execute()` уже владеет всем, что нужно для ответа: экземплярами
правил, их опциями и обоими множествами имён — правил с классом и продюсеров без
класса (`allProducers()` строит из них те же 51 имя, что публикует `allRules()`).
Оно же — единственное место, где решение о работе принимается на самом деле.

- `RuleExecutionResult` получает **снимок активности**: для каждого продюсера и
  каждого уровня, который этот продюсер объявляет, — работал он или был выключен
  конфигурацией.
- Снимок строится опросом самих правил. `AbstractRule` отвечает один раз за все
  45 классов (измерено: не наследует его ноль), `ComputedMetricRule`
  переопределяет ответ за свои шесть продюсеров, потому что их включённость
  решает `ComputedMetricProducerOptions::isEnabledFor()`.
- Оба потребителя аудита читают снимок вместо
  `RuleConfigurationInterface::isRuleDisabledByOptions()`, которая **удаляется**.

Порядок вычислений это допускает и проверен по коду: `UnusedDirectiveRule::analyze()`
ничего не считает — только включает отчётность через `enableUsageReporting()`, — а
сам аудит выполняется в `AnalysisPipeline` после исполнения, уже имея
`RuleExecutionResult` (`AnalysisPipeline.php:129`, `:344`).

### Что снимок делает невозможным

| дефект, найденный ревью                                 | почему в этой редакции его нет                                                                                       |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| перечисление не покрывает шесть `health.*`              | множество имён — то же, что у `allProducers()`, и берётся не копией, а тем же кодом                                  |
| два авторитета уровней (опции против объявления канала) | авторитет один — правило; согласие с объявлением канала проверяется стражем при построении снимка                    |
| пустое пересечение уровней даёт «выключен»              | пары «продюсер × уровень» не существует, если продюсер этот уровень не объявляет, и её отсутствие — не выключенность |
| пересборка опций фабрикой с побочными эффектами         | опции не строятся: спрашивается объект, который уже у правила                                                        |
| цикл DI при доступе к `RuleExecution`                   | передаются данные, а не сервис                                                                                       |
| «опции строятся один раз» неверно                       | посылка больше не нужна                                                                                              |

### Ответ аудита

```
verdictInput(producerName, level):
    activity = executionResult.levelActivity
    if not activity.declares(producerName, level):  return NotADisablement
    return activity.ran(producerName, level) ? NotDisabled : Disabled
    // ... implementation details
```

Три исхода, а не два: «не объявляет этот уровень» — не выключенность, и вердикт
для такой директивы остаётся тем, чем был (`Inert` либо ответ адресуемости).
Именно на этом входе вторая редакция врала: `@qmx-threshold coupling.cbo` на
методе давал «выключен» по пустой истине.

### Уровень директивы

Отдельной таблицы соответствий не требуется, и шаг A0 первых редакций отменён —
измерено, что перечислять нечего:

- `SuppressionFilter::applies()` связывает символьную директиву с находкой
  **строгим равенством субъектов**, а раскрытие охвата на содержащиеся
  объявления происходит раньше, в `FileProcessor`. К моменту аудита каждая
  привязка имеет ровно один точный субъект;
- уровень субъекта даёт существующая тотальная проекция
  `SymbolLevelProjection::ofDeclaration($subject->toSymbolPath()->getType())` —
  тот же вызов, которым `Finding::level()` определяет уровень находки, то есть
  не копия;
- у авторской группы привязок может быть несколько, поэтому уровни группы — это
  множество уровней её привязок, а не уровень первой из них.

Два факта про формы директив, снятые исполнением продукта:

- `@qmx-threshold complexity.cyclomatic:callable` продукт **отвергает**
  (`annotation.unresolved-directive`, «a threshold addresses the producing
  rule»), то есть у пороговой директивы своего суффикса уровня нет;
- у подавления форма `channel:level` законна (`Suppression::matches()`), и когда
  автор её написал, уровень группы задаёт она, а не привязка. Это отдельный вход
  ключа, и он назван здесь, потому что первые две редакции его теряли.

### Контракты

```php
// Правило отвечает за себя. Реализация по умолчанию — в AbstractRule.
interface ...  // носитель решается при реализации: RuleInterface или отдельный
{
    /**
     * Работал ли каждый объявленный уровень каждого продюсера этого правила.
     *
     * @return array<string, array<string, bool>> producer => level->value => ran
     */
    public function levelActivity(): array;
}
```

`RuleExecutionResult` получает поле снимка. Из `RuleConfigurationInterface`
уходит:

```php
public function isRuleDisabledByOptions(string $ruleName): bool;   // удаляется
```

## Перечисление продюсеров

`enumeration-producer-enablement.tsv` (51 строка), снято
`enumeration-producer-enablement.php` по живому контейнеру.

| величина                                          | значение                                    |
| ------------------------------------------------- | ------------------------------------------- |
| имён-продюсеров                                   | 51                                          |
| классов правил в реестре                          | 45                                          |
| классов правил, не наследующих `AbstractRule`     | **0**                                       |
| плоских / иерархических опций                     | 46 / 5                                      |
| продюсеров без собственного класса                | 6 (`health.*`, хост — `ComputedMetricRule`) |
| строк, где столбец `isEnabled_sites` равен `NONE` | 6 — те же шесть `health.*`                  |

Шесть `NONE` — не пробел: у этих имён нет своего класса, токенизатору нечего было
читать; их включённость решает хост. Первая редакция писала здесь «0», противореча
собственному артефакту.

Иерархические пять: `complexity.cognitive`, `complexity.cyclomatic`,
`complexity.npath`, `coupling.cbo`, `coupling.instability`.

**Чем получено и чего этот способ не видит.** Имена и классы опций — из живого
контейнера (`RuleExecutionInterface::allRules()`, `RuleRegistryInterface::getClasses()`),
наследование — рефлексией, места обращения к включённости — токенизатором по
цепочке наследования внутри `src/`. Способ **не видит**: обращение из
коллаборатора, не являющегося предком правила; динамическую диспетчеризацию;
включённость, вычисляемую в обход объекта опций. Третье слепое пятно сработало —
см. краевой случай 2. Первая редакция искала точный идентификатор `isEnabled` и
объявила семь правил «никогда не спрашивающими», потому что семейство computed
зовёт `isEnabledFor`. В этой редакции утверждение о множестве сужено до того, что
перечислимо механически: снимок строит тот же код, что и `allProducers()`, а
согласие с объявлениями каналов проверяется стражем.

## Краевые случаи

1. **Продюсер не объявляет уровень директивы.** Сам по себе это не
   выключенность, и пока продюсер жив, вердикт остаётся прежним: вход
   `@qmx-threshold coupling.cbo` на методе даёт `inert`, а не `ProducerDisabled`
   по пустой истине — это и есть дефект второй редакции. Если же все уровни,
   которые продюсер объявляет, выключены, ответ становится «не работал», и это
   верно: порог адресует правило, а правило не работало. Обе ветки измерены.
2. **У семейства computed есть второй путь выключения, и отвечать на него не
   надо.** Секция `computed_metrics` (и `--exclude-health`) снимает определение
   из каталога до всякого объекта опций. Ревью предсказало здесь `Inert` и
   красный CI; **измерено — предсказание неверно**:

| вход                                                                                    | вердикт                                                   | код |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------- | --- |
| `computed_metrics: {health.cohesion: {enabled: false}}` + `@qmx-ignore health.cohesion` | `unmeasured` (отвечает `annotation.unresolved-directive`) | 0   |
| пользовательская `computed.branch-load` с `enabled: false` + `@qmx-ignore` на неё       | `unmeasured`                                              | 0   |
| те же входы с включённой метрикой (контроль)                                            | `effective`                                               | 0   |

   Выключение убирает канал из вселенной, и адресуемость отвечает раньше. Снимок
   на этот путь не отвечает намеренно: вторая жалоба судила бы одну ошибку дважды.
3. **`rulePattern` — не образец.** Поле названо `rulePattern`, но
   `ThresholdOverride::matches()` сравнивает строгим равенством, а докблок поля
   говорит «exact rule name».
4. **Две вселенные имён.** Пороговый потребитель адресует **правило**, потребитель
   подавлений — **продюсера канала** через `producerOf($code)`. Снимок ключуется
   именами продюсеров, и для всех правил, кроме computed-хоста, это одно и то же
   имя. Различие названо в контракте, а не оставлено читателю.
5. **Узкий свип.** `ThresholdDirectiveAudit` строит контрфактические прогоны;
   каждый возвращает свой `RuleExecutionResult` со своим снимком. Снимок
   контрфактического прогона относится к нему, а не к базовому, и путать их
   нельзя — проверяется тестом.

## Тестовый план

- **Согласие двух объявлений.** Для каждого продюсера уровни снимка совпадают с
  уровнями, объявленными его каналами (`ChannelDeclaration::levels`). Это тот
  самый конфликт авторитетов, который ревью нашло неотслеживаемым; здесь он
  становится проверяемым, а не предполагаемым.
- **Поведенческие, сквозь продукт.** Три строки таблицы «Дефект, измеренный»
  становятся кейсами: полное выключение → как сегодня; оба частичных →
  `unmeasured / ProducerDisabled` и код 0. Правило, проверяемое подставленным
  состоянием, не проверяется вовсе.
- **Иерархические поимённо, все пять** — источник списка TSV: каждый уровень по
  отдельности и оба сразу.
- **Плоские:** `enabled: false` и скалярное `false` — регрессия сегодняшнего
  поведения.
- **Computed:** выключение одного `health.*` через `rules:` не выключает соседей;
  выключение через `computed_metrics:` даёт `unmeasured` **не** через снимок.
- **Третий исход:** `@qmx-threshold coupling.cbo` на методе не становится
  `ProducerDisabled`.
- **Проверка самой проверки:** с откаченным исправлением обязаны краснеть
  поведенческие кейсы частичного выключения; снимается поштучно. Отдельно:
  мутация «снимок строится по конфигурации, а не опросом правил» обязана краснить
  страж согласия. Мутации «снимок берётся от базового прогона внутри узкого
  свипа» **не существует**: контрфактический прогон возвращает свой результат,
  и его снимок никем не читается — аудит берёт снимок базового прогона по
  построению. Пункт снят, а не отложен.

## Definition of Done

1. `composer cs-check`.
2. `composer phpstan` — уровень 8, покрывает и `scripts/`.
3. `composer test` — в отчёте называется **число исполненных тестов**.
4. Декларации манифеста правятся руками (новый тип, новые потребители, снятие
   записей об удалённой операции), затем `composer architecture:generate`.
5. Новый путь получает пробу в `scripts/directive-audit-controls/Probes.php`, и
   `composer directives:controls` краснеет на ней.
6. README: `src/Analysis/Finding/README.md` (снимок и его контракт),
   `src/Analysis/Policy/Inline/README.md` (что читает аудит вместо удалённой
   операции).
7. `composer check` целиком, с
   `QMX_MKDOCS=<основной checkout>/website/.venv/bin/mkdocs`.
8. `composer gate -- --reference=38ad58e9` — GREEN. **Чем является и чем не
   является:** вывод команды `directives` в сравниваемые поверхности гейта не
   входит, поэтому гейт свидетельствует «ничто другое не сдвинулось», а не
   «исправление работает». Свидетель исправления — поведенческие тесты и стенд.
9. `FOLLOWUPS.md`: запись про `isRuleDisabledByOptions()` закрывается; частичное
   выключение называется отдельно, потому что записью не покрывалось; отсутствие
   `directives` среди поверхностей гейта заводится записью.
10. `CHANGELOG.md`: запись `Fixed`. **Не `Breaking`:** удаляемая операция
    принадлежит внутреннему контракту, который политика обратной совместимости к
    внешней поверхности не относит.

Пакет не объявляется готовым по зелени одной группы: свидетельство — только
агрегат.

## Чего стоили первые две редакции

Два раунда, четыре ревьюера, 32 находки, из них по существу дизайна семь — и все
про решения планировщика, ни одной про исполнение:

- ответ давался с гранулярностью продюсера, а дефект имеет гранулярность уровня
  (найдено дважды независимо). Усугубляющий факт: агрегатный `isEnabled()` у всех
  пяти иерархических опций не вызывается сегодня ниоткуда в продакшене;
- опции строились фабрикой с побочными эффектами при готовых экземплярах рядом
  (найдено дважды);
- сводная таблица противоречила собственному артефакту (найдено трижды);
- страж дрейфа был тавтологичен (найдено дважды);
- перечисление 51 имени опиралось на пасс, который знает 45, при существующем в
  дереве механизме, который знает 51;
- пустое пересечение уровней давало «выключен» по пустой истине;
- уровни выводились из одного канала, самого широкого, при трёх существующих.

Опровергнута измерением одна находка — предсказание `Inert` и красного CI на
втором пути выключения computed: механизм назван верно, следствие нет.

**Правило, которое стоит унести дальше.** Три из семи дефектов дизайна порождены
одним способом — выводом факта об исполнении снаружи исполнения. Пока способ не
сменился, каждый раунд находил новый вход; смена способа закрыла шесть из семи
разом.

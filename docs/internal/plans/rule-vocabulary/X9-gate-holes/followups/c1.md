# Запись для FOLLOWUPS.md — пакет C1 захода Х9

## Х9 (2026-09-05) — ключ метрики внутри строки языка выражений

Слепое пятно словарного аудита «`ComputedMetricFormulaValidator` сверяет
`health.*`/`computed.*` ссылки друг с другом, но не проверяет каталожность
остальных ключей формулы» закрыто пятой проверкой валидатора.

- **Реализация:** `ComputedMetricFormulaValidator::validate()` получил
  `validateMetricKeyExistence()` — для каждой формулы каждого определения
  берёт все ключи через уже существующий AST-обход
  (`ComputedMetricExpression::keysOf()`), пропускает `health.*`/`computed.*`
  (владение — четвёртая проверка, `validateComputedMetricReferences()`) и для
  остальных проверяет каталог. Отказ называет метрику, ключ и формулу:
  `Computed metric "%s" references unknown metric key "%s" in formula: %s`.
  Каталог читается через `ReflectionClass(MetricName::class)` (кешируется в
  статическом свойстве), не хранится отдельным списком строкой в коде —
  дрейфовать от `MetricName` ему нечем. Отдельный файл-сосед не понадобился:
  reflection-хелпер остался приватным методом валидатора, чтобы не заводить
  производственный класс ради шести строк и не тянуть за собой перегенерацию
  манифеста/`qmx.yaml` (первая же попытка вынести каталог в
  `ComputedMetricKeyCatalog.php` дала `architecture.coverage`-отказ:
  `qmx.yaml` перечисляет классы предмета поимённо, не паттерном, и любой
  новый файл требует перегенерации `docs/internal/generated/modular-architecture/`
  — операция за пределами набора файлов C1).
- **Суффиксы агрегации** читаются не строкой плана, а через
  `MetricName::base()` — тот уже decompose'ит ключ по
  `AggregationStrategy::tryFrom()`, и пятая проверка переиспользует его,
  а не заводит вторую копию списка суффиксов.
- **Таблица популяции** (`X9-gate-holes/enumeration-c1-catalog.tsv`):
  публикуемая вселенная снята заново, своим читателем — `bin/qmx check src
  --format=metrics --workers=0` по всему `src/`, а не текстовым grep
  `scripts/finding-gate/MetricVocabulary.php` (тот способ дал разрыв 71/82
  на измерении 2026-08-26). 294 различимые опубликованные строки → 82 базовых
  ключа после снятия суффикса агрегации (суффикс — только когда он реальное
  значение `AggregationStrategy::cases()`); из них 6 — `health.*`
  (не в предмете этой проверки, остаётся 76). Каталог — 82 константы
  `MetricName.php`, снятые reflection'ом, а не тем же текстовым regex, что
  `MetricVocabulary.php` (иначе измерение и то, что оно проверяет, разделяли
  бы слепое пятно). **Разрыв (опубликованный небазовый ключ без константы) —
  пуст**: все 76 нашли константу. Шесть констант без строки в «published» —
  не разрыв в другую сторону, а условные ключи (`code-smell.unreachable-
  code.first-line`, три `code-smell.unused-private.*`, два `security.*`),
  которые этот конкретный прогон `src/` не поднял ни разу; таблица называет
  это прямо в шапке «чего не видит». Поскольку разрыв пуст, каталог пятой
  проверки — это `MetricName`, как и предписывал пакет на такой случай, а не
  более широкая переизданная вселенная.
- **Один путь, доказано исполнением:** `ComputedMetricsConfigResolver::resolve()`
  сливает встроенные определения (`ComputedMetricDefaults::getDefaults()`) с
  пользовательскими `computed_metrics:` в один список и один раз вызывает
  `$this->formulaValidator->validate($result)` — вторых путей нет. Тест
  `itAppliesTheCatalogCheckToAnOverriddenBuiltInFormulaTheSameWayAsAUserFormula`
  подменяет формулу встроенного `health.complexity` на опечатку и получает
  тот же отказ, что и на пользовательской формуле — доказательство
  исполнением, не чтением кода.
- **Тесты** (`tests/Analysis/Evidence/ComputedMetrics/Unit/ComputedMetricsConfigResolverTest.php`,
  файл уже покрывал валидатор через `#[CoversClass(ComputedMetricFormulaValidator::class)]`
  — отдельного файла для класса не заводилось): валидный каталожный ключ
  проходит, опечатка отказывает с именем, `health.*`/`computed.*`
  cross-reference не задет пятой проверкой, известный агрегатный суффикс
  принимается, неизвестный суффикс отказывает, встроенная формула идёт через
  ту же проверку, что пользовательская. Кейс «ключ из хвоста таблицы,
  не-константный» не заведён — разрыв пуст, предпосылки для него нет.
- **Докблок `JudgedMetricDeclarationGuard.php` п.6:** формулировка «no
  build-time pass can see its keys at all» осталась правдой без правки — п.6
  описывает build-time compiler pass над объявлениями каналов; новая
  пятая проверка исполняется в рантайме (`resolve()` вызывается из
  конфигурационного пайплайна, не из DI-компиляции), так что build-time
  проходов, видящих ключи computed-metric формул, по-прежнему нет.
- **Граница:** новый отказ на невалидный вход — раньше опечатка в ключе тихо
  давала `null`/несуществующее значение при вычислении формулы, теперь
  формула с такой опечаткой не резолвится вовсе. Корпус гейта держит только
  валидные формулы, так что для гейта это изменение невидимо; фиксируется
  здесь, а не как `CHANGELOG`-сюрприз.

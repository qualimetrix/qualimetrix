# Х10 — заморозка дискриминатора и перенос baseline по карте

Заход Х10 словарного направления. Ветка `claude/x10-execution` от свежего
`main` (`01f02856`, PR #53). Канон предмета — переписанный Х9 раздел П1/П2
файла `../X8-one-string-two-jobs/04-final-naming-step.md`; хвосты Х9 — раздел
«Х9» в `../FOLLOWUPS.md`, два пункта пакета «.sum» — в `../AUDIT.md`.

## Цель

1. **П1-заморозка.** Отвязать `OccurrenceKey::semantic()`-дискриминатор от кода
   канала в тех шести семействах, где сегодня он буквально код канала. После
   заморозки будущее переименование канала не двигает `occurrence`, и перенос
   принятой записи вырождается в подмену поля `channel`.
2. **П2.** Дать продукту пятую команду `baseline:*`, переписывающую поле
   `channel` записей baseline по объявленной карте `старое → новое`, без
   прогона анализа. Она обязана отказывать на чужом формате/версии и на карте
   с коллизиями.
3. **Пакет «.sum».** Закрыть два соседних пункта AUDIT: контрактный тест, что
   `ClassCountRule` читает агрегатный ключ, и запись про атрибуцию
   `NamespaceMetricContributions`. **Второй пункт закрывается измерением, а не
   правкой:** ревью плана и независимое повторение оркестратором показали, что
   многоблочный файл `.sum` не раздувает — предписанное лечение опровергнуто
   до начала работ (`03-namespace-sum.md`).
4. **Релиз.** П2 обязан выйти релизом **раньше** П4; значит заход завершается
   выпуском версии.

**Вне объёма, категорически:** П3 (ADR окончательных имён) и П4 (само
переименование). Таблица открытых вопросов имени в 04-файле снимается заново в
том заходе, не в этом. Также не чинится слепота `size.class-count` к нелистовым
неймспейсам (AUDIT, запись 2026-08-31) — продуктовый шаг с калибровкой,
отдельное решение владельца.

## Сквозной оракул захода

`composer gate -- --reference=main` **GREEN на пустых картах** после каждого
пакета, а не только в конце. Ни одна работа Х10 не должна двигать
опубликованное: заморозка равна сегодняшнему написанию, `.sum`-починка не
задевает однонамспейсовый корпус, новая команда в сравниваемые поверхности не
входит. **Любая дельта — стоп и диагностика, а не повод объявить строку в
`maps/`.**

Ограничение оракула названо вслух: он доказывает только инвариант (i)
(«заморозка не двигает сегодняшних хешей»). Инвариант (ii) («occurrence не
двигается при переименовании канала») тождественным прогоном недоказуем по
построению — дерево без переименования зелёное при любом устройстве `kind`,
в том числе до заморозки. Инвариант (ii) доказывает только мутационная проба
пакета B, и подменять одно другим запрещено.

## Что известно по коду до плана (проверено, а не унаследовано)

**Восемь вызовов `OccurrenceKey::semantic()`** — перечисление полно **по
построению**: конструктор `OccurrenceKey` приватный, `semantic()` — его
единственная фабрика, поэтому grep по имени фабрики покрывает все каналы
создания. Чем получено: `grep -rn "OccurrenceKey::semantic" src/`. Чего способ
не видит: вызовы в `tests/` (в предмет не входят — они не публикуют записей
baseline) и гипотетический вызов через `callable`-строку (в дереве таких нет,
проверено тем же grep по имени метода).

| вызов                                                             | `kind` сегодня    | заморозке подлежит  |
| ----------------------------------------------------------------- | ----------------- | ------------------- |
| `Evidence/CircularDependency/CircularDependencyRule.php:108`      | `self::NAME`      | да                  |
| `Evidence/CodeSmell/IdenticalSubExpressionRule.php:103`           | `self::NAME`      | да                  |
| `Evidence/Duplication/CodeDuplicationRule.php:138`                | `self::NAME`      | да                  |
| `Evidence/Security/HardcodedCredentialsRule.php:106`              | `self::NAME`      | да                  |
| `Evidence/Security/SensitiveParameterRule.php:106`                | `self::NAME`      | да                  |
| `Policy/Architecture/LayerViolation/LayerViolationFinding.php:92` | `$this->ruleName` | да                  |
| `Evidence/CodeSmell/CodeSmellFinding.php:57`                      | `$smellType`      | нет — уже отдельный |
| `Evidence/Security/SecurityPatternFinding.php:55`                 | `$patternType`    | нет — уже отдельный |

`LayerViolationFinding` строится **из одного места** —
`LayerViolationRule.php:142` (`grep -rn "new LayerViolationFinding"`), поэтому
заморозка этого семейства — одна константа, а не набор по числу продюсеров.
`CircularDependencyRule::NAME` — не литерал, а `PRODUCER_RULE_NAME` чужого
интерфейса; константа заморозки обязана быть **литералом сегодняшнего
значения**, иначе она не отвязана.

**Baseline.** Текущая версия — `Baseline::VERSION = 13`
(`src/Analysis/Policy/Baseline/Baseline.php:31`). `BaselineLoader` отказывает
версиям 5, 10, 11 и 12 поимённо (`REJECTED_VERSION_REASONS`) и **не отказывает
на невалидной записи**: она становится `InertBaselineEntry` (ADR 0017). Это
центральная развилка П2 — см. `02-baseline-channel-carry.md`. Имя
`baseline:migrate` **занято отказом**: команда снята, и
`tests/Analysis/Policy/Baseline/Functional/BaselineMigrateCommandTest.php`
утверждает её отсутствие; переиспользовать имя нельзя.
`BaselineMigrator`/`V5*` — живые классы без команды; **это не предмет Х10**,
называется владельцу отдельной строкой FOLLOWUPS.

**Формат карты.** `finding-gate/maps/channels.tsv` — три колонки
`old<TAB>new<TAB>reason`, сегодня только шапка. Классы гейта живут в `scripts/`
под namespace `QmxFindingGate` и производственным автолоадом не видны, поэтому
«одна строка кормит гейт и перенос» — намерение канона, а не проверяемое в Х10
утверждение: проверяется совпадение **формата**, пиннутое общим корпусом строк
(см. `02-baseline-channel-carry.md`).

## Каскады приёмки, которые заход обязан заложить заранее

Ловятся `composer check`, но дешевле знать до пакета:

- **Классификатор документации пофайловый и видит неотслеженное.**
  `documentationInventory()` перечисляет `.md` через
  `git ls-files --cached --others --exclude-standard`, поэтому даже
  незакоммиченный файл плана краснит `composer architecture:check` **сразу**
  (проверено: на этой ветке он красный уже от файлов плана). Отсюда жёсткий
  порядок: строки классификатора — **первый коммит захода**, и в них заранее
  объявлены все `followups/a.md`…`d.md` и таблицы перечислений, которые пакеты
  только напишут. На этапе E остаётся сверка, а не заведение.
- **Тесты Baseline держит пиннутый вручную дайджест.**
  `P6_C_BASELINE_PATHS_SHA256` в
  `scripts/generate-modular-architecture-test-inventory.php` — ревью-решение, а
  не производный артефакт; первый новый тест пакета C роняет `check:artifacts`.
  Пересчёт — отдельный шаг пакета C. Тесты пакета D под `Measurement/` идут по
  префиксному правилу `P7_MEASUREMENT_PATHS` и такого барьера не имеют.
- **`enumeration-renames.tsv`** протухает от любого движения литералов —
  шесть новых констант заморозки его двигают. Перегенерация — у оркестратора,
  по одной, без удивления.
- **`enumeration-threshold-directives.tsv`** протухает от правки текста
  директив (лечится `--write`); снимок подавлений — от движения подавленных.
- **Пороги `class-rank` масштабируются числом классов дерева.** Заморозка
  добавляет константы **внутрь существующих классов** (новых файлов нет) —
  значит её вклад нулевой; новые классы приносит только П2. Маржа `MetricName`
  тонкая (2.2%), поэтому перемер обеих директив — последним пакетом (E), как E1
  в Х9.
- **Правка аудита директив** тянет `directives:controls` и коверidж-арифметику:
  новые data set'ы требуют объявлений в `Probes.php`. Ожидается, если пакет C
  добавит запретную/функциональную директиву.

## Ратчет

Перегенерация `qmx-baseline.json` **запрещена**. Если новый код приносит
принимаемый warning — рукописная точечная запись с контрфактическим
`composer selfcheck` (зелёный на N, красный на N−1); мёртвые записи снимаются
`baseline:cleanup` с построчным дифом в отчёте. Предпочтение — рефакторинг, а
не запись (правило догфудинга).

## Правила исполнения

Пакеты исполняются агентами, оркестратор сводит. Агенты **не коммитят** и
**не редактируют** `FOLLOWUPS.md`/`AUDIT.md`: текст пакета кладётся в
`X10-freeze-and-carry/followups/<пакет>.md`, сведение — коммиты оркестратора.
Полные прогоны (`composer check`, гейт, `selfcheck`, `directives:*`) — только у
оркестратора, включая прогоны из DoD пакетов.

## Definition of Done захода

- Шесть дискриминаторов заморожены; инвариант (i) доказан тождественным гейтом,
  инвариант (ii) — мутационной пробой с контрфактикой на `main`.
- Пины `occurrence` идут через производственный путь и покрывают восемь
  семейств — либо шесть, с явной строкой FOLLOWUPS про два оставшихся.
- Пятая команда `baseline:*` выпущена; отказывает на чужой версии, на карте с
  коллизиями и на коллизии идентичности с содержимым файла; инертные записи
  переносит, а не удаляет и не делает поводом для отказа; проверена на реальном
  чужом baseline.
- D1 закрыт юнитом; запись AUDIT про атрибуцию закрыта измерением (или, если
  перечисление вскрыло воспроизводимый случай, — воспроизведена, починена и
  покрыта фикстурой).
- `composer check` зелёный; `composer gate -- --reference=main` GREEN на пустых
  картах; два раунда ревью исполнения.
- Релиз выпущен по процедуре CLAUDE.md, CI на теге зелёный.

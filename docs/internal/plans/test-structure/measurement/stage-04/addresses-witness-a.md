## 3. Method and blind spots

**Tool for pass 1 (taxonomy re-verification):** manual re-read of `addresses-to-edit.md`, cross-checked against the live file/line via `sed -n`/`grep -n` for each carrier, and against `relocation-map.csv` via ad-hoc Python one-liners (row filters, `dirname()` set diff, FQCN construction) run through Bash.

**Tool for pass 2 (fresh sweep):** a Python-generated list of the 114 `current` paths, then:
- `grep -rFn` for each file's basename across `git ls-files` output, filtered to tracked files only (explicitly excluding `.claude/worktrees/*`, which are untracked sibling checkouts and would have produced ~2900 false hits if not excluded — caught and corrected mid-run).
- `grep -rFn 'use <FQCN>;'` for the exact old FQCN of every one of the 114 files, fixed-string matched (backslash escaping breaks a bare regex `grep`, corrected mid-run) — this is what found both cross-file `use` clusters.
- A manual read of `classifyOwner()`, `dispositionFor()`, `targetPath()`, `testSuitePrefixTable()`, `currentSuite()`, `assertPathLiteralsResolve()`, and every `const P*_..._PATHS` array in the generator script, tracing each of the 114 target paths through the control flow by hand.
- A `dirname()`-based diff of "directories the CSV targets require" against "directories `phpunit.xml.dist` already declares."

**Channels this method covers:** literal path strings (grep), `use` imports (grep on the exact FQCN), directory-prefix classification logic (manual trace), and generated-artifact freshness (`grep -c` against the tracked TSV/TXT).

**Channels this method does NOT cover — named as uncovered, not asserted clean:**
- **Reflection / dynamic class-name construction.** A `sprintf('Qualimetrix\\Tests\\%s\\...', $subject)`-style dynamic FQCN, or a `class_exists()`/`::class` built from a variable, would not be caught by the fixed-string `use` grep. Not swept separately.
- **Config/YAML/JSON data referencing test paths.** Only `.tsv`/`.txt`/`.neon`/`.dist` were included in one grep pass; `.yml`/`.json` fixtures that might embed a test-tree path as data (e.g. a recorded fixture path inside a JSON test fixture) were not separately swept.
- **PHPStan baseline / ignore lists.** `phpstan.neon`'s `ignoreErrors` could pin a path+line inside one of the 114 files; not checked — a moved+renamed file's baseline entries would go stale silently if PHPStan baselines exist for test code (checked only the two fixture-path lines the stage-03 table already named, `:22` and `:34`, which are for the *TestSupport/ArchitectureStaticAnalysis* subject, not this CSV's subject).
- **Composer scripts / CI YAML referencing an exact test path** (as opposed to a suite name or `composer test` invocation) — not swept beyond the two composer-script/TSV-count checks already covered by taxonomy addresses 39/42's shared carrier.
- **Test attributes that name a class by string rather than `::class`** (e.g. `#[CoversClass('Qualimetrix\...')]` with a string literal instead of a class-constant) — not distinguished from `::class`-based attributes in this pass; if any of the 114 files' consumers use the string form, my `use`-statement grep would still catch the accompanying `use`, but a docblock-only `@covers ClassName` by short name was not separately checked.
- **External consumers.** Nothing outside this repository was checked (n/a for a private test-tree reorg, but named per the checklist).
- **`docs/internal/generated/modular-architecture/production-*.tsv` files** — only `test-ownership.tsv` and `test-phpunit-discovery.txt` were grepped for hit counts; the production-side generated artifacts were not individually re-derived to confirm they don't also reference a test-tree path (unlikely by construction, since they describe `src/`, but not independently verified).
- **A second, independent witness for the same evidence** (per this repository's own `two_witness_enumeration` lesson): this report is witness A alone; witness B's independent method is expected to catch what a code-flow trace like mine structurally cannot (e.g., a reference this method's specific greps happened not to construct).

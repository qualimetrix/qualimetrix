# Аудит тестов — срез `tests/Analysis/Finding/` (84 файла)

Read-only аудит. Ничего в репозитории не менялось; `composer`/PHPUnit/`bin/qmx`/git-команды,
меняющие состояние, не запускались. Работа выполнена по подкаталогам (Unit — 4 группы через
параллельные суб-агенты и напрямую, Integration и RuleConfiguration — отдельными группами), каждый
файл прочитан целиком и сверен с соответствующим кодом `src/` через `grep`/чтение.

84 файла = 62 unit-теста + 15 integration-тестов (Integration, первая половина) + 12
integration/control-тестов (Integration, вторая половина) + 3 RuleConfiguration/Unit-теста + 4
Support-файла (не тесты). Таблица ниже содержит ровно 84 строки.

- `Integration/OccurrenceLeafFreezeGuardTest.php` — то же плюс сверка с генерируемым артефактом (control-invariant).
- `Integration/RuleDocsPageCoverageTest.php` — сверка `DOCS_PAGE`-констант с `website/docs/**`.
- `Integration/RuleIdentifierLiteralGuardTest.php` — крупнейший скан среза (654 строки), literal-охота по всему src/ (control-invariant).
- `Integration/RuleRemediationMinutesCoverageTest.php` (3 из 4 тестов) — сверка `REMEDIATION_MINUTES` с docs (EN+RU).
- `Integration/ThresholdOverrideOwnRuleNameGuardTest.php` — AST/текст-скан src/ на чтение чужого threshold-override (1105 строк, control-invariant).
- `RuleConfiguration/Unit/DeclaredOptionKeysCoverReadKeysTest.php` — AST-оракул полноты декларации ключей (control-invariant).
- `RuleConfiguration/Unit/RuleOptionKeyDeclarationCoverageTest.php` — php-parser обход src/+tests/ ради инварианта популяции (control-invariant).
- `Unit/Exclusion/ConfiguredSuppressionTest.php` (последний тест) — control-invariant внутри иначе чистого unit-файла.

Пограничные (integration, а не control, но с той же по масштабу поголовной проверкой):
`Unit/ThresholdValidatorAssignmentTest.php`, `Integration/LevelActivityCoversEveryDeclaredLevelTest.php`,
`Integration/WarningBoundaryDeclarationTest.php` — все три гоняют реальный рантайм (не текст/AST), но
обходят ВСЮ популяцию классов через реестр/рефлексию. Формально это control-invariant-подвид («инвариант
снимается со всех классов src/ рефлексией»), но по содержанию — поведенческая регрессия, а не проверка
раскладки. Решение о переклассификации — за владельцем.

## Дубли и противоречия

1. **`FindingTest.php`: пять тестов-близнецов фингерпринта.** `itGetFingerprintFor{Method,Class,Namespace,File,GlobalFunction}`
   (строки 28–123) названы по-разному, но `Finding::getFingerprint()` не читает `symbolPath` вовсе —
   это прямо подтверждает соседний тест `itUsesSubjectOccurrenceAndEdgeRatherThanLocationOrMessageForFingerprint`
   на строке 245. Реальная защита от регрессии одна, четыре — балласт под видом покрытия пяти сценариев.

2. **`AnalysisContextThresholdTest.php` — имя лжёт содержанию.** `itGetThresholdOverrideRespectsLineScope`,
   `itMethodLevelOverrideTakesPriorityOverClassLevel`, `itBoundedOverrideWinsOverUnbounded` (строки 78–192)
   описывают границу по номеру строки, но во всех вызовах передаётся один и тот же `subject` без номера
   строки — сравнение «внутри/снаружи scope» реально не варьируется.

3. **`RuleThresholdKeyGroupRegistryCompletenessTest.php` (793 стр.) vs `RuleThresholdKeyGroupRegistryDriftTest.php` (513 стр.)**
   — оба гоняют AST-парсер по всему src/, чтобы проверить один и тот же `RuleThresholdKeyGroupRegistry`,
   с почти идентичными именами методов (`itMakesEveryRegistryEntryCorrespondToARealCallSite` /
   `...RealThresholdParserCallSite`). Авторы сами объясняют разницу в докблоках (литеральные аргументы
   vs поведенческий проб) — не слепой дубль, но стоимость прогона удвоена; кандидат на объединение.

4. **`DECLARED_CHANNEL_COUNT = 58`** захардкожен независимо в `ChannelUniverseCoverageTest.php:65` и
   `ChannelPresentationCoverageTest.php:31`. Докблок второго признаёт, что числа должны совпадать
   («a divergence between the two counts would itself be a regression»), но ничего программно это не
   проверяет — расхождение может остаться незамеченным, если поправить один файл и забыть другой.

5. **`LocationTest.php::itNoneCreatesLocationWithoutFile` ↔ `LocationNullFileTest.php::itLocationNoneCarriesNullFile`**
   — оба создают `Location::none()` и проверяют тот же набор свойств. `LocationNullFileTest` — отдельный
   файл под ADR 0015 Phase 1a с 3 собственными случаями, поэтому не чистый дубль, но пересечение почти
   полное — кандидат на слияние.

6. **`Support/FindingFactory.php` — файл физически не на своём месте.** Лежит в `tests/Analysis/Finding/Support/`,
   но ни один тест каталога `tests/Analysis/Finding/` его не использует — все 8 потребителей находятся в
   `tests/Analysis/Policy/Baseline/Unit/`. По правилу предметной связности это файл домена Baseline;
   правильное место — `tests/Analysis/Policy/Baseline/Support/FindingFactory.php` (рядом с уже существующим
   `tests/Analysis/Policy/Baseline/Fixtures/CeilingStageFixtures.php`).

7. **`RuleConfigurationIsolationTest.php`** частично пересекается по предмету (сброс `RuleOptionsRegistry`)
   с двумя тестами сброса состояния внутри `RuleOptionsFactoryTest.php` — не строгий дубль (разные поля),
   но кандидат на слияние.

8. **`RuleNamespaceExclusionProviderTest.php`** — первые два теста фактически проверяют `RuleOptionsRegistry`
   (делегирование), не заявленный SUT `RuleNamespaceExclusionProvider` — смешение предметов в одном файле.

9. **`RuleDocsPageCoverageTest.php` ↔ `RuleRemediationMinutesCoverageTest.php`** — дословно продублированные
   приватные хелперы (`ruleClasses()`, счётчик `48`, `docsRoot()`) между двумя файлами, использующими один
   и тот же паттерн сверки docs с реестром правил.

10. **Триада `ChannelLevelAssemblyTopologyTest`/`ChannelLevelDeclarationDriftTest`/`ChannelLevelRefusalTopologyTest`**
    — НЕ дубли: три разные грани (синтаксис объявления / фактическая эмиссия / топология отказа), явно
    обоснованные докблоками со взаимными ссылками. Отмечено только потому, что бриф просил явно
    проверить такие тройки.

Противоречий (два теста, утверждающих несовместимое об одном и том же поведении) не найдено ни в одной
из четырёх групп.

## Чем проверено и чего этот способ не видит

Метод: чтение каждого из 84 файлов целиком (Read/cat), сопоставление заявленного SUT с реальным кодом
`src/` через `grep`/переход по use-конструкциям, анализ структуры (`#[Test]`/`#[CoversClass]`/имена
методов) и сравнение соседних файлов на предмет дублей. Работа шла четырьмя параллельными потоками
(субагенты A/B/C + собственная работа над группой D), каждый поток независимо сверял код, но не видел
других групп — координация дублей МЕЖДУ группами (например, между Unit и Integration) выполнена только
на этом, финальном шаге, беглым сопоставлением таблиц, не повторным построчным чтением.

Что этот способ НЕ видит и НЕ доказывает:

- **Не проверено исполнением.** Ни один тест не был реально прогнан; оценки "integration"/"functional"/
  "control" опираются на статический анализ импортов и вызовов (`ContainerFactory`, `CommandTester`,
  реальные Options-классы, `proc_open('bin/qmx ...')`), а не на наблюдение реального прогона или
  реального провала при внесении регрессии.
- **Не подтверждена боеспособность control-guard'ов мутационно.** Для крупных control-invariant файлов
  (`OccurrenceKindFreezeGuardTest`, `RuleIdentifierLiteralGuardTest`, `ThresholdOverrideOwnRuleNameGuardTest`
  и др.) докблоки утверждают «было измерено, ловится» — это принято на веру по тексту докблока, ни одна
  мутация не воспроизводилась заново в рамках этого аудита.
- **654- и 1105-строчные файлы прочитаны не полностью построчно** (`RuleIdentifierLiteralGuardTest.php`,
  `ThresholdOverrideOwnRuleNameGuardTest.php`) — докблок, полная структура методов (`grep`) и
  репрезентативные фрагменты тела; то же для `RuleOptionsFactoryTest.php` (2194 стр.) и
  `RuleExecutorTest.php` (1504 стр.) в группе A. Точечные дефекты в непрочитанных середине/блоках могли
  быть пропущены.
- **Оценка «дубль» ограничена этим срезом.** Дубли SUT/утверждений с тестами ВНЕ `tests/Analysis/Finding/`
  (например, тем же SUT, проверяемым из `tests/Infrastructure/` или `tests/Functional/`) не искались —
  это вне границ выданного среза.
- **Использование `Support/*.php` вне среза установлено `grep -rl` по имени класса** — надёжный, но
  синтаксический метод; для каждого совпадения контекст (наличие `use`-конструкции и реального вызова
  конструктора) бегло подтверждён, но не гарантированно исчерпывающе для каждого из ~45 потребителей
  `StubChannelDeclarationRegistry`.
- **Оценка "control-invariant" вместо "control"** — по определению брифа («инвариант снимается со ВСЕХ
  классов src/ рефлексией») этот аудит относил сюда и файлы, сканирующие ПОДМНОЖЕСТВО src/ (например,
  `ThresholdValidatorAssignmentTest` — только `Evidence/*`), а не буквально «все» классы. Граница спорная,
  решение — за владельцем, как и просит бриф.
- **Правильность "каталог" оценена по физическому пути класса-владельца**, не по формальному ADR-анализу
  (ADR 0016/0022 co-change/counterfactual-ownership тестам не подвергались) — для явных случаев (не тот
  namespace, использование только другим доменом) расхождение бесспорно, для пограничных (например,
  `Rule/LevelActivityReadsBothDisablingSpellingsTest.php` в `Rule/` вместо `RuleConfiguration/`) оценка
  мягкая ("не критично").

## Допущения

- Категория "control" присваивалась по критерию брифа буквально: тест не гоняет продуктовое поведение
  в реальном времени, а сверяет разложенное состояние (документация, сгенерированные артефакты, текст
  исходников через regex/AST). Пограничные integration-тесты с поголовным обходом популяции классов
  (см. раздел «Кандидаты в control») оставлены как integration с явной оговоркой.
- Для 4 Support-файлов "SUT" описан как объект конструирования/инструмент измерения, а не проверяемое
  поведение — по прямой инструкции брифа для этого случая; "категория" — `helper (fixture)`.
- Нарушений CLAUDE.md §9 (`#[Test]` + форма `itXxx`) во всех 84 файлах **не найдено** — везде либо оба
  признака присутствуют корректно, либо (для Support-файлов) методы не являются тестами вовсе. Это
  проверено всеми четырьмя параллельными потоками независимо и ни один не нашёл нарушения.
- Один из фоновых субагентов (последняя восьмёрка файлов группы B) упал по 429 rate-limit API; эти
  8 файлов дочитаны и проанализированы напрямую оркестрирующим агентом без потери глубины — отмечено
  в отчёте группы B.
- "Правильный каталог" не заполнен (= "ok") там, где текущее расположение внутри `tests/Analysis/Finding/`
  соответствует владению предметом по коду src/, даже когда категория — control/control-invariant:
  вопрос "должен ли control-тест вообще жить в tests/" — отдельный от вопроса "правильный ли это
  подкаталог внутри tests/", и первый явно вынесен в раздел «Кандидаты в control» по требованию брифа,
  а не смешан со столбцом «каталог».

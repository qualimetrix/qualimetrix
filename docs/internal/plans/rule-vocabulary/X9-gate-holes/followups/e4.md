# Запись для FOLLOWUPS.md — пакет E4 захода Х9

## Х9 (2026-09-05) — режим записи у перечислителя директив

`Enumerator::main()` (`scripts/directive-audit/Enumerator.php`) знало только
stdout и `--check`; текст сообщения о протухании велело "refresh" командой
без `--check`, которая всего лишь печатает свежие строки в stdout — лечение
либо ничего не чинило, либо (редиректом в файл) сносило 50-строчную
хвостовую шапку `enumeration-threshold-directives.tsv`. Наблюдено дважды в
предыдущих заходах.

- **Закрыто:** третий режим `--write`. Читает committed-файл, вычленяет
  ведущий блок строк `#` (шапку — единственную часть артефакта, которую сам
  скрипт не измеряет), пишет шапку + свежие строки атомарно (temp-файл +
  `rename`, правило проекта §5). Сообщение о протухании в `--check` теперь
  называет ровно эту команду: `php scripts/enumerate-inline-directives.php
  src --write`.
- **Доказано на чистом дереве:** `--check` до правки — up to date (33
  сайта); `--write` поверх committed-файла даёт байт-в-байт идентичный
  результат (`diff` пуст, `git diff` пуст); `--check` после записи —
  снова up to date. Идемпотентность режима записи на неизменном дереве —
  это и есть проверка сценария «шапка не двигается».
- **Что не входит:** алиас в `composer.json` — файл в волне 2 принадлежит
  C3, а лечению достаточно режима самого скрипта; вызов `--write` остаётся
  прямым (`php scripts/enumerate-inline-directives.php src --write`), не
  через `composer enumeration:directives:*`.
- Точечных тестов на `Enumerator::main()` в дереве не было и не появилось:
  существующий `ThresholdPopulationAgreementTest` покрывает
  `ThresholdDirectiveScan`/`EnumeratedSite`, а не CLI-обвязку вокруг них;
  сама CLI-обвязка (stdout/`--check`/`--write`, выбор режима, сообщения)
  тестировалась запуском на живом дереве, а не unit-фикстурой — так же,
  как в остальных сценариях этого скрипта до Х9.

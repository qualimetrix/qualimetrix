# Х3-D — страж собственного имени: точность вместо мнимой гарантии

Закрывает две записи `FOLLOWUPS.md`: «Страж инварианта видит форму, а не тип, и
три класса чтения проходят мимо» и «Контроль полноты стража не привязан к
местам, которые называет». Гейт: нет.

Редакция вторая. Первая предлагала снять страж и держать инвариант типом:
метод принимает экземпляр правила, карта переопределений приватизируется. Ревью
опровергло это тремя измерениями, и решение сменилось целиком — не потому, что
типовая гарантия хуже, а потому, что в этом дереве её нет по цене одной
сигнатуры.

## Что измерено до планирования

Измерение 2026-09-02, ревью 2026-09-03 на дереве `84effeaf`. Способ: Serena и
grep со сверкой списков, исполнение стража над девятнадцатью синтетическими
формами, рефлексия по типам, прогон продукта на копии дерева с применённой
правкой.

**Контракт и его вызовы.** `AnalysisContext::getThresholdOverride(string $ruleName, MetricSubject $subject)`;
карта — публичное свойство `AnalysisContext::$thresholdOverrides`. Вызовов в
`src/` ровно два, оба изнутри правила и оба передают `$this->getName()`.

**Почему типовая гарантия отвергнута — три факта, каждый достаточен.**

1. **Цикл зависимостей уровня error.** `RuleInterface` уже импортирует
   `AnalysisContext`; типизация параметра на `RuleInterface` замыкает пару.
   Измерено на копии дерева с применённой правкой: сегодня циклов ноль, после
   правки — один прямой, то есть `error`, а `selfcheck` идёт с
   `--fail-on=warning`.
2. **Приватизация карты ломает живого производственного читателя.**
   `ThresholdDirectiveAudit` читает `$input->baseline->thresholdOverrides` в двух
   местах, а `$input->baseline` — это `AnalysisContext`. Ноль нарушений у стража
   получался ровно потому, что его текстовый трекер не видит доступ через чужое
   поле; первая редакция сделала вывод о мире из измерения инструмента.
3. **Экземпляр правила подделывается одной строкой.** Конструктор `AbstractRule`
   публичный: `new WmcRule(new WmcOptions())` даёт `complexity.wmc` — проверено
   исполнением. `AbstractRule` не финален, анонимный подкласс с произвольным
   `getName()` тоже доступен. Значит «чтобы прочитать чужую директиву, нужен
   чужой экземпляр» — не барьер: экземпляр не нужно получать, его делают.

**Дефекты стража, которые реальны и остаются.**

- **Ложное срабатывание шире записи.** Приёмник вызова страж не проверяет
  вовсе, поэтому краснеет любой одноимённый метод постороннего типа, а не только
  коллаборатор с параметром `$ruleName`. В `src/` таких мест сегодня нет;
  существующий живёт в `tests/` и избегает стража только границей вселенной.
- **Список «легитимных прямых читателей» инертен**: оба названных в нём файла
  дают ноль нарушений и с исключением, и без, потому что проверка чтения
  свойства не видит доступ через чужое поле. При этом настоящий прямой читатель
  в дереве есть (пункт 2 выше) — и он невидим.
- **Контроль полноты требует «не меньше двух»**, а докблок называет
  `LongParameterListRule::analyze()`, где вызова нет: он в `checkVoConstructor()`.

**Запись описывает слепые пятна шире, чем они есть.** Из шести названных
«невидимых» форм страж краснит три: контекст из свойства, хинт по полному имени,
переприсваивание в локальную. Реально невидимы чтение карты через текстуально
нераспознанный носитель и динамическое имя метода.

**Числа записи неверны.** Правил не 65, а 45 конкретных классов (плюс четыре
абстрактных) — то же число называет докблок в самом дереве; файлов, зовущих
эффективные опции, 26 вместе с `AbstractRule`.

## Архитектурное решение

**Страж остаётся и становится точным.** Инвариант в этом дереве держать типом
нечем: имя правила — публичная константа, экземпляр — публичный конструктор,
карта — публичное свойство, нужное соседнему предмету. Текстовый страж не хуже
типа, он просто должен смотреть на то, о чём судит.

**Приёмник проверяется.** Вызов краснеет, только если приёмник — выражение,
которое страж распознал как `AnalysisContext`. Это убирает ложное срабатывание
целиком: коллаборатор с параметром-именем перестаёт быть нарушением, потому что
он и не читает контекст.

**Список прямых читателей становится живым.** Проверка чтения свойства учится
видеть доступ через цепочку полей (`$x->y->thresholdOverrides`), и тогда
настоящий читатель — аудит директив — попадает в список **по имени**, как
исключение с причиной. Инертный список превращается в утверждение, которое
можно нарушить: новый прямой читатель краснеет.

**Контроль полноты перечисляет места, а не считает их.** Два канонических вызова
называются файлом и методом; третий вызов допустим, но обязан быть внесён в
список. Исчезновение обоих канонических при появлении двух других краснеет.

**Что записывается вместо мнимого закрытия.** Три измеренные причины, по которым
типовая гарантия не куплена, идут в `FOLLOWUPS.md` — иначе следующий заход
предложит ровно то же самое и потратит те же измерения заново.

## Контракты

Продукт не меняется вовсе: ни сигнатура `getThresholdOverride()`, ни видимость
карты. Меняется только страж:

```php
// tests/.../ThresholdOverrideOwnRuleNameGuardTest
private const array KNOWN_CALL_SITES = [
    'src/Analysis/Finding/Contract/Rule/AbstractRule.php'   => 'getEffectiveOptions',
    'src/Analysis/Evidence/CodeSmell/LongParameterListRule.php' => 'checkVoConstructor',
];

private const array LEGITIMATE_DIRECT_READERS = [
    // путь => причина; сегодня один: аудит директив читает карту целиком,
    // потому что судит директивы, а не применяет их
];
```

Три проверки: (1) каждый распознанный вызов на приёмнике-контексте передаёт
`$this->getName()`; (2) каждый прямой читатель карты — из списка; (3) оба
канонических места на месте, и всякий распознанный вызов вне списка назван.

## Кейсы и граничные условия

Каждый — снятием, и каждый проверяется на синтетической форме, а не только на
живом дереве:

- вызов с чужим литералом на приёмнике-контексте — краснеет;
- вызов с `$this->getName()` — зелёный;
- одноимённый метод постороннего типа с параметром `$ruleName` — **зелёный**
  (сегодня краснеет; это и есть снятое ложное срабатывание);
- прямое чтение карты через цепочку полей вне списка — краснеет;
- то же чтение из файла в списке — зелёный;
- исчезновение вызова из любого канонического места — краснеет;
- третий вызов, не внесённый в список, — краснеет.

Слепые пятна называются в докблоке стража прямо: динамическое имя метода и
носитель контекста, не распознанный текстуально. Пропуск, который назван,
отличается от пропуска, которого не знают.

## Definition of Done

1. `composer test`, `composer phpstan`, `composer cs-check` — 0; затем
   `QMX_MKDOCS=<основной checkout>/website/.venv/bin/mkdocs composer check` — 0.
2. Каждый кейс из списка выше проверен снятием: покажи, что без правки стража он
   даёт противоположный результат.
3. Список прямых читателей **не пуст** и его непустота проверена: убери из него
   аудит директив — страж обязан покраснеть. Инертный список считается
   невыполненной работой.
4. Число распознанных вызовов на живом `src/` названо числом до и после правки
   (сегодня два). Изменение числа означает, что правка приёмника задела
   вселенную, и это надо объяснить.
5. `composer directives:controls` — 0.
6. В `FOLLOWUPS.md` заведена запись с тремя измеренными причинами отказа от
   типовой гарантии (цикл, живой прямой читатель, подделываемый экземпляр) — с
   числами, чтобы следующий заход не измерял их снова.

## Что пакет не закрывает

Инвариант по-прежнему держится текстом, а не типом: правило, собравшее имя метода
динамически или прочитавшее карту через нераспознанный носитель, страж не видит.
Цена названа и записана; закрытие требует другого контракта (например, чтобы
переопределения приходили правилу уже отфильтрованными по его имени), и это
работа своего масштаба, а не хвост этого пакета.

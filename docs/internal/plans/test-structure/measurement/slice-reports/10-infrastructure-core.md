## Кандидаты в control

- `tests/Unit/Core/Util/GlobSyntaxTest.php::itIsTheOnlyPlaceInSourceThatEnumeratesTheGlobCharacters` — сканирует весь `src/` как текст ради инварианта «единственное место, перечисляющее glob-алфавит»; не проверяет поведение конкретного класса.
- `tests/Unit/Core/Util/NamespaceMatcherTest.php::itLeavesPatternNormalizationToThePrimitiveOnEverySurface` — сканирует весь `src/` как текст, сверяя с рукописным реестром call sites (`SELECTOR_SURFACES`); инвариант раскладки/дисциплины кода, не поведение.
- `tests/Unit/Core/VersionTest.php::itDoesNotResolveTheVersionThroughTheRootPackage` — grep по исходнику одного файла на отсутствие конкретного вызова API; проверяет реализацию через текст, а не через различающее поведение (сам докблок признаёт, что поведенчески дефектная и рабочая версии неразличимы внутри этого репозитория).
- `tests/Integration/DependencyInjection/RuleRegistrationDriftTest.php` — «второй свидетель»: реестр правил из реального контейнера сверяется с перечислением классов на файловой системе + рефлексией. Целиком про состояние репозитория (соответствие реестра и файлов), не про поведение одного продуктового класса.
- `tests/Infrastructure/Unit/RuleRegistryTest.php::itResolvesEveryCliAliasToARealRuleOption` (control-invariant, один тест внутри unit-файла) — реальный контейнер, обход ВСЕХ зарегистрированных правил, рефлексия по Options-классам; инвариант снимается со всего множества правил, не с одного SUT. Категория внутри файла отличается от остальных 4 тестов — стоит вынести отдельно.
- `tests/Integration/DependencyInjection/ContainerFactoryTest.php::itRegistersAllRules/itRegistersAllFormatters/itRegistersAllMetricCollectors` — рукописные списки классов, сверяемые с реальным контейнером; легитимный control-инвариант (перечисление), но рукописный список требует ручной поддержки при каждом новом правиле/формате/коллекторе — сам себе не докажет актуальность.

## Дубли и противоречия

- **Cache**: `tests/Integration/Infrastructure/Cache/CacheKeyGeneratorVOTest.php::itHandlesUnresolvableFileGracefully` дублирует `tests/Unit/Infrastructure/Cache/CacheKeyGeneratorTest.php::itReturnsEmptyKeyForNonExistentFile` — тот же SUT (`CacheKeyGenerator`), то же утверждение (пустая строка для отсутствующего файла). Остальная часть VOTest (символьные ссылки, содержимое-vs-путь) — не дубль, легитимное дополнение.
- **Cache Factory**: `tests/Infrastructure/Cache/Unit/CacheFactoryTest.php::itUsesTheCacheDirFromTheConfigurationAtFirstCall` дублирует `itReturnsAFileCacheConfiguredFromTheProvider` в том же файле — оба лишь `assertInstanceOf(FileCache::class)`.
- **Profiler**: `tests/Infrastructure/Profiler/Integration/ProfilerIntegrationTest.php` почти целиком повторяет `tests/Infrastructure/Profiler/Unit/ProfilerTest.php` и `ProfileSessionTest.php` (`itClearsAndResetsState` ≈ `itResetsProfilerOnClear`; `itExportsToJsonFormat`/`itExportsToChromeTracingFormat` ≈ `itExportsJsonFormat`/`itExportsChromeTracingFormat`; три теста про enable/disable ≈ `itClearsRecordedStateOnEveryModeTransition`). Из всего файла реально «интеграционный» только один тест (`itPerformsAtomicFileWrite`, настоящий I/O).
- **WorkerCountDetector**: `itReturnsFallbackWhenDetectionFails` — фактически повтор `itDetectsWorkerCountGreaterThanZero` того же файла под другим именем (см. таблицу).
- **FileDeclarationIndex**: `itAnswersAnUnregisteredPairInsteadOfRejectingIt`/`itRepeatsTheSameAnswerForARepeatedQuestion` содержательно повторяют первые два теста того же файла.
- **Namespace/путь разнобой в Profiler/Unit**: файлы физически лежат под `tests/Infrastructure/Profiler/Unit/...`, но `SpanTest`, `ChromeTracingExporterTest`, `JsonExporterTest`, `ProfilerTest` объявляют `namespace Qualimetrix\Tests\Unit\Infrastructure\Profiler[...]` (обратный порядок сегментов), тогда как соседний `ProfileSessionTest.php` в том же каталоге корректно объявляет `Qualimetrix\Tests\Infrastructure\Profiler\Unit`. Несогласованность неймспейса внутри одного каталога — механическая, но говорит о раскладке «на глаз», а не по конвенции.
- **RuleCompilerPass / RuleOptionsCompilerPass** (см. отчёт под-агента): внутренние дубли и тавтологии, где assert проверяет то, что тест сам же подставил.
- **ContainerFactoryTest.php** (898 строк): по отчёту под-агента — цепочка вложенных дублей, где более слабый тест является строгим подмножеством более сильного (`itHasAnalysisPipeline` ⊂ `itCreatesContainerWithDefaultConfiguration` ⊂ `itCreatesCompiledContainer`; аналогично для formatter-registry и rule-registry), плюс минимум 4 теста-тавтологии, где имя обещает одно, а `assertInstanceOf` проверяет совсем другое (комментарии в самом коде это признают).
- **Git Unit vs Integration**: вопреки предположению брифа, `tests/Unit/Infrastructure/Git/GitScopeResolverTest.php` не является родственным `tests/Integration/Infrastructure/Git/GitSubdirScopeTest.php` — у них разные SUT (`GitScopeResolver` vs `GitClient`+`ChangedFile`). Настоящая integration-пара для `GitSubdirScopeTest.php` — `Unit/Infrastructure/Git/GitClientTest.php` (тот же SUT `GitClient`), а настоящая пара для `ReportingGitScopeQueryProjectSubdirTest.php` — `Unit/Infrastructure/Git/ReportingGitScopeQueryTest.php` (тот же SUT). В обоих случаях дублирования утверждений не найдено: integration-версии целенаправленно бьют по границе «project root — строгий подкаталог git toplevel» (регрессия T10), которую плоский unit-репозиторий физически не может создать.

## Чем проверено и чего этот способ не видит

Проверка полностью read-only: каждый тестовый файл прочитан целиком вместе с соответствующим SUT-классом в `src/`
(через `use`-импорты и, где нужно, прямое чтение реализации — например, `KnownRuleNamesAdapter`, `WorseDirection`,
`FileDeclarationIndex`). Наличие `#[Test]`/форма `itXxx` проверены по факту чтения кода (grep на `function test`
не дал совпадений — явных нарушений §9 по имени метода в срезе не найдено; отсутствие `#[CoversClass]` в ряде
файлов Logging отмечено отдельно как минорная находка, не как нарушение §9). Соответствие каталога теста
владеющему предмету в `src/` сверено через `find`/`ls` по обоим деревьям.

Ни `composer check`, ни `phpunit`, ни `bin/qmx` не запускались — по прямому запрету брифа. Значит:
- «Тавтология» и «дубль» определены **по чтению** (assert не зависит от испорченного поведения SUT по конструкции
  теста), а не по фактическому мутационному прогону — по памяти проекта («стенд мутаций даёт ложно-зелёное»)
  только реальный мутационный прогон окончательно доказывает, что тест не ловит регрессию; здесь это гипотеза
  высокой уверенности, не факт.
- Не проверялось, зелены ли тесты сейчас и не разошлась ли документация внутри рукописных списков
  (`ContainerFactoryTest::itRegistersAllRules` и 46 других классов) с текущим состоянием `src/` — это может
  разойтись независимо от качества самого теста.
- Не проверялось покрытие строк: тест с «хорошим» именем и осмысленным assert-ом может всё равно не доходить
  до части веток SUT (например, `HookStatusCommandTest` прямо признан смоук-тестом, `execute()`-поведение
  не покрыто вовсе — это находка о **дыре**, не о дефекте существующих тестов).
- Категория «integration по факту, unit по каталогу» (`GitClientTest`, `GitRepositoryLocatorTest`,
  `ReportingGitScopeQueryTest`, `CachedFileParserTest` частично) определена по признаку реального обращения
  к git-процессу/файловой системе внутри теста, а не по официальному определению фреймворка — граница
  unit/integration в этом отчёте следует формулировке брифа («I/O или несколько классов»), которая шире,
  чем просто «медленный тест».
- Порядковая зависимость тестов (флап от `--order-by=reverse`, утечка глобального состояния через рефлексивные
  подмены статики в `FileSetInspectionParticipantCompilerPassTest`, `WorkerBootstrap::reset()`) не проверялась
  прогоном — отмечена как футган по чтению кода, не подтверждена эмпирически.

## Допущения

- Категория `control` применена по формулировке брифа: тест проверяет состояние репозитория/раскладки, а не
  поведение конкретного продуктового класса — включая случаи, когда control-часть — лишь один метод внутри
  иначе нормального unit-файла (в таблице такие файлы помечены смешанной категорией «unit + control» с указанием
  метода в дефектах).
- «Правильный каталог» предлагается только там, где расхождение — не про технический ярлык (Unit/Integration),
  а про предметную принадлежность (например, `NamespaceTreeTest` физически проверяет класс из `Analysis\Evidence\Measurement`,
  а не из `Core`) либо где фактическое поведение теста (реальный git/FS вызов) прямо противоречит объявленной
  папке `Unit/`.
- Дубли внутри `ContainerFactoryTest.php` и `RuleCompilerPassTest.php`/`RuleOptionsCompilerPassTest.php` взяты из
  отчёта параллельного под-агента, прочитавшего оба файла целиком с номерами строк; сведены сюда без
  перепроверки построчно моей собственной стороной — доверие ограничено тем же классом допущений, что и
  для моей части (чтение без прогона).
- Численность таблицы: 93 файла среза = 93 содержательные строки (несколько строк-заглушек в таблице
  явно помечены отсылкой «см. выше/см. блок» там, где один файл естественно описывается в одной строке рядом
  с прямым SUT-соседом, чтобы не дробить связанный разбор — по факту каждый путь встречается в таблице ровно
  один раз).

# Этап 01 — оракул класса «молчаливый приём»

Сквозные решения раунда — в `00-overview.md`; здесь они не пересматриваются.
Измерения — в `measurement/`. Этот файл фиксирует, **чем машинно доказывается,
что дверь пользовательского входа не молчит при промахе**, и чем это не
доказывается. Этот файл держит §1–4: обещание, артефакты, знаменатель и
классификацию. Продолжение решений этапа (нормализация, фикстуры, заморозка
«до», место в валидации, стенд контролей, развилки, риски — §5–13) вынесено в
`01-oracle-mechanics.md` (порог 400 строк) — нумерация §1–13 сквозная по обоим
файлам, номер раздела не меняется, меняется только имя файла у ссылок на §5 и
дальше. Пакеты работ, тестовый план и измерения этапа — в
`01-oracle-packages.md`: P1 сетка дверей → P2 декларации, фикстуры, сигналы →
P3 стенд, снапшот и заморозка наблюдений → P4 контроли, замер цены и место в
валидации.

## 1. Обещание и граница притязаний

**Обещание — ровно это и не шире:**

> Для каждого входа, видимого рефлексии `InputDefinition` и `ConfigSchema`
> (`ENTRIES` ∪ `DOCUMENT_ROOTS`), на **каждой команде, где рефлексия его видит**,
> и для каждого **объявленного** сайта внутри его значения вынесен машинно
> воспроизводимый вердикт о реакции на промах. `SPEAKS`/`REFUSES` засчитаны
> только при совпадении с **заранее объявленной формой сигнала** и только при
> наблюдаемом попадании; во всех прочих случаях исход — `SILENT`.

Умолчание раунда — в безопасную сторону: **не знаем ⇒ `SILENT`**; оракул,
ошибающийся в сторону «продукт говорит», не оракул, а разрешение не чинить.

**Чего оракул не докажет — обязательная часть контракта:**

| не доказывает                                | почему, по измерению                                                                                                                                                                          |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| полноту по сайтам                            | множество сайтов внутри значения двери **рукописное** (§3): рефлексия видит дверь, но не видит, сколько мест сопоставления живёт внутри её значения. Необъявленный сайт невидим по построению |
| отсутствие молчания там, где двери нет вовсе | `@qmx-ignore` в исходниках, окружение, ключи записей baseline, ссылки внутри формул computed-метрик (`reconciliation.md` §6). Зелёная таблица дверей совместима с молчанием в каждом          |
| что «отказывает» значит «отказывает всегда»  | вердикт снимается при одном порядке источников; §6 сужает, но не устраняет                                                                                                                    |
| что молчание — дефект                        | это суждение раунда, а не измерение                                                                                                                                                           |
| что промах «совпало не с тем» обработан      | меряется одна форма промаха — «не совпало ни с чем» (`reconciliation.md` §7.3)                                                                                                                |

**Разрез «девяти классов мест без двери» (`reconciliation.md` §6) — поправка к
первой редакции**, объявившей все девять невидимыми: пять из них — **сайты
существующих дверей**, и четыре из этих пяти раунд берёт (пятый — значения
внутри `--format-opt` — сайт, оставленный вне раунда). Отсюда четыре сайтовые
строки лечения в §7.

| класс                                                                  | статус в этом этапе                                                   |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------- |
| ключи внутри `--format-opt`                                            | сайт двери `--format-opt`: **пробуем при объявлении**, не перечисляем |
| значения внутри `--format-opt`                                         | вне раунда по решению `00-overview.md`                                |
| имена опций внутри `--rule-opt`, наличие `=value`                      | сайты двери `--rule-opt`                                              |
| `rules.<правило>.<опция>`                                              | сайт конфигурационного корня `rules`                                  |
| `architecture.layers[].exclude.patterns`                               | сайт конфигурационного корня `architecture`                           |
| ссылки внутри формул, ключи записей baseline, `@qmx-ignore`, окружение | двери **нет вовсе**: невидимы, нужен второй способ перечисления       |

Различие существенно: «сайт» пробуем при объявлении и охраняем контролем
(§11, `SITES UNDERDECLARED`), «нет двери вовсе» не пробуем никак.

## 2. Артефакты этапа

Предмет — «двери пользовательского входа»; каталоги названы по нему, а не по
роли, по прецеденту `finding-gate/`. Три рода артефактов, и разделение между
ними — часть механизма: **машинный**
знаменатель (`docs/internal/generated/input-doors/doors.tsv`), **рукописные**
декларации рядом с фикстурами (`input-doors/**`: аннотации дверей, пробники с
сигналами, наблюдаемые по командам, supplement нормализации, README) и
**стенд** (`scripts/input-doors*`), пишущий снапшот вердиктов и замороженные
наблюдения. Поимённый список с владельцем-пакетом — `01-oracle-packages.md` §15.

`verdicts-before.tsv` как самостоятельный артефакт **отменён**: «до» —
производная от замороженных наблюдений, а не файл, который пишут один раз (§9).

**Ловушка дерева.** Ни `01-oracle-packages.md`, ни `01-oracle-mechanics.md`, ни
`01-oracle-packages-measurements.md` не внесены в поимённый список
`scripts/generate-modular-architecture-production-inventory.php` — первый долг
раунда, а не находка приёмки; владелец дельты — P1 (подробности и правило
«остальные пакеты манифест не правят» — `01-oracle-packages.md` §15).

## 3. Знаменатель: сетка `команда × дверь × сайт`

**Ключ строки — `surface|command|door|site`, и ни одна его часть не константа.**
Это прямое следствие измерения: `doors-reconciled.tsv` держит 32 строки на
наследовании вердикта с `check` на другую команду, а 17 конфигурационных корней
несут команду-заглушку `(qmx.yaml)` — один вердикт на все команды, читающие
конфиг. Раскладка сетки:

| часть ключа           | чем порождается                                                                                                                                   |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `command` для CLI     | рефлексия `getDefinition()` каждой команды: дверь размножается по всем командам, где она объявлена                                                |
| `command` для конфига | команды, объявляющие дверь `--config` (измерено: 7 — `check`, `directives`, `debug:layer-assignment`, `baseline:cleanup/explain/generate/update`) |
| `door`                | `InputDefinition` (CLI) и `ENTRIES` ∪ `DOCUMENT_ROOTS` (конфиг)                                                                                   |
| `site`                | **рукописная** колонка `sites` в `door-annotations.tsv`; пусто ⇒ единственный сайт `whole-value`                                                  |

Размер сетки: ~93 CLI-строки × сайты + 17 × 7 = 119 конфигурационных строк.

**Чем получено и чего этот способ не видит.** Рефлексия по `InputDefinition` и
`ConfigSchema`; список конфиг-команд — рефлексия по двери `--config`. Не видит:
(а) команду, читающую `qmx.yaml` из cwd **без** двери `--config` — grep по
`src/Infrastructure/Console/Command/` показал явную загрузку у `CheckCommand` и
`BaselineRun` и не показал у `graph:export`/`rules`, но «подтягивается ли конфиг
глубже по стеку» этим способом не закрыто и остаётся слепым пятном; (б) сайты
внутри значения; (в) поддеревья `rules.<правило>.*`, `architecture.*` глубже
корня, `computedMetrics` — входят в сетку только объявленными сайтами своего
корня; (г) `@qmx-ignore` в PHP и окружение; (д) команду-сироту, не внесённую в
`ContainerCommandLoader`.

**Список сайтов: чем получен и чего не видит.** Рукописно, из колонки `verdict`
в `measurement/doors-reconciled.tsv`, где свидетель Б назвал расщепление
поимённо (девять строк `SPLIT`: `--rule-opt` на шести командах, `check --report`,
`baseline:rename-channels map`, конфиг-корень `architecture`). Не видит: сайты
дверей, до которых свидетель Б не дошёл; сайты, проявляющиеся только на другой
команде; сайты, вообще никем не измеренные. Поэтому объявление охраняется:
**дверь, у которой сайтов объявлено меньше, чем названо в
`doors-reconciled.tsv`, — красный исход генератора** (`SITES UNDERDECLARED`), а
«сайт один» требует причины в той же строке. Число «три пробника у `--rule-opt`»
из первой редакции DoD **отменено**: константа там, где нужна величина из
таблицы.

**Умолчание — «референтна».** Дверь считается референтной и подлежащей пробе,
пока в аннотации не стоит `referential=no` **с причиной**. Отсутствие двери в
`probes.tsv` не является заявлением о нереферентности: это отдельный красный
исход `NOT PROBED`. Правила соединения рефлексии с аннотациями (ключ
`command|door`):

| случай                                 | исход                                  |
| -------------------------------------- | -------------------------------------- |
| двери нет строки аннотации             | `referential=yes`, `sites=whole-value` |
| `referential=no` без причины           | отказ генератора                       |
| «сайт один» без причины                | отказ генератора                       |
| строка аннотации без двери в рефлексии | красный `STALE ANNOTATION`             |

Сегодняшний расклад (`doors-reconciled.tsv`, 110 строк до размножения по
командам): 97 референтных, 8 нереферентных с причиной, 5
`_complete`-внутренностей — последние уезжают в аннотации как `referential=no,
reason=Symfony completion internals`: либо проба, либо поимённая строка,
третьего нет.

## 4. Классификация: наблюдаемое, сигнал и сторож при каждом из них

**Отвергнут не только критерий `M ≠ A`, но и его исправленная версия
`additions(M,A) \ additions(H,A)`.** Обе выводят «продукт сказал» из разницы
текстов, а разница текстов есть **по построению** там, где продукт печатает
поданное значение: `check --namespace='Acme\NoSuch'` даёт шапку
`… 1 file analyzed [namespace: Acme\NoSuch]`, и это эхо всегда уникально
относительно `H` и `A`. Второй, независимый способ той же ошибки: `No violations
found.` печатается одинаково при «неймспейса нет» и при «неймспейс чист», то есть
уникальное добавление бывает **нейтральным**.

**Замена алгоритма на объявленный сигнал сама по себе дефект не снимает, а
переносит** — из кода, где сторож возможен, в рукописную декларацию, где его
раньше не было. Измеренный ход: на оси «больше задуманного» (`--exclude`,
`exclude:`, `suppress_*`, `layers[].exclude`, `frameworkNamespaces` — шесть из
четырнадцати лечимых мест) промах множество не сужает, поэтому `M ≡ A`; любой
регекс, выписанный человеком по тексту `M`, от `H` отличается, прежнюю проверку
специфичности проходит и даёт `SPEAKS` без единой правки продукта. Поэтому
ниже у **каждого** поля декларации назван сторож — машинная проверка, краснеющая,
когда поле утверждает неправду, — а там, где сторожа нет, это сказано словами.

### Три поля декларации пробника

| поле         | вопрос, на который отвечает                                                                                 | виды значений                                                                             |
| ------------ | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `observable` | **где видно попадание**                                                                                     | `format:<имя>`, `stderr`, `exitcode`, `file:<путь>`, `dir:<путь>`                         |
| `signal`     | **какой формой продукт обязан сказать о промахе**                                                           | `refusal`, `finding:<канал>@<формат>`, `stderr:<регекс>`, `exit:<код>`, `none` с причиной |
| `hit_empty`  | **попадание, дающее пустой результат законно** — значение, которое дверь принимает и которое сужает до нуля | значение, либо `none` с причиной                                                          |

`observable` берётся из `command-observables.tsv` по команде, а строка пробника
его **перекрывает**, когда наблюдаемое — свойство двери, а не команды
(`--fail-on` → `exitcode`, `--cache-dir` → `dir:`).

Правила «различается ли» — по виду наблюдаемого, а не одно на всех:

| вид                      | «попадание наблюдаемо», если                                     |
| ------------------------ | ---------------------------------------------------------------- |
| `format:<имя>`, `stderr` | нормализованные и очищенные от эха тексты `H` и `A` не совпадают |
| `exitcode`               | `exit(H) != exit(A)`                                             |
| `file:<путь>`            | факт существования файла различается между `H` и `A`             |
| `dir:<путь>`             | факт создания каталога различается между `H` и `A`               |

### Сторож 1: специфичность считается по трём сторонам, а не по одной

Прежняя редакция сверяла сигнал только с `H`. **Сигнал, срабатывающий на `H`, на
`A` или на `H₀` (наблюдение по `hit_empty`), — красный исход
`SIGNAL NOT SPECIFIC`, а не `SPEAKS`.** Три стороны закрывают три измеренных
способа ошибиться: `H` — «сигнал описывает попадание», `A` — «сигнал описывает
то, что печатается и без двери» (класс `M ≡ A` выше), `H₀` — «нейтральное
добавление»: `No violations found.` появляется и на законно пустом попадании,
поэтому сигнал, выписанный по нему, краснеет. Сторож применим к любой двери и не
требует наблюдаемого попадания.

**`hit_empty` обязателен там, где он строится, и не выдумывается там, где не
строится.** Он требуется у сигналов вида `stderr:`, `finding:` и `exit:` на оси
«меньше задуманного» (`--namespace`, `--class`, `graph:export --namespace`,
`debug:layer-assignment`), где законно пустой результат отличим от промаха. На
оси «больше задуманного» пустого попадания не существует: промах там и **есть**
неотличимое пустое попадание, поэтому `hit_empty=none` принимается **с
причиной**, и покрывающим сторожем для этих дверей объявляется сторож 2. `none`
без причины — отказ генератора. **`SPEAKS (unguarded)`** — отдельная строка
сводки для вердикта `SPEAKS` у двери, где `hit_empty=none` **и** ключ не входит
в `cure-sites.tsv`: стороны `H` и `A` сторожа 1 работают всегда, а нейтральное
добавление у такой двери не ловит ни `H₀`, ни сторож 2. Число измеряется прогоном
P3 и печатается; ожидание «ноль» проверяется, а не постулируется, и рост числа —
сигнал, что появилась третья ось.

### Сторож 2: объявленный сигнал обязан молчать на замороженном «до»

Для каждой строки лечения (§7) классификатор прогоняется над
`observations-before/**` — снимком продукта **до** пакетов лечения. Вердикт
«до», равный `SPEAKS` или `REFUSES`, — красный исход **`SPEAKS BEFORE CURE`**:
сигнал, срабатывающий на продукте до лечения, сигналом не является, и одно из
двух утверждений ложно — либо декларация, либо место в списке лечимых. Сторож
считается пересчётом, без прогонов, и переживает выход лечения: снимок «до»
заморожен один раз до первого пакета лечения (§9), поэтому после выхода лечения
он показывает всё тот же нелеченый продукт. Если снимок по ошибке снят уже на
вылеченном дереве, сторож **краснеет**, а не зеленеет, — направление отказа
безопасное.

Границу сторожа называю прямо: он покрывает только те строки, где план сам
утверждает «до молчит», то есть 15 строк §7. Для ~82 прочих референтных дверей
сторожем остаётся сторож 1; утверждения «до» о них план не делает.

### Порядок классификации

```
0. привести M, H, A, H₀ к сравнимому виду: токенизация путей (§9),
   вырезание эха (ниже), нормализация (§5)
1. вид signal несовместим с видом observable            -> SIGNAL/OBSERVABLE MISMATCH (красный)
2. нет наблюдения M, H, A — или H₀ при объявленном
   hit_empty                                            -> INCOMPLETE TRIPLE (красный)
3. signal срабатывает на H, на A или на H₀              -> SIGNAL NOT SPECIFIC (красный)
4. signal = refusal, exit(M)==3, exit(H)!=3, exit(A)!=3 -> REFUSES
5. попадание не наблюдаемо по правилу своего вида       -> NOT OBSERVABLE
6. signal объявлен и срабатывает на M                   -> SPEAKS
7. иначе                                                -> SILENT
// ... implementation details
```

**Отказ проверяется раньше наблюдаемости — перемена против первой редакции.**
Тройка `exit(M)==3, exit(H)!=3, exit(A)!=3` свидетельствует сама и наблюдаемого
попадания не требует. Измерено на `--memory-limit` (§19): `M` даёт exit 3 с
текстом отказа, `H` (`512M`) и `A` неразличимы после нормализации, — при прежнем
порядке доказуемо отказывающая дверь уходила в `NOT OBSERVABLE` и раздувала
остаток, который §13 называет обесценивающим знаменатель. Наблюдаемость остаётся
обязательной только для `SPEAKS` и `SILENT`, где без пары наблюдение испорчено.

**Отсутствие наблюдения — не `NOT OBSERVABLE`.** Пропавшая сторона тройки даёт
`INCOMPLETE TRIPLE`: «сравнить нечем» и «сравнили, различий нет» — разные факты,
и слияние их прятало бы поломку стенда под честным исходом.

Тройка шага 4 — это **определение** `REFUSES`, а не защита от чего-то: случай
«сломанная фикстура отказывает всегда» до шага 4 не доходит, его краснит шаг 3
(сигнал `refusal` срабатывает и на `A`). Перемена против первой редакции: там
этот случай защищался условием `exit(A)!=3` внутри самого шага и при
необъявленном сигнале молча падал в `SILENT`; теперь он красный и назван.

**Необъявленный exit 3 даёт `SILENT`, и это намеренно**: источник ~72 деклараций
`signal=refusal` — колонка `verdict` в `doors-reconciled.tsv`, а дверь, чьего
отказа никто не объявлял, падает в безопасную сторону. **`signal=none` требует
причины**, иначе отказ генератора: `none` без причины есть дверь к зелёному по
декларации — та же грабля «декларация выражает только простой случай». В сводке
`SILENT (declared none)` и `SILENT (declared, not fired)` печатаются
**раздельно**; живое число дефектов раунда — второе.

### Вырезание эха: сопоставление после преобразований, а не поиск литерала

Первая редакция объявляла вырезание «точным вхождением поданного значения» —
это неверно для целого класса дверей: продукт печатает пути **абсолютными**
(измерено на `--config` и `-o`, §19), а §9 подменяет корни на
`<FIXTURE>`/`<REPO>` перед записью. Значение в `probes.tsv` машинно-независимо,
поэтому его литерал в тексте наблюдения не встречается никогда.

**Правило:** значение из декларации прогоняется через **те же** преобразования,
что и текст (абсолютизация относительно корня фикстуры, затем токенизация), и
вырезается уже результат. Подстановка корней — **длиннейший префикс первым**:
фикстуры лежат под `input-doors/fixtures/` внутри репозитория, поэтому `<REPO>`
первым сделал бы `<FIXTURE>` недостижимым. Порядок и полнота подстановок
объявляются в `input-doors/README.md`.

**Сторож 3 (двусторонний, на само вырезание).** Колонка `echoes` в `probes.tsv`
утверждает, печатает ли продукт поданное значение. `echoes=yes`, а
преобразованное значение в тексте `M` не найдено → `ECHO NOT FOUND` (красный);
`echoes=no`, а значение найдено → тот же красный. Односторонняя проверка ловила
бы только опечатку в декларации, двусторонняя ловит и рассинхрон конвейера
преобразований — ту поломку, которой этот пункт и посвящён.

**Чего сторож 3 не видит:** преобразованное эхо — обрезанное, с нормализованными
разделителями, в другом регистре, разбитое по строкам. Это остаток, а не
закрытый вопрос.

**Побочный эффект вырезания на `format:summary` — не закрыт вырезанием, а решён
нормализацией (§5).** Утверждение первой редакции («после вырезания эха строка
нормализации `format:summary` снова совпадает») **ложно и снято**: вырезается
значение, а скобка остаётся — `— 2 files analyzed [namespace: ], 0.0s` регексу
гейта `~(— \d+ files? analyzed, ).*(s)$~m` не соответствует (проверено
`preg_match`, §19). Вырезанием это и не чинится: ту же строку разрывает вставка
`(scoped)`, внутри которой поданного значения нет вовсе.

**Калибровочные случаи выведены под это правило заново, а не перенесены**:
прежние три (Б №13, timestamp-диф, `baseline:cleanup`) ни одного эхо-случая не
содержали. Набор — в `01-oracle-packages.md` §16 (DoD P3). Плюс исходы стенда,
не про продукт: `NOT PROBED` (строка сетки без пробника), `STALE PROBE` (пробник
на исчезнувшую строку), `INCOMPLETE TRIPLE`, `ECHO NOT FOUND` — все красные,
прецедент разделения «пусто» и «устарело» — `directive-audit-coverage-control.php`.

**Инварианты прогона:** `--fail-on=none`, `--workers=0`, `--no-cache`, cwd —
каталог фикстуры, конфиг — только явный, код возврата снимается **без пайпа**;
инвариантный флаг подаётся, **только если команда его объявляет**.

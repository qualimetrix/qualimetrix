## Четыре причины, которых план не предвидел

### П1. Title-case расширение карты каналов бьёт по обычной английской прозе

`RenameMaps::titleCase('maintainability.index')` = `Maintainability Index` — это
не только имя правила в SARIF, но и **живая английская фраза**, которой продукт
называет метрику. Она лежит в дереве буквально в трёх ролях:

| место                         | что это                                                 |
| ----------------------------- | ------------------------------------------------------- |
| `MaintainabilityRule.php:121` | текст находки, «Maintainability Index is %.1f, below …» |
| `MaintainabilityRule.php:54`  | описание правила, попадает в SARIF `shortDescription`   |
| `MetricHintCatalog.php`       | human label, попадает в JSON отчёта HTML                |

Прямая карта переписывает эталон в `Maintainability Mi is 47.4, below …` и
`"label": "Maintainability Mi"`, кандидат печатает верное `Maintainability Index`.
Это **самая массовая причина**: 18 отказов `format:html` плюс `checkstyle`,
`github`, `gitlab`, `sarif`, `text`, `show-suppressed`.

Утверждение `00-overview.md` — «title-case имя `rules[].name` строится из кода в
`SarifRuleCollector.php:78-79` и в дереве как литерал не лежит» — **опровергнуто
измерением**: лежит, и не как имя правила, а как название метрики.

Свипом это не чинится: `Maintainability Index` — академическое название метрики
(CLAUDE.md, Metrics Policy), ADR 0048 переименовал **код канала**, а не
человеческое имя. Переписать прозу в `Maintainability Mi` значило бы соврать в
отчёте ради зелёного гейта.

### П2. Паддинг колонки: продукт не двигает, а подстановка двигает

`00-overview.md` объявляет риск ширины колонки «проверенным и опровергнутым»:
обе поверхности печатают `%-40s`, все восемь имён короче сорока. Про **продукт**
это верно. Но гейт сравнивает кандидата с **текстово подставленным** эталоном, а
подстановка паддинг не пересчитывает:

    - candidate:   complexity.ccn                           ~2h  (4 violations)
    + reference:   complexity.ccn                    ~2h  (4 violations)

Эталон печатал `complexity.cyclomatic` (21) + паддинг до 40, карта заменила
21 символ на 14 — строка стала короче на 7. Обратный знак у
`architecture.coverage-gap`: эталон короче на 4, мапнутая строка **длиннее**.
Задеты `tree|rules` (172 сравниваемых строки) и `format:text-verbose` кейсов
`complexity`, `duplication`, `layers`.

Опровержение в плане отвечало на другой вопрос: измеряли ширину у продукта, а
двигается она у мапнутого эталона.

### П3. Ключ метрики в верхнем регистре карта не переводит

`case:health|format:health`:

    - candidate:  Formatter   TYPE_COVERAGE.ALL=42.9
    + reference:  Formatter   TYPE_COVERAGE.PCT=42.9

`format:health` печатает ключ метрики в верхнем регистре. `metric-keys.tsv`
знает только точечное нижнее написание и разворачивается по суффиксам
агрегации, но не по регистру — ровно слепое пятно (i) из `00-overview.md`,
которое план назвал только применительно к SARIF.

### П4. Auxiliary-кейс обязан выдавать ровно свою заявку

`CaseDefinition::COVERAGE_AUXILIARY`: «сравнивается на каждой поверхности и
обязан выдавать ровно то, что заявляет; из арифметики покрытия он лишь
исключён». План выводит безопасность перенацеливания
`applied-threshold/src/Retuned.php:15` только из покрытия.

Измерено: единственный производитель `complexity.cyclomatic@callable` в этом
кейсе — ровно перенацеливаемая директива.

| состояние директивы                              | что выдаёт кейс                      | exit |
| ------------------------------------------------ | ------------------------------------ | ---- |
| оставлена `complexity.cyclomatic`                | `annotation.unresolved-directive` x1 | 2    |
| перенацелена на `complexity.cognitive warning=2` | `complexity.cognitive` x3            | 0    |

Значит пакет E обязан на время окна снять `complexity.ccn@callable` из
`channels` этого кейса и вернуть его тем же коммитом, что возвращает директиву
после K4. В плане этой правки нет.

## Ответ на вопрос 1: объявленная дельта перестановку НЕ принимает

После правки харнесса (П1) и свипа фикстуры остаток — ровно 11 отказов
`surface-mismatch`, новых причин нет. `--derive-declared-delta` записал 11 дельт
(exit 4), все меньше лимита `MAX_CHANGED_LINES = 200` (максимум 158), то есть
`delta-too-large` не срабатывает ни на одной. Прогон против заполненных причин:
**RED, 187 `delta-overreach`.**

| дельта                                  | вердикт    | причина расхождения                                    |
| --------------------------------------- | ---------- | ------------------------------------------------------ |
| `case:complexity\|format:text-verbose`  | принята    | паддинг                                                |
| `case:duplication\|format:text-verbose` | принята    | паддинг                                                |
| `case:layers\|format:text-verbose`      | принята    | паддинг                                                |
| `tree\|rules`                           | принята    | перестановка + паддинг                                 |
| `case:health\|format:health`            | принята    | ключ метрики в верхнем регистре                        |
| `case:design\|format:summary`           | принята    | `coverage:` в прозе                                    |
| `case:design\|format:text-verbose`      | принята    | `coverage:` в прозе                                    |
| `case:complexity\|baseline-file`        | ОТВЕРГНУТА | перестановка, поле `channel`                           |
| `case:complexity\|format:json`          | ОТВЕРГНУТА | перестановка, поле `channel`                           |
| `case:design\|format:html`              | ОТВЕРГНУТА | `coverage:` в прозе, поле `recommendation`             |
| `case:design\|format:json`              | ОТВЕРГНУТА | `coverage:` в прозе, поля `message` и `recommendation` |

Обе отвергнутые причины отсылают к одному и тому же поимённому послаблению:
строка `declared-field-moves.tsv`, называющая **ровно эту пару значений на ровно
этой поверхности**.

### Для `design` это послабление — верный механизм

Строка называет пару вида «`Parameter type coverage-gap: 0.0% …` ->
`Parameter type coverage: 0.0% …`» на поверхности `case:design|format:json`,
поле `message`. Это точное, поштучное, поповерхностное объявление ровно того,
что произошло: строка `coverage:` перевела постороннюю прозу. Ничего лишнего
оно не разрешает.

### Для перестановки это послабление было бы ложью

Строка объявила бы пару `complexity.cognitive -> complexity.ccn` в поле
`channel`. Это два **разных** канала, и такая строка узаконила бы на этой
поверхности ровно ту подмену, ради ловли которой гейт существует. Это тот самый
штамп, который механизм отказывается ставить.

### Приём/отказ по перестановке решает форма ханка, а не смысл

`tree|rules` несёт **ту же** перестановку и принят, а `complexity|format:json`
отвергнут. Разница не смысловая, а алгоритмическая:

- в `tree|rules` переставленный блок уехал далеко (строка 50 против 56), и
  `ExactDiff` разбил его на **непарные** ханки `-6 +0` и `+0 +6`;
  `overreachingLines()` не с чем спаривать, поле никуда не «двигается»;
- в `baseline-file` два соседних блока поменялись местами, ханк вышел `-9 +9`,
  и спаривание по позиции сложило `"channel": "complexity.ccn"` кандидата с
  `"channel": "complexity.cognitive"` эталона — «перемещение поля», которого в
  действительности нет.

То есть один и тот же факт — записи переставлены — на одной поверхности
проходит, на другой краснеет по тому, как лёг алгоритм разбиения. Это не
свойство шага и не свойство поверхности.

### Предпосылка теста может испариться молча

`complexity.ccn`, `maintainability.mi` и `design.dit` **уже существовали** как
ключи метрик. После переименования имя, бывшее только ключом метрики, стало ещё
и именем правила. Тест `DirectiveAddressabilityTest::itAnswersAThresholdNaming…`
утверждал «этот ключ — метрика, а не правило» и теперь получает валидное
правило: `problemWithThreshold()` возвращает `null`. Здесь он покраснел, но тот
же класс может дать **зелёный вакуумный тест**, который ничего не проверяет.
Поиск таких мест — в DoD пакета B2.

### `--emit-maps` работает только ДО свипа — порядок пакетов в плане неисполним

План ставит порождение строк карт в пакет E, то есть **после** A–D. Исполнение
показало, что так нельзя: `php scripts/generate-rename-enumeration.php
--emit-maps=Х12П4` на переименованном дереве отказывает —

    Step Х12П4 has already landed: 10 of its rows are retired into
    enumeration-renames-executed.tsv, so its maps are in git rather than
    re-derivable here. Read finding-gate/maps/*.tsv from the commit that landed it.

Скрипт измеряет идентичность продукта из живого контейнера; после свипа она уже
совпадает с новым словарём, и шаг читается как приземлившийся. Совет «читай из
коммита» неприменим: коммита нет, свип ещё не закоммичен.

Пакет E восстановил строки, воспроизведя формат `emitMapsForStep()` по решённым
строкам `enumeration-renames.tsv`. Восстановленное **сверено оркестратором с
авторитетным выводом той же команды, снятым в К0м до свипа**, и совпало до
строки (5 + 1 + 4, плюс одна рукописная строка ключа конфигурации).

Вывод для плана: `--emit-maps=<токен>` вызывается в К1, вместе с объявлением, и
его вывод сохраняется. Порядок «объявить -> свипнуть -> породить карты» не
исполним, и полагаться на восстановление вручную нельзя — оно верно только
потому, что было с чем сверить.

### Шаг создал одну лгущую константу — решение владельца

`00-overview.md` выводит имена PHP-констант из свипа на том основании, что они
«не равны коду канала и решением не затронуты». Для `COMPLEXITY_CCN`,
`DESIGN_DIT` и `MAINTAINABILITY_MI` это верно — они уже назывались по ключу
метрики и остались согласованными. Но одна константа **была согласована до
шага и разошлась из-за него**:

    было (origin/main):  DESIGN_TYPE_COVERAGE_PCT = 'design.type-coverage.pct'
    стало:               DESIGN_TYPE_COVERAGE_PCT = 'design.type-coverage.all'

`PCT` и `ALL` — не разное написание одного, а противоречие: «процент» против
«все виды». Ссылок 13, плюс класс `TypeCoveragePercentCollector` с тем же
корнем в имени. На поведение не влияет.

Основание исключения в плане («константы решением не затронуты») к этому случаю
не применимо: оно про константы, которые никогда не совпадали с
переименовываемым именем, а эта совпадала точно. Решение — переименовывать её в
этом шаге или записать в followups — за владельцем.

### Запрет «проверь, но повторно не правь» создал пропуск

Бриф добивочного пакета запретил трогать четыре страницы, которые уже сделал
предыдущий пакет. На двух из них ключ остался старым (`the "coverage" mode`,
`режим "coverage"`), и там же пример вывода диагностики разошёлся с реальным
после правки сообщения. Пакет нашёл оба и, следуя запрету, не тронул — то есть
запрет сработал как задумано, а дефект был в самом запрете: «этот файл уже
сделан» и «в этом файле не осталось работы» — разные утверждения. Закрыто
оркестратором.

### Корневой `qmx.yaml` — генерируемый, и владелец у него не тот, кого назвал план

`00-overview.md` говорит: «`qmx.yaml` принадлежит F, и только F… двойного
владения нет». Владения действительно нет, но владелец другой: секция
архитектуры в корневом `qmx.yaml` **генерируется**
`scripts/generate-modular-architecture-production-inventory.php` (шаблон строки
`$lines[] = '  coverage: error';`, стр. 2313), между маркерами
`# END GENERATED MODULAR ARCHITECTURE`.

Ручная правка ключа в `qmx.yaml` пережила пакет F, но **не пережила пакет H**:
первый же `composer architecture:generate` вернул старый ключ, и следом
`composer suppression-snapshot` упал с exit 2 —
`architecture: unknown key "coverage"`. То есть между F и H дерево несло
конфигурацию, которую собственный продукт отвергает, и обнаружилось это только
регенерацией.

Правильный владелец ключа в `qmx.yaml` — шаблон генератора. Исправлено;
`architecture:generate` перегенерирован, `suppression-snapshot` прошёл.

Обобщение для будущих шагов: файл, лежащий в корне и выглядящий рукописным,
может быть артефактом. Перед тем как отдать его пакету, проверять, не пишет ли
его генератор, — иначе правка тихо откатится на регенерации.

## K4 — что план описал неточно

### Релизная карта не может быть `.json`

`04-release.md` называет файл `docs/migration/v0.26-rename-map.json` «в формате
команды». Формат команды — **tab-separated** (`map — Path of the tab-separated
rename map (columns: old, new, reason)`), поэтому `.json` дал бы потребителю
отказ на первом же шаге миграции. Файл назван `.tsv` и **проверен догфудингом**:
скормлен `baseline:rename-channels` на копии корневого baseline, откаченной к
старому словарю, — `Carried 66 of 209 entries`, exit 0.

### Класс 1 миграции — тоже не одна команда

Проба вскрыла: baseline старее текущей версии команда **отвергает** —

    is a version 11 baseline and this build carries version 13. A carry
    substitutes a name and converts nothing, so the file has to be brought to
    version 13 first.

То есть даже там, где команда есть, шагов два: привести файл к текущей версии,
потом перенести имена. Релизная заметка обязана называть оба.

### Снимать надо не только строки карт

K4 шаг 3 говорит «снять строки из `finding-gate/maps/*.tsv`». Этого мало:
`delta-stale` и `field-move-stale` — такие же классы отказа, как `map-stale`,
поэтому объявленные дельты (11 поверхностей) и лицензированные переезды полей
(11 строк) обязаны сниматься тем же коммитом. Все три — объявления об одном
шаге, и любое, пережившее его, становится утверждением о переименовании,
которого больше нет.

### Причина в `reason` карты для гейта и для релиза — разные тексты

Строки, порождённые `--emit-maps`, несут `reason = "Х12П4 renames this channel"`
— токен шага, потребителю ничего не говорящий. Релизная карта переписывает
колонку на причину, понятную читателю («the channel now carries the same name as
the metric it judges»). Файлы совпадают по парам `old`/`new` и намеренно
расходятся по `reason`.

# План: идентичность канала — точное равенство вместо префиксного матчинга (редакция 4, финал)

**Статус:** предложение, перед ревью
**Дата:** 2026-08-18
**Область:** `src/Analysis/Finding/Contract/Rule/` (матчер, селектор), `src/Analysis/Policy/Inline/Contract/Suppression/`, `src/Analysis/Finding/Contract/Threshold/`, реестры каналов, `ChannelDeclaration`
**Отношение к предыдущим редакциям:** заменяет редакцию 3 (NO-GO). Ограничения, установленные по коду, и реестр находок A1-A32 — в `channel-identity-findings.md`; они остаются в силе.

## 0. Итог дискуссии

Редакции 1-3 провалились по одной причине: каждая пыталась заменить словарь адресации **целиком** (объявленные семьи + авторитет с произвольными семьями), тогда как реально был заблокирован один сценарий — префиксный захват дочернего канала (§1.1 findings).

Дискуссия установила три факта, которых не было в редакции 3:

1. **Нотация уже существует.** `coupling.cbo.class` ровно и есть `family.rule.violation`. Проблема не в нотации, а в семантике матчинга: `RuleMatcher` даёт `exact ∨ prefix`, поэтому `architecture.coverage` глотает `architecture.coverage.source`, а `@qmx-ignore`/`@qmx-threshold` принимают разные словари.
2. **Семья — проекция, а не сущность.** Имя семьи не хранится нигде; `coupling` — это первый сегмент `NAME = 'coupling.cbo'`, извлекаемый одной операцией. Объявлять её (Family::NAME) — вводить второй словарь и кросспредметную константу: `architecture` делится между `CircularDependency` и `LayerViolation`, `design` — между `Design` и `Cohesion`.
3. **Категория — атрибут, не уровень адресации.** Реальных категорийных подавлений в репозитории ноль (findings §5.4, §2.6); трёхуровневая рамка редакции 3 опиралась на несуществующую аннотацию. Реальных уровней адресации два: правило и канал.

Отсюда финал: **убрать префикс, матчинг = точное равенство.** Семья — производная имени. Категория — объявленный атрибут вне адресации. Реестр — валидатор и резолвер, а не авторитет с произвольными семьями.

## 1. Решение (ядро)

### 1.1 Матчинг = точное равенство

`RuleMatcher::matches()` теряет prefix-семантику (`str_starts_with($subject, $pattern . '.')`) и вырождается в сравнение `===`. Семейное сравнение — одна функция `familyOf($name)`: первый сегмент до точки, применяется только там, где нужна групповая адресация. `anyReverseMatches` и его противоречивый докблок (A8) разбираются здесь же: обратный режим перестаёт существовать, его боевые потребители (`only_rules`-валидация, `RuleNameValidator`) переходят на точное равенство.

### 1.2 Уровень определяет директива, а не число сегментов

| Директива/потребитель                     | Что адресует            | Матчинг                                                                                                 |
| ----------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------- |
| `@qmx-ignore X`                           | канал (`violationCode`) | точное равенство; 1-сегментная форма `X` = семья (`familyOf(violationCode) === X`), групповая адресация |
| `@qmx-threshold X`                        | правило (`ruleName`)    | точное равенство; `*` и prefix удалены                                                                  |
| селекция (`only_rules`, `--disable-rule`) | producer и/или channel  | точное равенство; `#`-форма адресует обе половины явно                                                  |

Ключевое следствие: неоднозначность «имя = и производитель, и канал» (2.2 findings) **снимается директивой**, а не переименованием 38/51 каналов. `@qmx-ignore code-smell.boolean-argument` — всегда канал; `@qmx-threshold code-smell.boolean-argument` — всегда правило. Дублирование `rule.violation` (`coupling.cbo.cbo`) **не требуется** — от этого варианта отказываемся, публичный violationCode 38 каналов не трогается.

### 1.3 threshold: «did you mean» от реестра

Закрывает §1.2 (отчёт печатает `coupling.cbo.class`, threshold ждёт `coupling.cbo`). Подсказка строится обратным запросом к реестру (`violationCode → ruleName`), а не отсечением суффикса и не перечислением producers вручную.

### 1.4 Breaking-поверхность

Публичная семантика меняется в двух местах, оба — осознанный слом с записью `Breaking` в `CHANGELOG.md` и разделом миграции от лица потребителя:

- 2-сегментный селектор/подавление больше не глотает точечных потомков (это и есть фикс §1.1);
- `@qmx-threshold` перестаёт принимать prefix (`coupling 15`) и `* 15`.

## 2. Семья и категория

### 2.1 Семья = проекция первого сегмента, не объявляется

Единственный источник — `NAME` правила. `familyOf()` вычисляется в реестре один раз при регистрации; отдельная константа `Family::NAME` не заводится (см. §0.2). Для закрытых правил первый сегмент `NAME` взаимно-однозначен с существующим `RuleCategory`.

### 2.2 Категория = `getCategory(): RuleCategory`, остаётся как есть

Категория — объявленный enum-атрибут, её потребители: `qmx rules --group` (`RulesCommand`) и exemption `architecture.*` от `exclude_paths`/`exclude_namespaces` (`NamespaceExclusionFilter`/`PathExclusionFilter`). Она **не** уровень адресации. Расходится с префиксом только у `computed.health → Maintainability` — этот producer вынесен в отдельный род (§3.2).

---

## 3. Реестр

### 3.1 Единая инстанция — валидатор и резолвер, не участник матчинга

Два существующих реестра (`ChannelDeclarationRegistryInterface`, `RuleChannelRegistryInterface`) сводятся к одной инстанции с узкими представлениями по потребителям. Авторитет отвечает на вопросы и хранит объявленные свойства; **матчинг остаётся строковым равенством** и в реестр не ходит.

```
Rule (производитель):
  name: string                       # полное имя правила, единственный литерал (NAME)
  category: RuleCategory             # объявлено getCategory(), для группировки
  supportsThresholdOverride: bool    # §4.1

Channel (владелец — Rule):
  violation: string                  # суффикс после имени правила
  acceptability: ChannelAcceptability  # §4.2
  shape: Occurrence | Magnitude(+direction)
```

Операции авторитета: существует ли имя; какой это уровень; какие каналы производит правило; `violationCode → ruleName` (для «did you mean»); принимаемость канала.

### 3.2 Открытые семьи — отдельный род

`computed.*` / `health.*` (один producer, два префикса, имя метрики произвольной глубины) не вписываются в трёхсегментную нотацию. Род декларации отдельный: имя метрики из конфигурации прогона, override не поддерживается (A10), принимаемость резолвится рантаймом. В общий матчинг не тащатся.

## 4. Свойства (отдельная задача)

### 4.1 `supportsThresholdOverride` (§1.3)

Признак «адресуем ли правилом через `@qmx-threshold`» — объявленное поле на правиле, а не вывод из наличия интерфейса у класса опций.

### 4.2 `acceptability` (§1.4)

Объявленное поле на канале: `AcceptableAsDebt | ConfigurationError`. Четыре канала `architecture.*` (`coverage`, `unreachable-layer`, `potential-shadow`, `empty-template`) переклассифицируются в `ConfigurationError`; пятый (`layer-violation`) — долг кода, не трогается. `ConfigurationError` влечёт эффективную severity не ниже `Warning` и не принимается ратчетом.

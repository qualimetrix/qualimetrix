# Протокол замеров

Числа в DoD пакетов P1 и P2 воспроизводятся этой процедурой. Скрипты намеренно
**не** лежат в репозитории: они одноразовые и не проходят PHPStan level 8, а
доводить их до этой планки — значит выдать черновик за поддерживаемый код.
Каждый — 20–30 строк, пишется заново за минуты.

## Вход

Синтетический снимок: взять `qmx-baseline.json` и размножить его записи с
различающимися ключами субъектов (подставляя сегмент неймспейса, чтобы длина
ключей осталась реалистичной). Коэффициент 100 даёт **125 512 записей, ~44 МБ** —
на нём получены все числа ниже.

## Замеры

| Что меряем                                     | Как                                                                             | Полученное значение                                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| База: нынешний путь чтения                     | `BaselineLoader::load()` на синтетическом снимке, `memory_get_peak_usage(true)` | **328,8 МБ, 2,25 с**                                                                 |
| P1: вклад индекса `bySelector`                 | то же после переноса индекса к `BaselineCleaner`                                | ожидается −72 МБ                                                                     |
| P2: построчный ридер, скан без удержания       | построчное чтение канонической формы, записи не удерживаются                    | **2,0 МБ, 0,42 с**                                                                   |
| P2: построчный ридер с удержанием всех записей | то же, но записи складываются в индекс                                          | 105 МБ на прототипе с вложенными массивами; с настоящими объектами оценочно 50–60 МБ |
| P2: размер                                     | построчная сериализация текущего файла                                          | **60 806 Б против 90 119 Б (67%)**                                                   |

Для загрузчика в отрыве от контейнера нужен тестовый двойник
`ChannelDeclarationRegistryInterface`: `declarationFor()` возвращает
`ChannelDeclaration::occurrence()` для каналов без величины и
`ChannelDeclaration::magnitude(WorseDirection::Higher)` для остальных.

## Открытый замер, с которого начинается P2

Раскладка внутри файла — см. таблицу двух расходящихся замеров в `PLAN.md`.
Мерить надо третий вариант, который не мерил никто: сохранить нынешнюю
группировку по субъекту, положив одну запись на строку.

## P2: сверка потолков до и после смены формы ключа (DoD 12)

Скрипт, как и остальные здесь, в репозитории не лежит — ниже процедура, по
которой он пишется заново, и полученный результат.

**Вход:** `2682106a:qmx-baseline.json` (v12, 264 группы в 199 субъектах) и
регенерированный `qmx-baseline.json` (v13).

**Нормализация ключа.** Ключ режется на логическую и файловую части по
**последнему** `@`; суффикс `#<n>` ищется только в хвосте после файловой части,
поэтому `#` внутри логической части (`{closure#N}`, `{anonymous#N}`) под него не
подпадает; из файловой части v12 снимается хвост `:<offset>`. Суффикс `#0`
приравнивается к его отсутствию.

**Сравнение — мультимножество**, а не множество: две записи, схлопнувшиеся в один
нормализованный ключ, обязаны дать расхождение кратности, а не совпадение.
Идентичность записи — (нормализованный ключ субъекта, канал, `occurrence`,
`edge`, `mode`), величина — `count` либо `magnitudes`. Записи `architecture.*`
сверяются отдельным мультимножеством **без** `occurrence`: их отпечаток берётся
от старой формы ключа объявления и пересчитан быть не может. В текущем ратчете
таких записей ноль.

**Негативный контроль.** Скрипт прогоняется против заведомо ослабленного снимка
(в копии v12 у одной записи поднят `count`, другая удалена) и обязан на нём
падать. Прогнан — падает, называя обе записи поимённо.

**Результат.** 261 из 264 записей переносятся без изменений. Расхождения:

| Запись                                            | Было | Стало    | Причина                                                                |
| ------------------------------------------------- | ---- | -------- | ---------------------------------------------------------------------- |
| `project:` `duplication.code-duplication`         | 36   | 32       | улучшение: восемь одинаковых сборок класс-записи сведены в один хелпер |
| `DependencyVisitor` `coupling.cbo`                | 20   | снята    | заменена точечным порогом 23 при raw 22                                |
| `VisitorFileEntryScope` `complexity.wmc`          | —    | 57       | новая: нумерация добавлена в тот же класс                              |
| `VisitorFileEntryScope` `size.method-count`       | —    | 21       | новая: там же                                                          |
| `VisitorMethodContext` `coupling.instability`     | —    | 0.894737 | новая: доставка индекса                                                |
| `ns:…\Measurement\Visitor` `coupling.instability` | —    | 0.92     | новая: то же на уровне неймспейса                                      |

Ни одно расхождение не вызвано формой ключа: все они — стоимость кода, который
P2 добавляет. Четыре оставшиеся новые записи — один кластер: нумерация легла в
`VisitorFileEntryScope`, который уже владеет лексическими стеками и реестром
проводных субъектов. Разбиение этого класса по предметам снимет их все и ждёт
решения владельца.

# Этап C — П2: перенос baseline по объявленной карте каналов

Канон — «Кандидат на форму переноса» раздела П1/П2 файла
`../X8-one-string-two-jobs/04-final-naming-step.md`.

## Что команда делает и чего не делает

Читает TSV-карту `старое имя канала → новое` и переписывает поле `channel`
записей `qmx-baseline.json` **без прогона анализа** и без обращения к коду
проекта. После заморозки (этап A) это подмена строки: `occurrence` не
пересчитывается, потому что пересчитать его из baseline нельзя в принципе.

Не трогает: ключи записей (субъекты), `occurrence`, `count`, `magnitudes`,
`mode`, `edge`, `scope`, `generated`.

## Решённые развилки

### Развилка 1 — инертные записи: перенос по сырому документу, с отчётом

`BaselineLoader` не отказывает на невалидной записи: она становится
`InertBaselineEntry` (ADR 0017). Цикл load → rewrite → save поэтому **молча
удалил бы** у потребителя каждую такую строку — потеря принятого долга под
видом переноса.

**Решение: команда переносит по сырому документу и не удаляет ничего**, а
строки, которые сегодняшний загрузчик считает инертными, называет в отчёте
числом и причиной. Отказ на инертных записях **не вводится** — это была бы
плата за чужую битую строку всем остальным.

Конверт читается сырым `json_decode`, не `CanonicalBaselineReader`: тот по
построению recogniser и на нераспознанной раскладке отвечает `null`.

### Развилка 2 — байтовая идентичность

Требование: перенос меняет **только** поля `channel`. Проверка «пустая карта →
`cmp` совпал» этого **не доказывает**: реализация, которая при пустой карте
просто не пишет файл, её проходит, а на непустой переформатирует документ
целиком.

**Несущий свидетель — непустой перенос:** на фикстуре с известным набором
записей посимвольно сравниваются исходный и результирующий документы, и
единственные отличия обязаны быть значениями полей `channel` тронутых записей.
Пустая карта и `cmp` остаются дополнительной, а не единственной проверкой.

Порядок записей: `BaselineWriter` сортирует записи внутри субъекта по коду
канала. Сырое переписывание порядок не трогает, поэтому после переименования,
меняющего относительный порядок, файл перестаёт быть каноническим до следующей
записи продуктом. Решение — **привести порядок к каноническому после
переписывания** и сказать об этом в документации; если исполнитель измерит, что
это ломает посимвольный свидетель выше, он докладывает противоречие, а не
выбирает молча.

### Развилка 3 — гарантии записи

Сырой путь **обязан нести те же гарантии, что `BaselineWriter`**: sibling-lock,
проверку неизменности файла с момента чтения (compare-and-swap) и atomic
rename. Реализация может отличаться, гарантии — нет. Без них перенос вносит
TOCTOU-гонку там, где остальные `baseline:*` её не допускают.

## Отказы

| ситуация                                                   | поведение                                      |
| ---------------------------------------------------------- | ---------------------------------------------- |
| версия файла ≠ `Baseline::VERSION`                         | отказ, называющий найденную и ожидаемую версии |
| конверт не разбирается (не JSON, не объект, нет `entries`) | отказ, файл не тронут                          |
| файл изменился между чтением и записью                     | отказ (CAS)                                    |
| два одинаковых `old` в карте                               | отказ                                          |
| `new`, равный какому-то `old` той же карты (цепочка)       | отказ                                          |
| `old === new` в одной строке                               | отказ                                          |
| два разных `old` → один `new`                              | отказ                                          |
| **результат переноса даёт две записи одной идентичности**  | **отказ, до записи** — см. ниже                |
| `old`, которого нет ни в одной записи                      | не ошибка — строка отчёта «ничего не задела»   |
| карта пуста или только шапка                               | успех, файл не изменён                         |

**Коллизия идентичности проверяется против содержимого файла, а не только
внутри карты.** `BaselineIdentity` — субъект + код канала + `occurrence` +
`edge`; у magnitude-каналов `occurrence` в записи отсутствует вовсе. Значит
перенос `old → new` может столкнуться с **уже стоящей** в файле, картой не
тронутой записью канала `new` под тем же субъектом. `BaselineLoader::separateDuplicates()`
демотирует в инертные **обе**, а `BaselineWriter::serializeEntries()` — тот
единственный страж, который сегодня такое отвергает, — сырым путём обходится.
Поэтому проверка результирующего множества идентичностей обязательна и
случается **до** записи.

**`new` не валидируется по реестру каналов.** П2 выходит релизом раньше П4,
значит новых имён в продукте ещё нет. Валидируется только форма строки. Это
ограничение называется в докблоке и в документации вслух.

## Контракт карты

Формат — `finding-gate/maps/channels.tsv`: `old<TAB>new<TAB>reason` с шапкой.
Классы гейта (`QmxFindingGate\Tsv`, `RenameMaps`) живут в `scripts/` и
**производственным автолоадом не видны** (`composer.json`: `psr-4` только
`Qualimetrix\` → `src/`). Переиспользовать их из команды нельзя, поэтому
формулировка «одна строка кормит гейт и перенос» понижается до проверяемой:
**формат совпадает, и совпадение пиннуется общим корпусом строк** — один набор
валидных и невалидных строк, по которому проверяются оба потребителя. Правила,
которые корпус обязан покрыть, снимаются исполнителем по `Tsv.php`/`RenameMaps.php`
(как минимум: несовпадающая шапка, краевой пробел и `\r`, `old === new`,
несколько строк на одно имя) — и это перечисление кладётся на диск.

Путь к карте — **аргумент команды**: `finding-gate/` потребителю релиза не
поставляется, и команда обязана принимать произвольный файл.

## Раскладка и CLI-контракт

- Предметная логика — `src/Analysis/Policy/Baseline/`: чтение и валидация
  карты, переписывание документа, отчёт. Владелец предмета — Baseline.
- Команда — тонкая, `src/Infrastructure/Console/Command/`, рядом с четырьмя
  `baseline:*` (adapter-exclusion, ADR 0022).
- **Регистрация обязательна и явна:** команды не сканируются автоматически —
  правится `src/Infrastructure/DependencyInjection/Configurator/OutputConfigurator.php`
  (там же зарегистрированы четыре существующих `baseline:*`).
- **Имя.** `baseline:migrate` занято отказом (команда снята,
  `BaselineMigrateCommandTest` утверждает её отсутствие). Предложение —
  `baseline:rename-channels` (верб + квалификатор под-объекта, случай
  `rebase-contracts` из `docs/internal/CLI_CONVENTIONS.md`).
- **CLI-сигнатура фиксируется планом, а не исполнителем:** позиционный аргумент
  `baseline` (путь к файлу, как у существующих команд), позиционный аргумент
  `map` (путь к TSV), `--format={text|json}` по конвенции. Коды возврата:
  `0` — перенос выполнен (в том числе «ничего не задето»), `1` — отказ по
  содержимому (версия, конверт, карта, коллизия), `2` — файл или карта
  недоступны. Исполнитель сверяет с прецедентом четырёх команд и докладывает,
  если прецедент говорит иначе.
- Новые классы перегенерируют манифест и `qmx.yaml` и двигают числитель
  `class-rank`; состав называется числом и именами в отчёте.

## Барьер, о который пакет споткнётся первым

`scripts/generate-modular-architecture-test-inventory.php` держит
`P6_C_BASELINE_PATHS_SHA256` — **пиннутый вручную дайджест набора путей тестов
Baseline**; несовпадение даёт жёсткий `fail`, а неизвестный путь под
`tests/Analysis/Policy/Baseline/` — `fail('Unclassified P6-C Baseline test
artifact')`. Первый же новый тест пакета роняет `check:artifacts`.

Пересчёт этой константы — **отдельный шаг пакета и ревью-решение, а не
перегенерация**: её формулировка («reviewed finite path digest») означает, что
набор тестов Baseline расширяется осознанно. Шаг называется в отчёте с новым
значением и списком добавленных путей.

## Тесты

- Успешный перенос: запись `old` получает `new`, всё остальное посимвольно
  идентично.
- Каждый отказ таблицы — свой кейс; каждый обязан оставлять файл **не
  тронутым** (проверяется содержимым файла, не только кодом выхода).
- Коллизия идентичности — отдельный кейс на файле, где `new` уже занят.
- Общий корпус строк карты — оба потребителя формата.
- Функциональный кейс через реальный `bin/qmx` (прецедент
  `BaselineMigrateCommandTest`).

## Проверка на реальном чужом baseline

Локально проекта-потребителя с готовым `qmx-baseline.json` нет
(`benchmarks/local-projects.json` отсутствует). Предлагается снять baseline
**текущим продуктом** с реального стороннего дерева в `benchmarks/vendor/`
(кандидат — `nikic/php-parser` или `symfony/console`) и прогнать по нему
перенос. Наружу — **только счётчики и формы, ни одной строки содержимого**
(правило №10 CLAUDE.md).

Утверждается:

1. изменились **только** поля `channel` сопоставленных записей, всё остальное
   посимвольно идентично;
2. число переписанных записей равно числу совпавших по карте;
3. пустая карта на том же файле даёт байтовую идентичность.

**Пункт «продукт грузит результат без инертных строк» из проверки убран.**
Он структурно недостижим для основного сценария: перенос на имя, которого в
продукте ещё нет, даёт ровно `InertEntryReason::UndeclaredChannel` — то есть
штатный исход обязан был бы провалить собственный DoD. «Структура переноса
корректна» и «сегодняшний продукт принимает результат» — разные утверждения, и
второе для будущих имён ложно by design. Загрузка проверяется отдельно и только
на карте, чьи `new` уже объявлены (тождественная карта `old → old` не годится:
она запрещена как `old === new`; годится фикстура из двух существующих каналов).

**Вопрос владельцу:** годится ли baseline с бенчмарочного vendor-дерева как
«реальный чужой baseline», или проверка должна ждать настоящего потребителя.

## Definition of Done

- Команда есть, зарегистрирована в `OutputConfigurator`, CLI-сигнатура и коды
  возврата — как выше.
- Все отказы таблицы покрыты кейсами, каждый оставляет файл нетронутым;
  коллизия идентичности отказывает до записи.
- Гарантии записи (lock, CAS, atomic rename) перенесены на сырой путь и
  покрыты кейсом на изменившийся файл.
- Несущий свидетель — **непустой** перенос с посимвольным сравнением; пустая
  карта — дополнительно.
- Общий корпус строк карты проверен обоими потребителями формата.
- `P6_C_BASELINE_PATHS_SHA256` пересчитан отдельным шагом, с новым значением и
  списком путей в отчёте.
- Проверка на чужом baseline выполнена (или отложена явным решением владельца
  строкой FOLLOWUPS).
- Документация EN+RU, README обоих предметов, CHANGELOG с предупреждением о
  селекторах.
- `composer check` целиком — у оркестратора; `composer gate -- --reference=main`
  GREEN.

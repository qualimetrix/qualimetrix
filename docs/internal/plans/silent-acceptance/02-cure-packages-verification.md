# Этап 02 — тестовый план, порядок исполнения и остатки

Владение файлами и пакеты P1–P11 — в `02-cure-packages.md` (P1–P5) и
`02-cure-packages-producers.md` (P6–P11). Здесь — §3–8: тестовый план,
порядок исполнения, методология перечисления мест, матрица «место × команда»
и остатки раунда числом.

## 3. Тестовый план — что именно проверяет тест каждого места

Один тест на место минимум; каждый строится парой «промах / заведомое
попадание», иначе доказывает не то (`00-overview.md`, дефект оракула).

| место  | что проверяет тест                                                                                                                                                                                                                                                                                                                                             |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Б1     | ключ, неизвестный всем форматтерам → exit 3 с перечислением известных; ключ чужого форматтера (`contributors` при `--format=json`) → exit 0 и вывод не изменился; `--all` не отказывает на собственном `violations`; перечислитель вызовов `getOption(`/`options[` покрыт объединением объявлений                                                              |
| Б2     | `rule:option` без `=` → exit 3; `rule:option=value` → прежнее поведение; форма без двоеточия отдаёт прежнее сообщение                                                                                                                                                                                                                                          |
| Б3     | авторский `--exclude=NoSuchDir` → находка warning; существующий → находки нет; **встроенный `node_modules` в дереве без него → находки нет**; обе формы Finder; прогон только с файловыми аргументами → находки нет; **полный `bin/qmx check`, а не только резолвер**                                                                                          |
| Б4, Б5 | привязка-0 → находка в дефолтном отчёте **полного прогона `bin/qmx check`**; эффект-0 без привязки-0 → находки нет, строка остаётся в `neverMatched`; `suppress_paths: []` → находки нет; находка не подавляется собственным паттерном; `--disable-rule` гасит её; перегон снапшота подавлений даёт пустой дифф                                                |
| Б6     | паттерн внутри привязанного селектора не указал ни на что → находка; селектор с несуществующим правилом → прежний exit 3; канал, не объявленный правилом, → по-прежнему молчит (объявленный остаток)                                                                                                                                                           |
| Б7, Б8 | несуществующий неймспейс/FQCN → exit 3; существующий и чистый → `No violations found.`, exit 0 — два ответа перестали быть одной строкой; glob-форма `--namespace` разрешается тем же матчером, что и фильтр                                                                                                                                                   |
| Б9     | несуществующий неймспейс → exit 3; существующий → прежний граф; проверка и отрисовка используют **один** матчер                                                                                                                                                                                                                                                |
| Б11    | clause, не исключившая ни одного класса у слоя, **который что-то поймал**, → находка warning; исключившая → находки нет; **слой, чей позитив не совпал ни с чем, находки не даёт**; `pending: true` слой пропускается; `resolveAll()` для исключённого класса по-прежнему `[]`, вывод `debug:layer-assignment` не изменился; `--fail-on=none` → exit 0, а не 2 |
| Б13    | подсказка при 0 файлов в диапазоне отличается от подсказки при N>0; вывод `--format=html` на той же паре байт-в-байт прежний; число доживает до подсказки после `with`-копии контекста; exit-код не изменился ни в одном из двух случаев                                                                                                                       |
| Н1     | `--log-level=zzz` → exit 3 с перечислением четырёх уровней; `--log-level=debug` → прежний объём лога                                                                                                                                                                                                                                                           |
| Н2     | незаписываемый путь → exit 3 на всех трёх командах-потребителях; тот же путь при `--no-cache` и `cache.enabled: false` → exit 0; отсутствующий записываемый каталог создаётся, exit 0                                                                                                                                                                          |
| Н3     | несуществующий FQCN → exit 3; реальный класс вне всех слоёв → прежние `(no layer)` и совет, exit 0                                                                                                                                                                                                                                                             |
| Н4     | префикс, не встретившийся ни в одной цели графа → находка warning; встретившийся → находки нет; наблюдаемое — находка, а не диффы метрик                                                                                                                                                                                                                       |

Сквозные проверки этапа: `bin/qmx rules` перечисляет каждый новый канал;
`bin/qmx directives` сохраняет коды 0/2/4 у пакетов, добавляющих канал в
`produced`; гейт красный только объявленным у каждого пакета, вводящего канал или
меняющего поверхность; полный `composer check` — на сведении (P11).

## 4. Порядок исполнения

```
01 (оракул, число «до»)
        │
        ▼
       P1
        ├──────┬──────┬──────┬───────────────┬──────┬──────┐
        ▼      ▼      ▼      ▼               ▼      ▼      ▼
       P2     P3     P4     P5              P6     P8     P9
        ├──────┤                             │      │      │
        ▼      │                             │      │      │
       P7      │                             │      │      │
        │      ▼                             │      │      │
        │     P10 ◄── P2, P3                 │      │      │
        └──────┴─────────────────────────────┴──────┴──────┘
                                 │
                                 ▼
        P11 (манифест, слои `qmx.yaml`, `declared-delta.tsv`, `mkdocs.yml`,
             help, полный check + selfcheck)
                                 │
                                 ▼
        03 (ADR, CHANGELOG, сайт, число «после», приёмка)
```

P10 идёт после P2 и P3 из-за двух общих файлов, а P7 — после P2 из-за одной
строки в `OutputConfigurator.php` (§1); ни то ни другое не про предмет. P6, P8 и
P9 параллельны между собой. Между P1 и P11 дерево красное по `architecture:check`,
`check:artifacts` и `check:self` у каждого из пяти пакетов, вводящих новый класс
(P2, P3, P4, P6, P7), и каждый из пяти несёт эту строку в «некомпенсировано».
Это цена решения «параллельные пакеты манифест и общие файлы не правят».

## 5. Чем получено перечисление и чего оно не видит

- **Читатели ключей `--format-opt`** — `grep -rn "getOption(\|->options\[" src/Reporting/`
  с отбросом `Template/node_modules`, плюс перекрёстная проверка литералами шести
  ключей. Результат — восемь вызовов, шесть ключей, четыре владельца: `json`
  (`violations`, `limit`, `top`, `rank-by` — `Json/JsonFormatter.php:259,263,299`,
  `Json/JsonOffenderSection.php:142`), `summary` (`rank-by`, `top` —
  `Summary/OffenderListRenderer.php:129,134`), `html` (`project-name` —
  `Html/HtmlTreeBuilder.php:57`), `health` (`contributors` —
  `Health/HealthTextFormatter.php:66`). **Не видит:** ключ, собранный из
  переменной или конкатенации; ключ, читаемый вне `src/Reporting/`; JS-шаблон
  HTML-отчёта.
- **Реализации `FormatterInterface`** — `grep -rln` по `src/Reporting/Formatter`;
  13 классов. **Не видит:** форматтер из другого дерева (таких нет).
- **Форматы, несущие текст находки** — `grep` на чтение списка находок
  (`getFindings`, `->findings`) по каждому `*Formatter.php`, затем ручная
  проверка трёх нулевых результатов: `html` читает через `HtmlTreeBuilder:63`,
  `text-verbose` делегирует в `TextFormatter`, `suppressed` не читает вовсе.
  Результат — не несут `health`, `metrics`, `suppressed`: **3 из 12**. **Не
  видит:** формат, добирающийся до находок через ещё один делегат.
- **Двери по командам** — `grep` по определениям опций в `Command/*.php`,
  `CheckCommandDefinition.php`, `BaselineCommandDefinition.php`: все шесть
  (`--namespace`, `--class`, `--format-opt`, `--log-level`, `--cache-dir`,
  `--exclude`) определены **только** в `CheckCommandDefinition`, кроме
  `--namespace`, который есть ещё у `graph:export`. То есть 32 унаследованные
  строки сводки этих дверей не касаются. **Не видит:** опции, добавляемые
  командой динамически.
- **Места конструирования `RunConfiguration`** — `grep -rn "new RunConfiguration("`:
  **2 в `src/`** (`RunConfigurationResolver:26`, `CheckCommand:247`) и **16 в
  `tests/`**. Именно этот счёт добавил `CheckCommand.php` в набор P6. **Не
  видит:** конструирование через фабрику или рефлексию (таких нет).
- **Команды-потребители `RunConfiguration`** — `grep -rln` по
  `src/Infrastructure/Console/Command/`: четыре (`check`, `directives`,
  `BaselineRun`, `debug:layer-assignment`). Потребителей
  `ConfiguredFindingExclusions` — две (`check`, `BaselineRun`). Отсюда матрица
  «место × команда» (`02-cure.md` §5). **Не видит:** будущую команду, которая
  начнёт читать те же корни.
- **Швы «анализ × проекция»** — `grep` по вызовам `->project(` и `->analyze(`:
  ровно два (`MeasuredFindingSet::run()`, `CheckCommand` + `FindingFilterOrchestrator`).
  На этом счёте стоит выбор шва P7. **Не видит:** шов, собираемый в тестах.
- **Потребители `MembershipResult`** — `grep`; один (`LayerRegistry:166`).
- **Собственная цена по конфигу** — `grep` по `qmx.yaml` плюс все 20 строк
  `inert.tsv`. **Не видит:** пресеты (`--preset=strict|legacy|ci`) — их
  `suppress_*` не проверялись; если пресет несёт непривязанный путь, находка
  появится у пользователя пресета. Это **непокрытый канал**, назван, а не закрыт,
  и вынесен строкой в остатки `02-cure.md` §8.
- **Тесты под риском** — `grep -rln` по `tests/`. **Не видит:** фикстуру, где
  значение собирается в коде теста, а не написано литералом.

- **Композиционные швы новых зависимостей** — `grep -n "register(" ` по
  `src/Infrastructure/DependencyInjection/Configurator/OutputConfigurator.php` и
  чтение конструкторов трёх объектов, которым пакеты добавляют зависимость:
  `FormatterContextFactory` (зарегистрирован **без аргументов**, `:333`),
  `ResultPresenter` (`:342`), `FindingFilterOrchestrator` (`:355`). Отсюда
  строки набора P2 и P7 и решение P3 не заходить в этот файл. **Не видит:**
  сервис, собираемый автовайрингом или компилятор-пассом, а не явной строкой.
- **Потребители `FormatterContext::$scopedReporting`** — `grep -rn` по `src/`
  с ограничением на `*.php`: девять вхождений в шести файлах
  (`FormatterContext.php:25,38,82`, `HtmlTreeBuilder.php:54,87,335,341`,
  `HtmlFormatter.php:28`, `SummaryFormatter.php:106`, `HintRenderer.php:58`,
  `FormatterContextFactory.php:30,105`). На этом счёте стоит решение «соседнее
  поле, а не замена» (`02-cure.md` §3.1). **Не видит:** чтение поля из шаблона
  HTML-отчёта — JSON-ключ `scopedReporting` в `Template/` подаётся строкой
  сборщика, и его имя раунд не трогает.
- **Модель регистрации late-продюсера** — чтение `UnusedDirectiveRule`,
  `AnalysisConfigurator.php:183-205` и `ChannelDeclarationCompilerPass.php:144,347`.
  Результат: продюсер — обычное тегированное правило, Options достаются
  коллаборатору через `RuleOptionsCompilerPass::optionsServiceIdForRule()`.
  **Не видит:** правило, регистрируемое не конфигуратором владельца.

## 6. Матрица «место × команда» и цена продюсера

`RunConfiguration` читают четыре команды, `ConfiguredFindingExclusions` — две.
Форма входа × команда — то, чего ни один пакет не покрывает целиком:

| место                | `check`          | `baseline:generate/update`                       | `directives`                                                           | `debug:layer-assignment` |
| -------------------- | ---------------- | ------------------------------------------------ | ---------------------------------------------------------------------- | ------------------------ |
| Б3 (`exclude:`)      | находка в отчёте | попадает в записываемый baseline                 | **не производится**: `auditDirectives()` не зовёт `reportedFindings()` | **молчит**               |
| Б4–Б6 (`suppress_*`) | находка в отчёте | **не производится** (решение, `02-cure.md` §4.3) | не производится                                                        | не производится          |
| Б11, Н4 (правила)    | находка в отчёте | попадает в baseline                              | в `produced`, вердиктов не меняет                                      | не применимо             |
| Н2 (`--cache-dir`)   | отказ 3          | отказ 3                                          | отказ 3                                                                | отказ 3                  |

**Названный остаток покрытия: 5 клеток** — `exclude:` под `directives` и
`debug:layer-assignment`, `suppress_*` под `baseline:*`, `directives` и
`debug:layer-assignment`. Причина одна: эти корни читают команды без отчёта о
находках; поднимать производство выше, к общему резолверу конфигурации, значит
заводить сигнал там, где его некому предъявить. Остаток идёт строкой в
«некомпенсировано» P6 и P7 и в границу притязаний раунда. Обратное верно для Н2:
`CacheConfigurationResolver` зовут три места (`CheckConfigurationResolvers`,
`BaselineRun`, `AnalysisPreflight`), а через последнее — `directives` и
`debug:layer-assignment`; одна дверь закрывается сразу на четырёх командах, и это
единственная такая в раунде.

**Инвариант, который матрица обязана сохранить:** коды 2 и 4 у
`bin/qmx directives` (их читает `composer directives:audit`) — новый канал в
`produced` не двигает ни один директивный вердикт (DoD P8, P9; у P6 канала в
`produced` нет вовсе, и его прогон `directives` — чистая проверка на регрессию).
**Цена одного нового продюсера, файлами:** класс правила + Options + константа
канала + строка в конфигураторе владельца + строка DI, если у продюсера есть
коллаборатор + дельта манифеста + строка в `qmx rules` + страница
`website/docs/rules/{группа}.md` (EN и RU) + кейс в `finding-gate/cases/`.

## 7. Б6: три координаты промаха, охвачены две

| координата                                                     | что сегодня                                                                    | раунд                  |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------- |
| селектор `rules.<имя>` — несуществующее правило                | отказ 3 (X13, 23 позиции)                                                      | не трогаем             |
| паттерн внутри привязанного селектора                          | молчит                                                                         | **лечим** (Б6)         |
| канал в `suppress_namespace_channels`, не объявленный правилом | молчит: `RuleNamespaceExclusionProvider:108` проверяет только непустоту строки | **остаток, 1 позиция** |

Привязка-0 для Б6 определена как «паттерн не указал ни на что» при привязанном
селекторе, то есть по второй координате; совместная пара и третья координата в
раунд не входят. Значения продюсер читает из реестра опций правил
(`RuleConfigurationInterface`), а не из `RuleExclusionLedgerAttributor` — тот
остаётся нетронутым. **Чем получено:** чтением `RuleNamespaceExclusionProvider` и
`RuleExclusionLedgerAttributor`. **Не видит:** координату, добавляемую опцией
правила, которую эти два класса не разбирают.

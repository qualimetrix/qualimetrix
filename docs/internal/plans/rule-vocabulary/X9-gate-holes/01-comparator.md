# Этап A — компаратор объявляет корневой ключ и значение поля отчёта

Три пакета. А1 — правка компаратора и его проверок. А2 — прогоны оркестратора.
А3 — ретро-доказательство Э2 с временными строками карт.

## Разведанная механика (адреса проверены разведкой Х9)

- `inputs.tsv` применяется **назад** к входу референса: к CLI-аргументам
  (`TreeRun::forCase()`, `TreeRun.php:48`) и полнотекстово к `qmx.yaml` кейса
  (`TreeRun::configurationArgument()`, `TreeRun.php:194-211` — reverse по
  regex-паттерну строгих границ имени, изменившийся текст уходит во временный
  файл `-c`).
- `assertWholeInputToken()` (`RenameMaps.php:946-969`) принимает три формы:
  `rule:option-key`, `--flag`, точечное имя продюсера. `$dottedName` требует
  хотя бы одну точку; `exclude_paths` не подходит ни под одну.
- Карты к артефактам применяются **вперёд** к тексту референсного вывода до
  нормализации (`Gate.php:1108`); ограничение по поверхностям —
  `RenameMaps::SURFACES` (`RenameMaps.php:138-140`), сейчас только
  `METRIC_KEYS => ['format:json','format:metrics','format:html']`.
- Staleness: `replace()` инкрементирует `hits`, `staleRows()` требует
  срабатывания каждой строки, `Gate::checkStaleMaps()` даёт `MAP_STALE`.
- Референс `730941c1` на неизвестный корневой ключ даёт
  `ConfigLoadException` → exit 3; на неизвестный **per-rule** ключ —
  предупреждение и молчаливое неприменение подавления (запись Х2 FOLLOWUPS).
  Корпус держит per-rule `suppress_paths`/`suppress_namespaces` в кейсе
  `rule-exclusion-ledger` — перевод обязан накрывать оба уровня.

## Пакет А1 — четвёртая форма и пятая карта

Набор файлов: `scripts/finding-gate/RenameMaps.php`,
`scripts/finding-gate/SelfTest.php`, `scripts/finding-gate/Surfaces.php` (если
понадобится), `scripts/finding-gate-controls/Controls.php`,
`finding-gate/README.md`, `finding-gate/maps/report-values.tsv` (новый, только
заголовок), правки заголовков-комментариев других `maps/*.tsv` не входят.

### Решение 1: четвёртая форма входного токена — ключ в написании документа

Токен — `exclude_paths:` **с двоеточием**: написание, которым YAML-документ
адресует ключ. Свойства, ради которых выбрана эта форма:

- отличима от «ключа опции без правила»: голое слово без двоеточия
  по-прежнему отвергается, и существующий отказ сохраняет свой смысл;
- отличима от `rule:option-key`: у той формы до двоеточия стоит точечное имя
  правила и после двоеточия непустой ключ;
- полнотекстовая подстановка по `key:` ловит корневой и per-rule уровень при
  любом отступе и не может сработать внутри флага (`--suppress-path` без
  двоеточия) или внутри значения `--rule-opt=rule:option=value` (там ключ
  не в позиции `key:` YAML — проверить контрпримером в self-test).

Контракт (псевдо):

```php
// RenameMaps::assertWholeInputToken(): четвёртая форма
'a configuration key as a document writes it' => '~^[A-Za-z0-9][A-Za-z0-9_-]*:$~'
// ... implementation details
```

Обязанности исполнителя сверх формы:

- выяснить и назвать в отчёте, применяются ли inputs-строки **вперёд** к
  артефактам (`buildSubstitutions()`), и если да — проверить, что написание
  `suppress_paths:` не встречается ни в одной сравниваемой поверхности
  (stderr-отказы, тексты ошибок), либо ограничить новую форму входными
  поверхностями явно;
- докблок `assertWholeInputToken()` и раздел README о четырёх формах.

### Решение 2: пятая карта — значение перечислимого поля отчёта

Новый файл `finding-gate/maps/report-values.tsv`, схема `old → new → reason`.
Предмет — строковое значение перечислимого поля отчёта. Применение — только
вперёд, только к `format:suppressed` (запись в `RenameMaps::SURFACES`),
подстановкой значения в кавычках `"old"` → `"new"` (по образцу keyRole-ветки
`buildSubstitutions()`, `RenameMaps.php:612-634`) — значение поля, а не
подстрока произвольного текста.

- Форма строки: плоский kebab-токен (`[a-z0-9-]+`), отказ на `#`, `:`, `--`,
  точку — чтобы строка этой карты не могла нести чужую роль.
- `FILES[REPORT_VALUES] = false` (не reversible), staleness — как у остальных.
- Порядок `mechanisms` (массив в порядке `cases()`) на `730941c1` и HEAD
  совпадает — сверено оркестратором; перестановку карта не выражает, и
  README называет это ограничением вслух.

### Проверки А1 (self-test и контроли)

Self-test: четвёртая форма принимается; голое слово без двоеточия отвергается
прежним текстом; `rule:option` матчится первой формой, а не четвёртой;
`--rule-opt`-контрпример из Решения 1; загрузка/дубли/staleness
`report-values.tsv`; отказ строки пятой карты не-kebab формы.

Контроли (`Controls.php`), по одному на дыру:

- переименовано значение `SuppressionMechanism` в клоне без строки пятой
  карты → ожидаемый `SURFACE_MISMATCH` на `format:suppressed`;
- переименован корневой ключ конфигурации в клоне без строки `inputs.tsv` →
  исполнитель фиксирует фактический класс отказа (кандидатский бинарь
  отвергает корпусный конфиг — вероятно `RUN_FAILED`) и ожидает именно его.

DoD А1: `composer gate:self-test` зелёный; оба новых контроля включены в
общий список; README описывает обе формы и жизненный цикл строк; никакие
строки карт не добавлены (файлы карт — заголовки).

## Пакет А3 — ретро-доказательство Э2 (`reference=730941c1`)

Диапазон `730941c1..HEAD` несёт `89b952fb` (judged-строки `qmx rules`),
поэтому кроме строк карт нужна **пере-выведенная** объявленная дельта
`tree|rules` относительно `730941c1`.

Шаги (исполняет оркестратор или один агент под его прогоном; коммиты — два):

1. Коммит «строки доказательства»: в `inputs.tsv` — три строки
   `exclude_paths:` → `suppress_paths:`, `exclude_namespaces:` →
   `suppress_namespaces:`, `exclude_namespace_channels:` →
   `suppress_namespace_channels:`; в `report-values.tsv` — четыре строки
   `path-exclusion → path-suppression`, `namespace-exclusion →
   namespace-suppression`, `rule-namespace-exclusion →
   rule-namespace-suppression`, `rule-path-exclusion →
   rule-path-suppression`; дельта `tree|rules` через
   `--derive-declared-delta` (режим — запись, exit 4) с причиной,
   унаследованной от снятой в `e7d8c9ae` формулировки.
2. Прогон `composer gate -- --reference=730941c1` с логом в файл. Ожидание —
   GREEN; каждая строка карт обязана сработать (иначе MAP_STALE — и это
   правильный сигнал, а не помеха). PARTIAL не является свидетельством.
   Красный по непредвиденной поверхности — стоп и разбор, не подгонка карт.
3. Коммит «снятие доказательства»: строки карт и дельта удаляются в
   коммите-соседе; GREEN-лог и его итоговая сводка — в запись FOLLOWUPS
   (`followups/a3.md`), закрывающую «Чем доказана эквивалентность находок
   Э2» и обе записи о дырах. Дерево строк не сохраняет — следующий прогон
   с пост-Э2 референсом переписал бы reverse'ом живые ключи в отвергаемые.

DoD А3: лог GREEN-прогона существует и процитирован в followup-записи;
`git log` показывает пару коммитов «строки → снятие»; финальное дерево
держит пустые карты и не держит дельты; `composer gate -- --reference=main`
после снятия — GREEN.

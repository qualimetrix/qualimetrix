# Этап C — три слепых пятна словарного аудита

Три независимых пакета с непересекающимися наборами файлов.

## Пакет C1 — ключ метрики внутри строки языка выражений

Самый дешёвый: AST-обход уже существует
(`ComputedMetricExpression::keysOf()`/`accesses()`,
`src/Analysis/Evidence/ComputedMetrics/Contract/Evaluation/ComputedMetricExpression.php:165-234`),
недостаёт сверки с каталогом: `ComputedMetricFormulaValidator::validate()`
(`src/Analysis/Evidence/ComputedMetrics/ComputedMetricFormulaValidator.php:31-37`)
проверяет ссылки `health.*`/`computed.*` друг на друга и не проверяет
каталожность остальных ключей.

Набор файлов: `ComputedMetricFormulaValidator.php` и его тесты; при
необходимости — сосед по каталогу для доступа к ключам `MetricName` (новый
файл внутри предмета допустим); докблок
`JudgedMetricDeclarationGuard.php` п.6 (если формулировка «no build-time pass
can see its keys at all» перестаёт быть правдой — поправить);
`CHANGELOG.md`; `followups/c1.md`.

Контракт: пятая проверка валидатора — каждый адресуемый ключ формулы, не
начинающийся с `health.`/`computed.`, обязан существовать в каталоге с учётом
агрегатных суффиксов (`avg, count, max, min, p5, p95, sum`); отказ называет
ключ и формулу. Путь один и общий: встроенные формулы и пользовательские
`computed_metrics:` идут через `ComputedMetricsConfigResolver::resolve()` →
тот же валидатор — исполнитель проверяет это утверждение исполнением, а не
чтением.

Тестовый план: валидный каталожный ключ проходит; опечатка отказывает с
именем; `health.*`/`computed.*` не задеты; агрегатный суффикс принимается;
несуществующий суффикс отказывает. Прогон `bin/qmx check src/` и корпусного
кейса `health` — поведение на валидных формулах не изменилось.

Замечание границы: это новый отказ на невалидный вход — поведение продукта
меняется только там, где раньше молча возвращался null. `Changed`-строка в
CHANGELOG, гейту изменение невидимо (корпус держит только валидные формулы) —
сказать это в followup-записи вслух.

## Пакет C2 — ключи метрик, написанные руками в JS шаблона

Набор файлов: `src/Reporting/Template/**` (src и tests), возможный новый
скрипт населения, `followups/c2.md`. Правки PHP-стражей в пакет не входят.

Шаг 1 — популяция **читателем того же языка**: разобрать `.js` парсером
(в `node_modules` шаблона уже есть AST-инструментарий сборки; выбор парсера —
за исполнителем), собрать строковые литералы, равные ключу каталога или
`ключ.суффикс`, отдельно код и отдельно комментарии/тесты. Таблица на диск
(`X9-gate-holes/enumeration-js-metric-keys.tsv`) со строкой «чем получено и
чего не видит» (шаблонные строки, конкатенация, динамические ключи).
Разведка Х9 дала текстовую оценку: ~8 боевых мест в 4-5 файлах
(`size.loc.sum` ×5, `maintainability.mi.avg` ×1), вторая копия каталога
подсказок в `hints.test.js`; таблица пакета обязана её пересдать, а не
унаследовать.

Шаг 2 — развилка по измерению (обе цены в отчёте, выбор называется):

- ключи уезжают в модуль, генерируемый из `MetricName`, шаблон его
  импортирует — рассогласование ловит сборка бандла;
- страж по тому же читателю (vitest-тест со списком, снятым из PHP-артефакта)
  — написание остаётся рукописным, ловит тест.

Шаг 3 — реализация выбранной развилки, `composer test:js` и
`composer build:js` зелёные.

Вынесено владельцу (решение на ревью плана, не самовольно): `test:js` не
входит ни в `composer check`, ни в CI — любой страж из развилки 2 не будет
исполняться нигде, кроме рук. Предложение пакета: включить `test:js` в
`check:code` с измеренной ценой по времени.

## Пакет C3 — две половины вселенной каналов складываются одной командой

Набор файлов: `scripts/generate-rename-enumeration.php`, `composer.json`
(новый скрипт-алиас), докблок
`src/Infrastructure/DependencyInjection/CompilerPass/ChannelDeclarationCompilerPass.php:90-97`
и/или `JudgedMetricDeclarationGuard.php` (формулировка «по времени
разрешения»), статическое перечисление
`X8-one-string-two-jobs/enumeration-channels.tsv` (колонка/шапка «эта таблица
о статической половине»), `followups/c3.md`.

Контракт: одна команда печатает обе половины и сумму — статическая (52) из
своего артефакта, рантайм (6 builtin + observed) из своего, без слияния
файлов: у половин разное время разрешения, и слияние соврало бы о том, когда
канал известен. Докблок третьей проверки ADR 0046 называет, что
runtime-половина не покрывается ею **по времени разрешения**, а не по
недосмотру.

DoD: команда существует и её вывод процитирован в followup-записи; числа
не повторены прозой в докблоках (адрес канона — артефакты).

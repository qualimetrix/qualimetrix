# П4. Команда

Пакет делает ответ доступным человеку и машине. Логики вердикта здесь нет ни
строки — адаптер, две проекции одного отчёта и проводка. CI в следующем пакете:
включать enforcement можно только после того, как измерена его цена.

## Поверхность

```
bin/qmx directives [paths...] [--config=…] [--format=text|json]
```

Имя верхнеуровневое. `CLI_CONVENTIONS.md` даёт критерий буквально: команда,
принимающая исходный код и производящая аналитический вывод, — верхнего уровня;
`noun:verb` — для управления подсистемой. Эта принимает пути ровно как `check` и
гоняет полный конвейер. Прецедент рядом — `qmx rules`. Первая редакция плана
ссылалась на несуществующую формулировку конвенций; ссылка исправлена, а не
подпёрта.

Коды возврата берутся у `CheckCommand`, а не изобретаются:

| код | значение                                  |
| --- | ----------------------------------------- |
| 0   | ни одной `Inert` и ни одной `Overrun`     |
| 1   | найдены `Inert` или `Overrun`             |
| 2   | негодный ввод (`Command::INVALID`)        |
| 3   | ошибка конфигурации (`EXIT_CONFIG_ERROR`) |

`Unmeasured` кода возврата не двигает: это отсутствие ответа, а не долг.

Текстовый отчёт: шапка с охватом, признаком полноты охвата и селекцией (если
она не пуста), затем строка на директиву — путь, строка, форма, адресат,
вердикт, а для `Unmeasured` причина и, для `Masked`, перекрывающая директива.
Итог четырьмя числами.

JSON — тот же отчёт документом; обе проекции читают один `DirectiveAuditReport`.
На ошибке в JSON печатается конверт `{error, exit_code}`, как у
`debug:layer-assignment`: машинный потребитель всегда находит валидный JSON и
различает ошибку по форме, а не по коду.

Оговорки печатаются фактами отчёта, а не дисклеймером: охват и полнота (О2),
`Unmeasured` с причиной (О3), О1 — в справке команды.

## Размещение

- `src/Infrastructure/Console/Command/DirectivesCommand.php`. Не в `Debug/`:
  команда не диагностика внутренностей, а обслуживание собственных аннотаций
  проекта.
- Регистрация: `#[AsCommand]`, запись в карте `bin/qmx`, регистрация сервиса в
  конфигураторе Infrastructure рядом с остальными командами — автоконфигурация
  на команды не распространяется, они перечислены явно.
- Зависимости: `DirectiveAuditInterface`, `RunConfigurationResolverInterface`,
  `ConfigurationInputAdapter`, `RuntimeConfigurator`, валидаторы ввода — тот же
  набор, что у `debug:layer-assignment`. Команда **импортирует типы вердиктов
  Inline**, потому что печатает их поля; утверждения «в Analysis не заглядывает»
  в плане больше нет — оно было неверным по составу отчёта.

## Документация

- `website/docs/usage/cli-options.md` и `.ru.md` — обе версии одновременно.
- `CHANGELOG.md`, раздел `Changed`, одной строкой от лица пользователя.
- ADR: решения D3 (почему отдельный контракт, а не поле результата и не порт),
  D5 (почему вердиктов четыре) и D6/D7 (почему коалиция и неполный охват — не
  инертность). Из кода эти три не выводятся.
- README `src/Infrastructure/`.
- `composer docs:check` в новом worktree требует `QMX_MKDOCS=<основной
  checkout>/website/.venv/bin/mkdocs`.

## Тестовый план

- Функциональный на фикстуре: `--format=text` и `--format=json` одного прогона
  согласованы по составу вердиктов.
- Коды возврата: `0` без долга, `1` при `Inert`, `1` при `Overrun` без единой
  `Inert` (иначе `Overrun` попадает в отчёт, но не в гейт), `2` на негодном
  формате, `3` на нечитаемом конфиге.
- `Unmeasured` не роняет код возврата — отдельным тестом, потому что это ровно
  то место, где легко перепутать «нет ответа» с «долг есть».
- Команда, зарегистрированная в `bin/qmx`, но не в контейнере, падает явно.

## Definition of Done

- Команда есть в `bin/qmx --help` и исполняется на нашем дереве; результат по
  `src/` разобран: каждая `Inert` и каждая `Overrun` объяснена **механизмом**, а
  не фактом исчезновения находки — главный урок Х1.
- Обе языковые версии документации обновлены; `composer docs:check` — exit 0.
- ADR написан, `CHANGELOG.md` дополнен.
- **Манифест**: декларация команды и рёбра `Infrastructure.Console →
  DirectiveAuditInterface` и `→` типы вердиктов Inline внесены.
- Новые `.md` плана вписаны в список классификации
  `scripts/generate-modular-architecture-production-inventory.php`.
- `composer check` — exit 0; `composer gate -- --reference=<коммит П3>` — GREEN.
- Коммит и полная цепочка до начала П5.

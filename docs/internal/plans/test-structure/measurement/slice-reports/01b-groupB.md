## Control candidates

- **Exclusion/ConfiguredSuppressionTest.php::itIsTheOnlyPlaceInSourceThatReadsASuppressionOptionKey**
  (lines 77–103) — a pure **control-invariant**: it walks all of `src/` with reflection/regexp and
  asserts that exactly one file (`ConfiguredSuppression.php`) reads the `suppress*` key. It
  doesn't check a specific class's behavior — it checks the code's layout across the whole tree. A
  candidate for moving out of the tests into a separate architecture guard (similar to
  `composer architecture:check`), or an explicit owner decision to leave it as is.
- **ThresholdValidatorAssignmentTest.php** (both tests) — a borderline case: it walks 9
  `src/Analysis/Evidence/*` directories via `RecursiveDirectoryIterator`, finds `*Options.php`
  classes via a regexp over the source, then checks a **behavioral** contract via reflection
  (`getOverrideValidator()` returns the right type). This isn't a layout invariant (not about
  documentation/generated artifacts), but "the invariant is taken from every class in an src/
  subset via reflection" — it fits the control-invariant subtype from the brief, but it checks
  real behavior (which validator comes back), not a layout fact. Owner's decision.

## Duplicates and contradictions

- **FindingTest.php: `itGetFingerprintForMethod` / `itGetFingerprintForClass` /
  `itGetFingerprintForNamespace` / `itGetFingerprintForFile` / `itGetFingerprintForGlobalFunction`**
  (lines 28–123) — five twin tests with differently worded names, but `getFingerprint()` doesn't
  depend on `symbolPath` at all (confirmed by the neighboring test at line 245–268). There is one
  real regression guard here, not five; four of the five are ballast disguised as coverage of five
  different scenarios.
- **AnalysisContextThresholdTest.php: `itGetThresholdOverrideRespectsLineScope` /
  `itMethodLevelOverrideTakesPriorityOverClassLevel` / `itBoundedOverrideWinsOverUnbounded`** —
  the comments describe line-based behavior ("line 30 inside both ranges"), but the actual
  `subject` passed to `getThresholdOverride()` is the same in every call within each test and
  carries no line number; the repeated assertions (`itGetThresholdOverrideRespectsLineScope` calls
  the same method 5 times with the same result) never vary the input — the scope boundary itself
  is never demonstrated, the comment describes implementation logic (which of the overlapping
  `ThresholdOverride` entries wins by `span`/`ControlScope`), not what the test actually varies.
- **PathExclusionFilterTest.php ↔ NamespaceExclusionFilterTest.php** — not a duplicate (different
  SUTs), but the mirrored test structure and private helpers (`declaredFileScope()`,
  `declaredProjectScopedChannelKeys()`, `createChannelFinding()`) are copied 1:1 between the
  files. A candidate for a shared trait/abstract test case when a third such filter appears.
- **LocationTest.php::itNoneCreatesLocationWithoutFile ↔
  LocationNullFileTest.php::itLocationNoneCarriesNullFile** — both create `Location::none()` and
  check the same set of properties (`file === null`, `isNone()`, `pathString() === ''`,
  `toString() === ''`). `LocationNullFileTest` is a separate file under ADR 0015 Phase 1a and adds
  3 cases of its own (a constructor with `null`, a normal file, `line` without a file), so not a
  pure duplicate, but the overlap is nearly complete — a candidate for merging into `LocationTest`.

## Assumptions

- Placement (the "correct directory" column) was checked with a grep over `src/` only for
  explicit class owners; it was not verified with `composer architecture:check` (running tools is
  forbidden by the task's scope).
- The "control-invariant" assessment rests on the brief's definition ("the invariant is taken
  from ALL src/ classes via reflection") — `ThresholdValidatorAssignmentTest` formally scans a
  subset (`*Options.php` in `Evidence/*`), not all of `src/`; the decision on whether to count a
  partial walk as the same class as a full one is left to the owner.
- A background subagent, originally launched on group 4 (the last 8 files), crashed on a 429 API
  rate limit; these 8 files were read through and analyzed directly by the same (orchestrating)
  agent, without loss of analysis depth.
- No repository files were changed; `git`/`composer`/PHPUnit/`bin/qmx` were never run — reading
  only (Read/grep/find).

# П2. Пороговая половина и шов, через который её видно

Пороговая директива не отвечает на вопрос «сработала ли» ничем наблюдаемым:
спросить правило, что оно решило, некому — шов Ш7 отменён, единого понятия
границы у слоя правил нет. Наблюдаема только **разность исходов**: исполнить
правила с директивой и без и сравнить произведённое.

## Что делает пакет

1. Перегенерирует популяцию `@qmx-threshold` (`composer enumeration:directives`)
   заново, а не наследуя таблицу Х1.
2. Заводит в `Analysis\Policy\Inline` контрфактический аудит пороговых директив,
   включая разбор коалиций и вердикт `Overrun`.
3. Открывает подготовленную стадию прогона аудиту — внутренним шагом
   `AnalysisPipeline`, без публичного контракта Run: его читатель появляется
   только в П4.

Команды здесь нет — она в П4. Контролей нет — они в П3. Узкого прохода нет — он
в П5.

## Контракты

`Analysis\Policy\Inline\Contract\Directive`:

```
final readonly class ThresholdDirectiveAuditInput {
    public AnalysisContext $baseline;          // контекст, на котором прогон уже отработал
    public RuleExecutionInterface $executor;   // тот же исполнитель
    public RuleExecutionResult $baselineResult; // произведённое первым исполнением
}

interface ThresholdDirectiveAuditInterface {
    /** @return list<DirectiveVerdict> */
    public function verdicts(ThresholdDirectiveAuditInput $input): array;
}
```

Базовый результат приходит во входе, а не снимается лишним проходом. Знание о
выключенности продюсера берётся из тех же `RuleSelector` и
`RuleConfigurationInterface`, что уже инъектированы в `DirectiveUsage`, —
инъекцией, и **утверждения о «чистой функции от двух аргументов» в плане больше
нет**: оно было неверным по составу того, что нужно для вердикта.

`Analysis\Run` — **внутренний** шаг пайплайна, без публичного контракта: его
единственный будущий читатель, команда, появляется в П4, а запись потребителя,
которого ещё нет, проверяющий манифеста отвергает
(`unused contract consumer entry`). Поэтому в П2 пайплайн получает метод и
возвращаемое значение как внутренние типы; контракт `DirectiveAuditInterface`
объявляется в П4 вместе с командой, и тогда же типы вердиктов Inline
повышаются до контракта.

Форма возвращаемого значения, которая в П4 станет контрактом:

```
final readonly class DirectiveAuditReport {
    /** @var list<DirectiveVerdict> */ public array $verdicts;   // обе половины
    public AnalysisCoverage $coverage;
    public RuleSelection $selection;
    public int $producedFindings;
}

interface DirectiveAuditInterface {
    public function auditDirectives(
        RunConfiguration $configuration,
        ?FileDiscoveryInterface $discovery = null,
    ): DirectiveAuditReport;
}
```

`AnalysisPipeline` получает второй вход; внутри выделяется приватный шаг
«подготовленный прогон», возвращающий собранный контекст и результат первого
исполнения. `analyze()` и `auditDirectives()` зовут его одинаково. Отдельного
публичного типа для шага нет — он не пересекает границу владельца.

**Контракт Inline пайплайн читает через `RuleProducerPreparation`, а не сам.**
Тот же посредник уже задаёт капабилити второй, послеисполнительный вопрос
(`auditInlineDirectives()`), так что аудит приезжает туда, где половина ответа
уже живёт, — и это первая причина. Вторая измерена: конструктор
`AnalysisPipeline` принят ратчетом ровно на десяти параметрах
(`qmx-baseline.json`, `code-smell.constructor-overinjection`, magnitudes `[10]`),
при `warning=8 error=12` у правила. Любой одиннадцатый аргумент — новая находка
выше принятого потолка, то есть красный `selfcheck --fail-on=warning`, а
двенадцатый ещё и error. Поэтому пайплайн новых зависимостей не получает вовсе:
`ThresholdDirectiveAuditInterface` инъектируется в посредник, и он же отдаёт
селекцию для шапки отчёта.

Подавляющая половина приходит в отчёт через операцию, которую
`InlineDirectivePolicyInterface` получает **здесь**, вместе со своим первым
читателем:

```
/** @return list<DirectiveVerdict> */
public function directiveVerdicts(array $producedFindings): array;
```

Тем же пакетом типы вердиктов переезжают из `Directive/` в `Contract/Directive/`
и получают поля, которые заполняет эта половина (`maskedBy`,
`boundaryObservable`). Run во внутренности Inline не лезет.

## Метод и его границы

- **Leave-one-out поверх переиспользованного контекста.** `AnalysisContext` —
  `final readonly` с публичным `array $thresholdOverrides`, метрики, граф и
  дерево неймспейсов переиспользуются, повторный сбор не нужен.
- **Единица снятия — авторская директива.** Снимаются **все** записи группы
  разом; ключ группы тот же, что у `authoredThresholdOverrides()`. Снятие первой
  записи вместо группы — ошибка, которую поштучные контроли П3 обязаны ловить
  отдельным свидетелем.
- **Отпечаток несёт код канала, субъект, severity, величину, границу и
  сообщение.** Различие «сдвинулась только граница» не выбрасывается, а
  становится вердиктом `Overrun`: severity совпала, граница разъехалась, находка
  осталась — значит директива применена, но обещанного послабления не дала.
  Это воспроизводит измерение Ш8, а не спорит с ним.
- **Коалиции.** Директива, получившая `Inert`, проверяется структурно: есть ли
  другая директива того же правила, привязанная к тому же субъекту. Механизм
  перекрытия: классовая директива даёт привязки со `ControlScope::Class_` на
  классе и на каждом методе (`DeclarationControlBindings:278-281`), методная —
  `Callable`, а `getThresholdOverride()` выбирает одну по специфичности; при
  совпадающем вердикте снятие любой поодиночке невидимо.

  **Перекрытие проверяется только там, где канал отчитывается.** Пересечение
  привязок само по себе доказывает возможность маскирования, а не факт: на
  субъекте, где правило не производит находки вовсе, маскировать нечего, и
  `Masked` там был бы ложным — это нашли оба ревьюера второго раунда
  независимо. Поэтому перекрытие ищется на субъектах, на которых базовый прогон
  произвёл находку этого правила; их даёт `baselineResult`, дополнительного
  прохода не нужно.
- **Судим по `produced`.** О1; универсум единый с подавляющей половиной (П1).
- **Копию политики не трогаем.** О4: диагностики `InlineDirectiveValidator`
  одинаковы на всех проходах и в разность не входят. В докблок контракта.
- **Выключенный продюсер.** О3: прохода не делается, вердикт
  `Unmeasured / ProducerDisabled`.
- **Охват.** D7: признака «полный охват» нет и вычислить его не из чего —
  `RunConfiguration` хранит уже разрешённые пути. Вердикт относителен
  проанализированному охвату по построению, охват печатается в шапке отчёта, а
  неполнота **прогона** (`ReportCoverage::isComplete()`) — отдельный сигнал,
  который команда переиспользует кодом возврата `4`.
- **Граница наблюдаема не везде (О5), и признак снимается с находок, а не со
  списка имён.** `enumeration-boundary-publication.tsv`: девять из двадцати
  семи правил не кладут границу в находку, и четыре из них оверрайд
  поддерживают — `UnreachableCodeRule`, `DataClassRule`, `GodClassRule`,
  `CodeDuplicationRule`. Захардкодить эти четыре имени в продукт значило бы
  внести рукописный список, который разъедется с деревом молча, поэтому
  `boundaryObservable` вычисляется из базового прогона:

  > **ложь ровно тогда**, когда находка адресуемого правила сработала на
  > субъекте, который директива покрывает, и пришла с `threshold === null`.

  Пустое множество таких находок даёт `true` вакуумно, и это верно по существу:
  если правило на покрытых субъектах не отчиталось вовсе, обещанию нечего было
  не сдержать, и `Inert` там достоверен.

  **Вердикт при `boundaryObservable = false` зависит от исхода, а не остаётся
  `Effective`.** Первая редакция этого пункта утверждала обратное; механизм
  говорит иначе. Отпечаток у такой находки не несёт границы, поэтому поднятие
  порога, которое величина уже прошла, даёт **совпадающий** отпечаток — то есть
  `Inert`, а не `Overrun` и не `Effective`. `Effective` эти правила получают
  тогда же, когда все прочие: когда снятие директивы двигает произведённое.
  Роль признака в том, чтобы отчёт при `Inert` назвал сомнение вслух, а не
  выдал молчание за проверку.

  Оговорка, которую признак не покрывает: правила, печатающие границу **в
  тексте** находки, а не полем (`ComplexityRule.php:185` — эталонный случай),
  различимы отпечатком через `message`, потому что сообщение в него входит.
  Признак говорит о поле, и только о нём.

## Повторная исполнимость

Утверждение: повторное исполнение правил на том же контексте даёт тот же исход.
Свидетелей два, и **статический ничего не доказывает сам по себе** —
отсутствие записанного свойства не есть стабильность исхода:

- **Статический.** `enumeration-execution-state.tsv`: 49 классов правил
  (транзитивный отбор), ноль присваиваний `$this->` вне конструктора. Слепые
  пятна названы в шапке; поверхность сотрудников — в
  `enumeration-rule-collaborators.tsv` (49 правил и 2 валидатора; мутирующий
  сотрудник известен один — `InlineDirectivePolicy::enableUsageReporting`,
  идемпотентная установка severity).
- **Эмпирический, он же доказывающий, и он внутри продукта.** Свип, у которого
  есть хоть одна измеримая директива, начинается и заканчивается контрольным
  исполнением с **полным** набором оверрайдов; оба отпечатка обязаны совпасть с
  отпечатком базового результата. Дрейф за промежуточные исполнения ловится
  только парой «первый и последний», а не одним прогоном.
  Расхождение — это отказ метода, а не находка о директиве, поэтому аудит
  бросает `LogicException` с именами разошедшихся каналов и не отвечает вовсе.
  Цена свидетеля — два исполнения правил сверх популяции; при пустой популяции
  свип не запускается и контроля нет.

Расхождение эмпирического свидетеля отменяет метод и становится находкой о
разделяемом состоянии правил с именами двух правил. Это условие остановки.

## Тестовый план

- **Единичные, на `ThresholdDirectiveAudit`** с поддельными контекстом и
  исполнителем: снятие меняет исход → `Effective`; не меняет → `Inert`;
  severity та же, граница другая → `Overrun`; продюсер выключен → `Unmeasured /
  ProducerDisabled`; классовая директива с несколькими записями → один вердикт,
  один проход и **все** записи группы сняты; перекрывающая пара класс+метод с
  совпадающим вердиктом на субъекте, где правило отчитывается → обе
  `Unmeasured / Masked`; та же пара на субъекте, где правило не отчитывается →
  `Masked` **не** ставится; правило без публикуемой границы → `Effective` и
  `boundaryObservable = false`.
- **Интеграционный, через настоящий контейнер**, на фикстуре с парой директив на
  одном якоре: одна заведомо действующая, одна заведомо инертная. Парность
  несущая: сломанная адресация дала бы `Inert` обеим. Прототип провалил первую
  попытку именно так — якорем был enum, у которого WMC не измеряется.
- **Повторная исполнимость** на той же фикстуре: два прохода — один отпечаток.
- **О1**: находка под `exclude_namespaces` фикстуры, директива на ней остаётся
  `Effective`; мутация «судить по `published`» краснеет.

## Definition of Done

- `composer enumeration:directives` перегенерирован, расхождений нет; популяция
  названа числом из прогона.
- Все тесты выше зелёные, каждый проверен снятием своей ветки поштучно.
- Замерена и записана цена полного свипа на нашем `src` — числом из прогона, не
  из прототипа.
- Манифест: контракт Inline объявлен вместе со своим настоящим потребителем —
  `Analysis\Run\RuleProducerPreparation`, единственным чужим читателем в
  пакете, плюс конфигуратор композиции; ребро
  `Analysis.Policy.Inline → Analysis\Finding\Contract\RuleExecutionInterface`
  внесено. Публичного контракта Run пакет не заводит.
- `composer check` — exit 0; `composer gate -- --reference=<коммит П1>` — GREEN.
- README `src/Analysis/Run/` дополнен; README Inline дополняется здесь только
  пороговой половиной — словарь вердиктов там уже описан П1.
- Коммит и полная цепочка до начала П3.
